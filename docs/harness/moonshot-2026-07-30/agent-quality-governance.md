# Moonshots — Agent Quality & Governance

## 1. The Trust Contract: certification becomes a runtime-enforced, signed license to run
- **Tier**: 1 (10x category-defining)
- **Category**: trust
- **Impact**: Every persona version carries a continuously-recomputed, attestable trust grade that *gates what it is allowed to do* — schedule, trigger, touch credentials, join chains, serve MCP, deploy to fleet — turning governance from dashboards people look at into a contract the engine enforces.
- **Feasibility**: medium
- **Time-horizon**: months
- **Why it's a moonshot**: Today the group produces an enormous amount of quality evidence — eval runs, SLA violations, arena wins, Director verdicts, healing episodes, audit incidents, user ratings — and *none of it constrains anything*. The Certification Command Center is explicitly a read-only dev viewer over on-disk JSON bundles (`src-tauri/src/commands/eval_runs.rs` header says so verbatim: "read-only viewer... if this ever ships in a packaged build the commands should be gated"). The moonshot inverts the relationship: quality evidence compiles into a per-persona-version **Trust Certificate** (grade + capability envelope + evidence digest, signed), and the execution runner, scheduler, trigger system, chain composer, credential vault, and MCP endpoint all check it before acting. This is the "TLS certificate for agents" — no other agent platform makes certification load-bearing, and it converts Personas from an agent runner into an agent *governance authority*. Because personas are already externally addressable (MCP endpoints, fleet dispatch to other repos, p2p with trust levels in `src-tauri/engine/src/p2p/types.rs`), the certificate travels: external hosts and other Personas installs can verify "this agent is certified Gold for code-review up to $2/run" before accepting work from it.
- **What exists today**:
  - `personas.trust_level` / `trust_origin` already in the schema and threaded through ~15 files (`src-tauri/db/src/repos/core/personas.rs`, `src-tauri/engine/src/enclave.rs`, `src-tauri/engine/src/p2p/types.rs`) — a trust axis exists but is static, not evidence-derived.
  - Evidence producers, all live: `eval_runs`/`eval_results` + audit incidents (`src-tauri/src/commands/eval_runs.rs`, `src-tauri/src/commands/execution/audit_incidents.rs`), SLA definitions/violations (`src-tauri/core/src/models/sla.rs`), output assertions (`src-tauri/engine/src/output_assertions.rs`), lab consensus + arena matches (`src-tauri/db/src/repos/lab/eval.rs`, `arena.rs`), Director verdicts (`src-tauri/src/engine/director.rs` — pinned judge model for score comparability), healing episodes (`src-tauri/engine/src/healing_timeline.rs`), failure signatures (`src-tauri/engine/src/failure_signature.rs`), per-version ratings (`src-tauri/db/src/repos/lab/versions.rs`).
  - Enforcement choke points, all live: persona-level circuit breaker in `src-tauri/engine/src/healing_orchestrator.rs` (already disables personas on evidence — the one existing "trust gate"), the execution runner, review policies (`auto_triage.rs`), and version promotion (`PostActivationReconcileDialog.tsx` shows activation is already a first-class event).
  - UI to grow into: `src/features/overview/sub_certification/CertificationCommandCenter.tsx` + `useCertificationData.ts` (deferred-loading slice, gate breakdowns, trajectory charts already rendered).
- **Path to implementation**:
  1. Add a `trust_certificates` table + a pure Rust `cert_compiler` module that folds the existing evidence tables into a per-persona-version grade (Provisional/Bronze/Silver/Gold) with a capability envelope (max budget, allowed connectors, review_policy floor, chain/MCP eligibility). Recompute on eval-run completion, SLA violation, healing episode, and version activation — all existing events.
  2. Enforce at one choke point first: the execution runner refuses (or downgrades to `manual_review` policy) any run whose requested capability exceeds the persona's envelope. This generalizes the circuit-breaker pattern that already exists in `healing_orchestrator.rs`.
  3. Extend enforcement to scheduler/trigger admission and chain composition; surface the envelope in the Certification Command Center as *the* live cert (replacing the read-only bundle viewer's dev-only status) with "what would unlock Silver" gap analysis.
  4. Make demotion evidence-driven and automatic (SLA breach streak → downgrade + notification), promotion require a passing eval-run battery — wiring `create_eval_run` as the promotion exam.
  5. Sign certificates (device key via existing keyring integration) and expose verification on the MCP surface and fleet dispatch, so external consumers can check an agent's license before delegating.
  6. Federate: p2p trust exchange upgrades from static `trust_level` to certificate exchange.
- **Dependencies**: eval-runs, lab-quality-models (SLA), overview-certification, execution-runner admission path, credential-vault (envelope enforcement), mcp-protocol context (external verification); no external services required.
- **Risks**: (1) Over-blocking a solo power-user's own agents is annoying — needs a one-click owner override that logs an audit incident rather than a hard wall. (2) Grade compilation from heterogeneous evidence can be gamed by easy evals — the exam battery must be curated, not self-selected. (3) Enforcement touches many hot paths; a buggy gate could brick scheduling (mitigate: advisory mode first, enforce per-capability incrementally).
- **What changes if we ship it**: "Is this agent safe to give real work?" stops being a judgment call and becomes a queryable, enforced fact — and Personas becomes the certifying authority whose trust grades other systems (fleet repos, external MCP hosts, peers) can rely on.

## 2. The Director's Lab: from prose coach to autonomous experiment-running scientist
- **Tier**: 1 (10x category-defining)
- **Category**: intelligence
- **Impact**: The Director stops merely *writing notes about* personas and starts *running the scientific method on them* — converting each verdict into a testable hypothesis, commissioning A/B experiments and breeding cycles in the Lab, measuring outcomes in production, and presenting the operator with proven diffs instead of opinions: a roster that measurably improves every week with human effort reduced to approving promotions.
- **Feasibility**: medium
- **Time-horizon**: quarters (first loop closed in weeks)
- **Why it's a moonshot**: The group already contains every organ of a self-improving system, but as disconnected silos: the Director diagnoses (prose verdicts → human review), the evolution engine breeds (`evolution.rs` — but its fitness comes from *synthetic lab scenarios*, per `test_runner::generate_scenarios`), genome-critique rewrites prompt segments from failure history, auto-rollback reverts regressions, and `lab_ab_experiments` stores experiments nobody commissions automatically. The missing 10x is the *connective tissue*: verdict → hypothesis → controlled experiment → production-measured outcome → promotion, with the Director allocating a real compute/cost budget across the roster like a portfolio manager (the `RunBudgetState` plumbing in `EvolutionCycleSummary` already exists). This differs fundamentally from Moonshot 1: that one is a gate (what agents *may* do); this one is an engine (making agents *better*). `director.rs` itself declares Phase 3 as "planned" (verdict → healing-issue routing) — this moonshot is Phase 4: verdict → experiment. No agent platform has a resident meta-agent that runs evidence-based improvement campaigns on its own roster.
- **What exists today**:
  - Director loop with taste-learning: `src-tauri/src/engine/director.rs` (LLM verdicts anchored on executions, approve/reject captured as `director_feedback` memories), `director_brain.rs` (Obsidian persistence), scoring/attention engine (`src/features/overview/sub_director/directorScore.ts`, `useDirector.ts`, `momentum.ts`).
  - Evolution machinery: `src-tauri/src/engine/evolution.rs` (full cycle: breed → arena-test → promote, single-flight guarded, budget-tracked), `genome.rs` (prompt-segment crossover/mutation, fitness from execution knowledge), `genome_critique.rs` (LLM gradient on failure history), `auto_rollback.rs` (regression safety net already mutex-coordinated with healing via the `healing_personas` slot documented in `healing_orchestrator.rs`).
  - Experiment substrate: `src-tauri/db/src/repos/lab/ab.rs` (`lab_ab_experiments`, `lab_matrix` — assignment buckets + outcome measurements), arena head-to-head (`src/features/agents/sub_lab/components/arena/ArenaPanelColosseum.tsx`, `lab/arena.rs`), consensus scoring (`lab/consensus.rs`), version matrix + economics (`LabVersionsTable.tsx`, `LabEconomicsPanel.tsx`), model A/B comparison (`model-config`'s compare_models).
  - Judges: `src-tauri/engine/src/eval.rs` (pluggable EvalStrategy, LLM + heuristic fallback), `auto_triage.rs` (LLM verdicts against decision principles), output assertions.
- **Path to implementation**:
  1. Make Director verdicts structured: extend the `DIRECTOR_VERDICT:` parse in `director.rs` with an optional `hypothesis` block (`{segment_target, proposed_change, success_metric, metric_source}`) — the rubric already asks for concrete improvements; this just types them.
  2. Build the `verdict → experiment` compiler: an approved hypothesis materializes a variant version via `genome.rs` segment-rewrite (reusing `genome_critique.rs`'s rewriting) and registers a `lab_ab_experiments` row with the verdict as provenance.
  3. Ground fitness in production: extend `compute_fitness` to consume real signals — SLA violations, healing-episode counts, auto-triage reject rate, user ratings — not just lab-scenario scores, using the assignment buckets in `lab/ab.rs` to attribute live executions to variants (shadow/canary split on real scheduled runs).
  4. Give the Director a budget ledger: per-week evolution spend allocated across personas by attention score (`directorScore.ts` already ranks who needs work); `run_evolution_cycle`'s existing `RunBudgetState` enforces per-cycle caps.
  5. Close the loop through human review only at promotion: experiment concludes → Director files a "proven improvement" review (existing `persona_manual_reviews` path) with before/after metrics; approve = activate version (existing `PostActivationReconcileDialog` flow), reject = feedback memory that tunes future hypotheses.
  6. Weekly campaign report in the Director tab: hypotheses tested, win rate, cost, roster-wide score trend — the Director's own performance review.
- **Dependencies**: director-coaching + scoring, persona-evolution, lab-ab-testing-repo, lab-versioning-repo, test-runner-lab, execution-runner (canary assignment), human-review inbox; Claude CLI spend for experiments (budget-gated).
- **Risks**: (1) Production canarying of variant prompts can ship a bad variant to real work — must ride the existing auto-rollback + assertion nets, and start shadow-only (variant runs scored but outputs discarded). (2) Metric attribution noise: low-traffic personas won't reach significance — Director must be taught to say "insufficient evidence" rather than promote on 3 runs. (3) LLM-judge circularity (Director proposes, LLM judges) — anchor success metrics on deterministic signals (SLA, assertions, healing counts) wherever possible, mirroring `eval.rs`'s heuristic strategies.
- **What changes if we ship it**: The roster becomes a portfolio under active, evidence-based management — the owner's role shifts from editing prompts to approving proven wins, and every approval makes the Director a better scientist. Multiplied across the owner's fleet of projects, it's compounding agent quality with near-zero marginal human effort.
