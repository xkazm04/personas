# Core Sample

## Philosophy
The first question a 102-project portfolio answers is how far the fleet has got
on each DIMENSION, so a dimension is one continuous cut through the whole
portfolio and a project is a depth through all of them at once.

## How it stays readable at scale
Nothing about the figure's height depends on the lens: 102 laminae at 3px is a
306px drawing, and 500 projects would be a finer grain in the same box rather
than more scroll. There is no row chrome at all - no band, no stripe, no name
column - because a lamina needs none; a run of the same state reads as banding
in the rock. The dimension names sit horizontally in a label rail above the
cores at full type size, never rotated. Cores are ordered deepest-cut first, so
the lens reads as one silhouette.

## The wow moment
The cursor's lamina blooms open to eleven laminae across every core at once, so
one project still reads as a complete slice and gets a real click target, and
the depth axis prints its name at exactly that depth with nothing measured in
script. Absence is drawn as uncut ROCK rather than as empty dots, so each
core's inked fraction is its own denominator and the `9/102` at its foot only
confirms what the drawing already said.

## Known limits
A 3px lamina is a hostile pointer target off the cursor row; the figure assumes
the keyboard, which this operator uses, and the bloom is the mitigation. A
single project is not identifiable without moving the cursor to it. The
transposed grid semantics announce a core, not a project, so a screen-reader
tour of the portfolio reads dimension-first.
