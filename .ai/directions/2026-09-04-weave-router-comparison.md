# personas vs. `weave-os/router` — peer study (routing, attribution, and the run record)

- **Source**: `weave-os/router`, clone `C:/t/workweave-router-0904`, pinned `1699cf6`. Read read-only; nothing in this study was built.
- **Paths**: router anchors are relative to `C:/t/workweave-router-0904`; personas anchors are relative to the personas root.
- **Why this peer.** The router fronts five vendor pools behind one endpoint and decides, per inbound API request, which model serves it (`docs/SEMANTICS.md:57-60`). personas runs one wrapped CLI and decides, per execution, which model to spawn it with. `.ai/manifest.yaml:97-98` fixes personas at *"run local AI agent personas over wrapped CLIs, local-first storage, one operator per install"* and *"observe runs — cost, health, traces — and tune routing from evidence."* The second clause is the whole overlap: **both systems make a model decision, dispatch it, and then have to say afterwards what actually served.** That second half is where the router is a decade ahead and where almost every `adopt` below lands.
- **Verdicts** come from the closed set `adopt` / `adapt` / `keep ours` / `different forces`. Every one carries its reason, and `keep ours` argues from personas' own forces — local-first, one operator, one wrapped CLI provider, no multi-tenant control plane, no hosted billing.

**Verdict tally: 48 points — 14 `adopt`, 15 `adapt`, 15 `keep ours`, 4 `different forces`.** `keep ours` and `adapt` tie for the largest class, and that is the honest shape of this pairing: the router is a hosted multi-tenant service and personas is a single-operator desktop app, so most of what the router does well is answered here by a different force rather than a missing feature. The `adopt` column is small and concentrated — it is almost entirely about *what personas records after it decides*, which is the one axis where the two systems face the same problem.

## The asymmetry that governs every verdict below

The router **owns the request**. It parses the body, scores a candidate set, resolves a credential, dispatches to an upstream, and reads the usage back off the wire (`internal/proxy/CLAUDE.md:24-38`). personas owns **neither end**: `apply_provider_env` is a documented no-op because *"Claude Code CLI validates model names against Anthropic's list and does not support OLLAMA_BASE_URL, OPENAI_BASE_URL, etc."* (`src-tauri/engine/src/prompt/cli_args.rs:19-28`), and the whole prompt leaves as one stdin blob under `-p -` (`cli_args.rs:101-112`). The only first-party HTTP inference path in the tree serves exactly two SKUs — `matches!(…, "qwen" | "dashscope")` (`src-tauri/src/engine/http_engine/config.rs:24-29`).

So every point touching the wire format, the message array, the candidate score or the prompt-cache breakpoint is a candidate for `different forces`. The points that are **not** protected by that asymmetry are exactly the ones the router earned by watching its own decisions in production: the decided-vs-served split, the enumerated suspension of competing writers, the null-not-zero cost, and the log key that is bound once and never re-passed. Those transfer whole.

**Headline — the seeds are right about the router and wrong about personas five times, and each correction sharpens the finding.**

1. **Seed 2 is inverted.** The `CLAUDE_MODEL_CHAIN` ladder is not a fail-soft alternative to the router's 503; it is **unreachable for every failure a different model could survive**. `break 'failover driver` fires on the first *successful spawn* (`src-tauri/src/engine/runner/mod.rs:1899-1903`), so a rate limit, a 404 on the model id, or a bad output never touches it. The repo already says so: *"the model ladder is reachable only when changing the model cannot help"* (`docs/concepts/golden-paths/failure-recovery-strategy.md:674`), against `provider_audit_log`: **4,001 rows, `was_failover = 0` on every one** (`:220-224`). §2.2.
2. **Seed 3 is correct and worse than stated.** Both writers hit `persona_executions.model_used` (`src-tauri/db/src/repos/execution/executions.rs:838`, `:864`), the second overwrite is *deliberate and documented as authoritative* (`:854-856`), and the decided value is copied nowhere first. §3.1.
3. **Seed 4 undercounts.** personas has **twelve** mechanisms that can change model, prompt, persona or session after the decision, and **four partial lists** that each cover a different subset — the most complete, `src-tauri/engine/src/healing_orchestrator.rs:7-61`, covers the failure-aftermath family only. §4.1.
4. **Seed 6 is half wrong in both directions.** personas *does* have a prefix-stability instrument — but only in the companion, and it is an instrument for a reorder that was never built (`src-tauri/src/companion/prompt/budget.rs:118-124`). And the two cache columns *are* read — by exactly one React stat tile (`src/features/agents/sub_executions/detail/inspector/inspectorShared.tsx:34-49`) and nothing else. §5.2, §3.6.
5. **Seed 9 is right, and the router is worse than suspected.** personas has the one door and a pre-push ratchet; the router states the same rule in prose (`CLAUDE.md:177`) and carries **225 bare `"claude-…"` / `"gpt-…"` / `"gemini-…"` literals in non-test Go** with no counter. But re-measuring personas today gives **127 live bypasses across 57 files**, and **no file in the desktop crate imports the door at all**. §8.1.
6. **Seed 11 has already been answered, in writing, with numbers.** `docs/concepts/golden-paths/crate-layering.md:22-30` establishes that Cargo enforces the acyclic property *by construction* — 0 references in 114 and 143 files respectively — and `:219-273` records two census instruments built, measured and **declined**, one of them because it matched 0 of 701 and *"a rule pinned at 0 is a gate that can never fail."* That is a better artifact than the router's layer diagram. §10.1.

**And the single highest-value finding is not in any seed:** a warm-pool session reuse silently converts a fresh run into a resume (`src-tauri/src/commands/execution/executions.rs:505-511`), and the resume argv builder pushes **no `--model` at all** (`src-tauri/engine/src/prompt/cli_args.rs:305-323`). The candidate model profile is computed at `runner/mod.rs:1739-1746` and then discarded. §4.3.

## 1. Routing decision and grain

**1.1 — What a routing decision is *about*.**
Router: one **action** = one upstream API request, named as the finest addressable grain and given a formal notation for nesting — `A2_S4_SA1_S1` is agent turn 2, step 4, subagent 1, step 1 (`docs/SEMANTICS.md:14`, `:47`, `:57-60`). The analytics export is one row per action and says so, with the consequence spelled out: *"`COUNT(*)` is a count of model calls, not of user requests"* (`docs/ANALYTICS_EXPORT.md:96-110`).
personas: the execution is the atom. The model is resolved through a six-layer cascade that all completes before spawn (`src-tauri/src/engine/runner/mod.rs:182-234`, `:243-255`, `:323-393`, `:405-437`, `:1613-1630`, `:1640-1644`), emitted as `--model` at argv-build time (`src-tauri/engine/src/prompt/cli_args.rs:119-127`), and never revisited. Subagents inherit it — personas never passes `--agents` (zero hits in `src-tauri/**/*.rs`).
**Verdict: `different forces`.** The router routes because it sits between the client and five vendors; personas hands one process one flag and the CLI owns everything after. A per-step grain would require personas to own the loop, which `cli_args.rs:19-28` and the manifest's "wrapped CLIs" both rule out.

**1.2 — The finer grain personas already has, and does not use.**
Router: `internal/router/turntype/detect.go:15-23` classifies each action as `main_loop` / `tool_result` / `sub_agent_dispatch` / `compaction` / `probe`, and `turn_type` is an exported analytics column (`docs/ANALYTICS_EXPORT.md:169`) used to separate user-visible turns from machinery (`:117-119`).
personas: the stream parser already carries subagent attribution — `parent_tool_use_id` (`src-tauri/engine/src/parser.rs:168`) — and it is observability only. Nothing groups a run's cost or duration by what kind of step spent it.
**Verdict: `adapt`.** Not to route on, but to *report* on: personas' own scope clause is "observe runs — cost, health, traces". A run's cost today is one scalar with no breakdown by what kind of work incurred it, and the field that would give it is already parsed.

**1.3 — Hard capability requirement vs. soft quality hint.**
Router: `TranslationRequirements` is derived at ingress *before* scoring and applied as candidate filters, explicitly separated from quality inputs — *"`HasTools` and `HasImages` can still influence model quality, while requirements describe semantics that must survive the selected wire-format path"* (`docs/TRANSLATION_COMPATIBILITY.md:1-13`), with a three-mode rollout (`off` / `shadow` / `enforce`, `:16-23`).
personas: no model capability metadata exists anywhere. `src-tauri/engine/src/prompt/capabilities.rs` is about *persona* capabilities; its only model logic is a three-entry tier map (`:9-16`). The frontend catalog carries id/label/provider only (`src/lib/models/modelCatalog.ts:8-14`). The distinction **does** exist in the tree, for tools, stated exactly right: *"`tool_allowed` is a SECURITY boundary … the persona roster is a LATENCY/COST lever. A latency lever must never be able to reopen a security boundary"* (`src-tauri/src/engine/http_engine/config.rs:96-101`).
**Verdict: `adapt`.** The doctrine is already written in this tree, in the right words, one file away from where it is needed. A model with a 200k window and a persona whose prompt budget tripwire is 200,000 chars (`src-tauri/engine/src/prompt/budget.rs:16`) is a requirement, not a hint.

**1.4 — How many places spell the tier ladder.**
Router: one. `internal/router/catalog/catalog.go:140-169` is the `Model` struct — tier, context window, tool-use quality, image support, ordered provider bindings — and `internal/router/CLAUDE.md:11` names it *"single source of truth for per-model data"*.
personas: four, and they disagree. `CLAUDE_MODEL_CHAIN` (`src-tauri/src/engine/failover.rs:639-643`), `tier_slug_to_model_id` (`src-tauri/engine/src/prompt/capabilities.rs:9-16`, which bakes the same three ids as literals), `model_ids.rs`'s job-named tiers (`src-tauri/core/src/model_ids.rs:43-45`), and the companion's turn-class table (`src-tauri/src/companion/model_routing.rs:24-47`, which names `claude-sonnet-5` — an id absent from `model_ids.rs` entirely). `failover.rs:637-638` acknowledges the duplication in a comment rather than removing it.
**Verdict: `adopt`.** `model_ids.rs:1-15` already exists as the door and already states the incident that built it; three of the four tables should read from it rather than re-declare it. This is the cheapest structural fix in the study.

**1.5 — A selection table that cites a measurement.**
Router: the planner's economics carry their own error bar — *"Measured over 30 days of production, the legacy model understates a turn's cost by ~11x (cost-weighted bias -91%, of which the k=1 assumption is 52 points)"* (`internal/router/planner/CLAUDE.md`, "Corrected economics"), shipped behind `ROUTER_SWITCH_CORRECTED_ECONOMICS` default off.
personas: exactly one table cites a measurement — `src-tauri/src/companion/model_routing.rs:2-3`, *"calibrated by the 1,026-turn bench"*. The persona-side ladder cites an incident (`failover.rs:631-638`) but no outcome data.
**Verdict: `keep ours`.** One measured table out of four is not good, but the companion's is the right shape and the right size for a single-operator app: a bench the operator ran, on their own traffic, cited at the constant. The router's fleet-wide 30-day regression is not available to a desktop install and pretending otherwise would manufacture a number.

## 2. Failure and the fail direction

**2.1 — There is no strategy fallback.**
Router: *"There is no strategy fallback. If a serving policy cannot return a valid selection after bounded transient retries, the client receives HTTP 503. Availability comes from healthy replicas, readiness gates, immutable artifacts, and staged rollout rather than a second hidden policy"* (`docs/POLICY_ROUTER_HARNESS.md:27-30`). Enforced by a sentinel: `ErrClusterUnavailable` (`internal/router/cluster/scorer.go:18-20`) maps to 503, and the reason is stated as a design rule — *"silent fallback to a default model masks regressions + lets quality silently degrade in eval + prod"* (`internal/router/CLAUDE.md:29`). The retired heuristic A/B is named as the counter-example (`CLAUDE.md:252`).
personas: a hard-coded descending ladder, opus → sonnet → haiku (`src-tauri/src/engine/failover.rs:639-643`), private, with no settings key, no env override and no UI.
**Verdict: `different forces`.** A desktop app cannot 503 at the person sitting in front of it, and a single-operator install has no replica to fail over to. The ladder is the right *shape*. What is wrong with it is §2.2, not its existence.

**2.2 — A rescue must be reachable from the fault class it targets. — CORRECTS SEED 2.**
Router: the rescue chain is armed exactly where the fault appears. A buffered upstream 404 triggers one cross-binding hop and is *deliberately excluded* from the generic retryable set because re-hitting the same provider is futile (`internal/proxy/CLAUDE.md:217`); a 402 gets the same treatment (`:219`); and when every binding is exhausted pre-commit, `sibling_failover.go` re-dispatches a **different model** from the pool the policy already scored (`:221`). All of it fires post-dispatch, pre-commit, gated on `preludeBuf.Committed() == false` (`:233`).
personas: the ladder advances **only** when `CliProcessDriver::spawn` returns `Err`; `break 'failover driver` exits on the first successful spawn (`src-tauri/src/engine/runner/mod.rs:1899-1903`). `is_failover_eligible` enumerates the classes that *should* trigger it — `ProviderNotFound | RateLimit | SessionLimit | Timeout` (`src-tauri/core/src/error_taxonomy.rs:455-463`) — and its only non-test call site runs at `runner/mod.rs:3157-3177`, **after the run has finished**, where it feeds circuit-breaker counters and nothing else. The repo's own audit states the outcome: *"A fallback chain walked only on connection failure … `was_failover = 0` on 4,001 audited runs; the model ladder is reachable only when changing the model cannot help"* (`docs/concepts/golden-paths/failure-recovery-strategy.md:674`, count at `:220-224`).
**Verdict: `adopt`.** This is the study's clearest transfer and it needs no router code: `is_failover_eligible` already names the right classes, and `healing_orchestrator.rs:264-270` already routes RateLimit/Timeout to a retry. The missing wire is that the retry re-enters the chain at the *next* rung instead of the same one.

**2.3 — Retries bounded twice: by count and by wall clock.**
Router: `maxSameBindingRetries = 2` (`internal/proxy/fallback.go:384`) *and* `sameBindingRetryBudget = 10 * time.Second` (`:390`), with the reason: *"The count alone bounds attempts but not cost — an upstream that accepts the stream and never answers burns a full ResponseHeaderTimeout (30s) per attempt, so three of them spend ~90s on a request that was never going to be served"* (`internal/proxy/CLAUDE.md:225`). The budget stop logs at WARN with `spent_ms`/`budget_ms`, *"without it, a hang and a blip are indistinguishable in the logs"*.
personas: counts only. Provider breaker at 5 consecutive failures / 60s cooldown / global trip at 10 in 120s (`src-tauri/src/engine/failover.rs:39`, `:42`, `:46`, `:49`); `MAX_QA_FIX_ROUNDS = 2` (`src-tauri/src/engine/team_assignment_orchestrator.rs:1146`); `STORM_RETRY_CAP` over `STORM_WINDOW_MINUTES` (`src-tauri/engine/src/healing_orchestrator.rs:99`, `:105`) — that last one is the one wall-clock-shaped bound and it caps *storm frequency*, not the time one rescue may consume.
**Verdict: `adapt`.** personas runs on the operator's laptop, where a hung retry costs battery and a foreground process rather than an SLO. But the diagnostic half transfers exactly: the WARN carrying `spent_ms`/`budget_ms` is what makes a hang legible, and personas' healing timeline has nowhere to record "this rescue burned twelve minutes and returned nothing".

**2.4 — The rescue that goes the other way, and its budget.**
Router: a cyclic-loop detection escalates a cheap/mid session onto `escalateModel = "claude-opus-5"` (`internal/proxy/loop_detection.go:19`), and the escalation is **budgeted per session** — `LoopEscalationStore.CountLoopEscalationEvents` *"enforces the once-per-session budget"* (`:22-26`), one row per session+role.
personas: AI healing escalates in the same direction, unconditionally and with no budget: `persona.model_profile = Some(r#"{"model":"claude-opus-4-6"}"#.to_string());` under the comment `// 2. Force Claude Opus model for healing` (`src-tauri/src/engine/healing_retry.rs:709-710`). The pinned id matches nothing in `model_ids.rs:31-33` and nothing in `CLAUDE_MODEL_CHAIN`. So the tree contains two opposite-direction failure responses — spawn failure ladders *down*, post-run failure heals *up* — that do not know about each other.
**Verdict: `adopt`.** Both halves: the per-session escalation budget, and reading the id from the one door. An unbudgeted forced-Opus retry on a persona that fails repeatedly is the single most expensive path in the codebase, and the persona breaker (5 consecutive, `healing_orchestrator.rs:83`) only stops it after five.

**2.5 — A recovery mechanism with no observed firing is a claim.**
Router: the release gate is explicit — *"sidecar loss produces bounded retries and an observable 503, never fallback; at least two ready replicas survive a single-replica loss test"* (`docs/POLICY_ROUTER_HARNESS.md:250-251`). The rescue must be demonstrated before promotion.
personas: the tree already states the general rule and its own violations — *"A recovery mechanism with no observed firing … It is a claim. `circuit_breaker_state`: 0 rows. `is_circuit_breaker`: 0 of 205. `healing_knowledge`: 0 rows, so one of the three counters the decision table is built on has never been consulted"* (`docs/concepts/golden-paths/failure-recovery-strategy.md`, defect table).
**Verdict: `adapt`.** personas wrote the rule before the router was read; what it lacks is the gate — and the router's gate is the wrong shape, since a promotion checklist for a two-replica hosted service does not fit a desktop install. The right shape is personas' own: the census already refuses to baseline a rule at zero because *"a rule pinned at 0 is a gate that can never fail"* (`scripts/census/lib/engine.mjs:304-314`). A recovery path with zero rows after 4,001 runs is the same condition, one table over.

## 3. Attribution and the run record

**3.1 — Decided model and served model are two different facts. — SEED 3 CONFIRMED.**
Router: two columns, always. `selected_model` / `selected_provider` alongside `served_model` / `served_provider`, plus the derived `selected_served_model_match` (`internal/proxy/service.go:4901-4907`), and the export carries `requested_model` and `decision_model` as separate fields (`internal/analytics/analytics.go:33-34`).
personas: one column, overwritten. `set_launch_model_info` writes `UPDATE persona_executions SET model_used = ?1, thinking_level = ?2` (`src-tauri/db/src/repos/execution/executions.rs:838`); `set_model_used_actual` writes `UPDATE persona_executions SET model_used = ?1` (`:864`). The overwrite is deliberate — *"Stamp the ACTUAL model the CLI reported on its stream init event — authoritative over any configured value (covers account-default runs and provider-side aliasing)"* (`:854-856`) — and the decided value is copied nowhere first. Call sites: `src-tauri/src/engine/runner/mod.rs:2034-2041` (argv scrape) and `:2415-2433` (stream `system/init`). Downstream, `metrics.rs:544-555` and `policy_evidence.rs:38-53` both group by that conflated column, so the tuning proposals in `src-tauri/db/src/policy_tuning.rs` are built on it.
**Verdict: `adopt`.** The docstring names the exact case that makes the conflation dangerous — *"provider-side aliasing"* — and then makes it undetectable. One nullable `model_requested` column, written once at launch and never updated, restores the fact. It is a single ALTER in the style the tree already uses (`incremental/e18_failure_classification.rs:44`).

**3.2 — A mismatch marks the row ineligible for downstream learning.**
Router: when the policy was authoritative and the served model differs, `trainingAllowed = false` and the line logs at ERROR (`internal/proxy/service.go:4859-4870`); the same treatment applies to an effort mismatch, with the reason stated — *"training on a clamped or overridden turn credits the arm with another level's outcome"* (`:4871-4873`).
personas: no eligibility concept exists. Every aggregate over `persona_executions` filters on at most `is_simulation`, `status`, and `created_at` (`src-tauri/db/src/repos/execution/metrics.rs:519`, `:552`). A row whose `model_used` was overwritten, whose `cost_usd` is the CLI's unverified number, and whose `cache_*` columns are 0 because finalize skipped the gated write (`src-tauri/src/engine/runner/mod.rs:3222`) is indistinguishable in every query from a fully instrumented one.
**Verdict: `adopt`.** personas' `policy_tuning.rs:12-16` is *"proposed, not imposed"* and every proposal is human-reviewed, which softens the blast radius — but a proposal built on rows that silently lost their attribution is a proposal the operator cannot audit. `business_outcome` (`incremental/e05_twin_and_memory_review.rs:289`) is the existing precedent for a per-row verdict column.

**3.3 — Unpriceable is null, not zero.**
Router: `ActualInputCostUSD *float64` / `ActualOutputCostUSD *float64` (`internal/analytics/analytics.go:55-56`), with the reason in the doc — *"Cost fields are null for rows the router could not price (an unknown model, an upstream error before any usage was reported). They are null rather than 0 so they drop out of an average instead of dragging it down"* (`docs/ANALYTICS_EXPORT.md:226-229`).
personas: `cost_usd REAL DEFAULT 0` (`src-tauri/db/src/migrations/schema.rs:123`), and the BYOM path stamps a literal zero for an unknown SKU — the price table matches exactly two models and returns `None` otherwise (`src-tauri/src/engine/http_engine/config.rs:33-46`), applied at `http_engine/openai.rs:228-233`.
**Verdict: `adopt`.** This one is nearly free and it is already breaking a number the operator reads: a run that failed before any usage came back and a run that genuinely cost nothing are the same row, and `metrics.rs`'s `SUM(cost_usd)` averages them together.

**3.4 — The row grain and its mutability.**
Router: one immutable row per action, unique `id`, deduplicated on replay — *"A row is written once and never updated … Deduplicate on `id` and a replayed page is a no-op merge"* (`docs/ANALYTICS_EXPORT.md:125-133`), ordered by ingest time with a 60-second holdback so a resumed cursor cannot skip a late commit (`:135-146`).
personas: one row per execution, mutated in place through its life — `update_status` (`executions.rs:1027`), `set_model_used_actual` (`:864`), `set_cache_tokens` (`:903`), `set_traceparent` (`:1617-1633`), plus 22 `ALTER TABLE`-added columns whose real shape no single DDL block lists (`:83-87`).
**Verdict: `different forces`.** A single-writer SQLite file on one machine has no replay, no cursor and no warehouse consumer, so append-only would buy nothing and cost a join on every list page. But the *attribution* subset — decided model, launch effort — should be write-once even inside a mutable row, which is exactly §3.1.

**3.5 — Whose number the cost is.**
Router: recomputed against the binding that actually served — *"After dispatch, `actPricing` is re-resolved against the WINNING binding via `catalog.PriceFor(finalProvider, decision.Model)` so debits and OTel `cost.actual_*` reflect the actually-served provider's per-1M rate"* (`internal/proxy/CLAUDE.md:237`), and again for the fast tier, per attempt (`:243`).
personas: trusted verbatim. `parser.rs:357` reads `total_cost_usd` off the CLI's `result` line; `parser.rs:866-868` assigns it; `runner/mod.rs:3384` persists it unchanged. The two local price tables — `src-tauri/engine/src/cost.rs:15-60` (substring-matched, pre-flight preview only, sole consumer `commands/execution/executions.rs:941-948`) and `http_engine/config.rs:33-39` (exact-matched, BYOM only) — never validate it.
**Verdict: `keep ours`.** The CLI is the billing authority for a subscription run and personas has no independent view of what Anthropic charged; a locally recomputed number would be a *worse* number presented with more confidence. The `cost.rs` table's own header already says so — *"These are approximate list prices"* (`:13-14`). What should change is not the source but §3.3's null.

**3.6 — The two cache columns are written, and read once. — CORRECTS SEED 6b.**
Router: `cache_creation_tokens` / `cache_read_tokens` are exported columns (`internal/analytics/analytics.go:49-50`, `docs/ANALYTICS_EXPORT.md:172`), reported on every policy outcome (`internal/proxy/service.go:4919-4920`), and **asserted end to end** — the smoke suite fails when a warm second call does not report `cache_read_input_tokens > 0` (`smoke/cache_test.go:26-28`).
personas: parsed with unusual care, including the CLI 2.1.152 `ephemeral_5m` + `ephemeral_1h` split (`src-tauri/engine/src/parser.rs:364-388`), written by exactly one gated call (`executions.rs:891-909`, called at `runner/mod.rs:3219-3231` only when one is non-zero), and read by exactly one consumer: a single percentage tile in the execution inspector (`src/features/agents/sub_executions/detail/inspector/inspectorShared.tsx:34-49`). No SQL aggregate touches them; the list projection omits them (`executions.rs:112-125`); the overview store hardcodes them to zero when merging global rows (`src/stores/slices/overview/overviewSlice.ts:259-260`).
**Verdict: `adapt`.** The seed was wrong that nothing reads them, and the correction makes the finding sharper: the data is captured correctly and then discarded before it can answer the one question it exists to answer — is the prompt prefix stable? §5.2 is where it should land.

## 4. What can change what serves, after the decision

**4.1 — The enumerated suspension. — CORRECTS SEED 4 (undercounted).**
Router: when a policy declares `authoritative_per_turn_selection`, the router names **exactly** what it disables — *"automatic session reuse, EV planner overrides, model-changing baseline failover, semantic-cache hits, and router-generated summarizer calls for those turns. Post-selection synthetic loop breakers are also bypassed so one accepted policy action maps to one selected model dispatch attempt"* (`docs/POLICY_ROUTER_HARNESS.md:65-72`). It is not only prose: one predicate (`internal/proxy/service.go:2405-2411`) gates the semantic cache (`:2413-2414`, consumed at `:3428` and `:6017`), the compaction summarizer (`internal/proxy/compaction.go:308`), and the turn loop (`internal/proxy/turnloop.go:551`).

## 5. Prompt assembly and the prefix cache

**5.1 — Prefix stability as a load-bearing constraint.**
Router: only the **leading** system run is hoisted; a mid-conversation system message is demoted to `user` in place, and the reason is measured — *"a client that emits a system reminder per turn (Claude Code) shifts the cached prefix on every turn and re-writes the entire prompt; prod traffic showed ~890k cache-creation tokens per turn against a flat 17.5k read"* (`internal/translate/CLAUDE.md:48-50`, implemented at `internal/translate/emit_anthropic.go:726-756`).
personas: the persona prompt's cacheable prefix ends within the first one or two kilobytes. Every `wrap_runtime_xml_boundary` mints a fresh tag from wall-clock nanoseconds (`src-tauri/engine/src/prompt/runtime_safety.rs:13-30`), the first fence lands at `## Description` (`src-tauri/engine/src/prompt/assemble.rs:285`), and there are fourteen more. Volatile blocks sit above the ~15 KB of compile-time constants: `## Correction Required` at position 5 (`assemble.rs:240`) and `## Triggering Event` at 6 (`:246-279`), against `## Protocol Tools` and the eight `PROTOCOL_*` constants at `:581-876`. `cache_control` appears nowhere in the repo.
**Verdict: `adapt`.** The nonce is a prompt-injection boundary, not an accident — `prompt/README.md:72-75` states the per-execution requirement — so it cannot simply be made constant. But a nonce minted **once per execution and reused across the resumed turns of that session** preserves the boundary property and stops re-writing the prefix on every turn, and the fifteen static blocks can move above the two volatile ones without touching the boundary at all.

**5.2 — The instrument exists; the reorder does not. — CORRECTS SEED 6a.**
Router: measured, then fixed, in the same change (`internal/translate/CLAUDE.md:48-50`).
personas: measured, and the fix is still a plan. `src-tauri/src/companion/prompt/budget.rs:118-124` — *"Athena's chat `cache_creation_tokens` climbed 239,852 → 305,401 turn over turn, which means the prompt's stable prefix is not stable — something above the volatile line is being rewritten every turn and invalidating the cache."* The churn lane hashes each block FNV-1a-64 and diffs turn over turn, sorted most-volatile-first (`src-tauri/src/commands/companion/observability.rs:865-949`); `:824-827` says outright that *"Phase L2 … reorders the prompt by volatility; this is the instrument that makes that reorder measurable rather than guessed"*, and L2 is unbuilt (`docs/plans/athena-longevity.md:194-205`). Today's order is not volatility-ordered: the 48 KB observability block sits at `src-tauri/src/companion/prompt/compose.rs:106`, above episodes.
**Verdict: `adopt`.** The measurement is done, the number is recorded, the instrument is wired, and the reorder is one file. This is the highest-confidence cost win in the study because personas already knows what it will move.

**5.3 — Which end you trim from.**
Router: never trims to rescue a switch — the summarizer either produces a summary or the full history goes through unchanged (`internal/proxy/CLAUDE.md:38`), and compaction engages *below* the window, at `ROUTER_COMPACTION_PCT` (default 0.85), because *"a summarizer can only ingest a history that still fits some model"* (`:42`).
personas: the companion trims episodes at the **front** — `fit_trailing_to_render` keeps the tail, and the rationale is recency: *"Trailing rather than leading because the caller's list is oldest-first with the recency tail last: when something has to go, it is the oldest turn"* (`src-tauri/src/companion/prompt/budget.rs:60-63`). That is correct for relevance and exactly wrong for the cache, since the oldest turn is the most-cached one.
**Verdict: `adapt`.** The trade is real and the current choice is defensible; what is missing is that the two forces were never weighed against each other, because until §5.2's instrument shipped there was no number on the cache side. Re-decide it with the number.

**5.4 — Volatile recall at the tail.**
Router: the whole prefix-stability rule exists to keep volatile content out of the front.
personas: the runner already does this, and does it well. Agent memory, knowledge-registry consult, prior human-review decisions, team shared knowledge and the team alignment block are all appended **after** the entire assembly (`src-tauri/src/engine/runner/mod.rs:1117`, `:1179`, `:1220`, `:1255`, `:1304`).
**Verdict: `keep ours`.** This is the cache-correct design, arrived at independently, and it is the reason §5.1's nonce is worth fixing: the append discipline is already right, and the nonce is what wastes it.

**5.5 — A budget that is a flare, not a fence.**
Router: over-window is a typed failure — the tiered cascade runs, and if even the trimmed floor overflows it returns `ErrContextWindowExceeded` → HTTP 413, *"distinct from the 'no provider keys' `ErrNoEligibleProvider`"* (`internal/proxy/CLAUDE.md:42`).
personas: *"Observability ONLY: [`warn_over_budget`] emits at most one `tracing::warn!` per assembly naming every block over its tripwire, and **NEVER truncates**"* (`src-tauri/engine/src/prompt/budget.rs:4-5`), and *"a huge prompt still ships; this is the flare, not the fence"* (`:86`). Total tripwire 200,000 chars (`:16`), measured in `chars().count()` (`assemble.rs:1042-1046`).
**Verdict: `keep ours`.** A desktop app that refuses to run the operator's persona because the prompt grew is worse than one that runs it and warns; the CLI will report the real failure with a real message. The honest naming — flare, not fence — is why this is `keep ours` rather than a defect: the tree does not pretend the tripwire is a limit.

**6.3 — Two defensive copies of one rule.**

## 7. Observability and correlation

**7.1 — Bind the correlation id before the body parses.**
Router: `observability.Middleware` binds `request_id` at first touch, *"Bound here rather than deeper because the body is still unparsed: first touch is what makes pre-parse failures findable at all"* (`internal/observability/logger.go:250-264`), and the guide states the failure it fixed — *"pre-parse failures ('Failed to parse Anthropic request') used to be untagged, which made exactly the errors you go hunting for the ones you could not find"* (`CLAUDE.md:214`).
personas: **there is no span for a run.** `run_execution` takes `execution_id: String` as a plain argument (`src-tauri/src/engine/runner/mod.rs:114-127`) and carries no `#[tracing::instrument]`; the attribute exists in the tree only on read-side Tauri commands (`src-tauri/src/commands/communication/observability/metrics.rs:53`ff). So `execution_id` reaches a log line only when a call site types it out, and the `tags.execution_id` convention appears at eight sites — three of which are INFO/DEBUG and therefore never reach Sentry at all under the level filter at `src-tauri/src/logging.rs:76-80`. The de-facto correlation surface is the filename: one `{execution_id}.log` per run (`src-tauri/engine/src/logger.rs:19-21`), so lines are correlated by *which file they are in* and carry no id themselves.
**Verdict: `adopt`.** One `#[tracing::instrument(fields(execution_id))]` on `run_execution` — or an `info_span!` around the failover loop — makes every line under it filterable without touching a single call site. This is the largest observability return per line of diff in the study.

**7.2 — Never adopt a client-supplied identifier into the authoritative key.**
Router: *"Always mint a fresh id; adopting an inbound one lets a client reuse a value across requests and breaks `request_id` as a unique key"* (`internal/observability/logger.go:259-261`); an inbound `X-Request-Id` lands in `upstream_request_id`, sanitized and length-bounded (`:268-270`), asserted by a test (`internal/observability/logger_test.go:44-45`, `:74-75`).
personas: mints all of its ids itself — `execution_id` at `src-tauri/db/src/repos/execution/executions.rs:672`, `trace_id` at `src-tauri/core/src/trace.rs:216`, the W3C traceparent at `:490-503`. There is no inbound HTTP surface to adopt from.
**Verdict: `keep ours`.** A local-first app with one operator has no untrusted caller supplying identifiers; the router's rule protects against a multi-tenant failure personas structurally cannot have.

**7.3 — A bound key must never be re-passed, and a test enforces it.**
Router: *"`slog` does not dedupe: re-passing `request_id`, `session_key`, `client_session_id`, `api_key_id`, `ingress`, or `name` emits the key twice and JSON consumers keep the **last** value, overwriting the bound one — so the line goes missing from exactly the search that should find it"* (`CLAUDE.md:218`). Two tests hold it: `TestGlobalLoggerBudget` fails when a package gains an untagged log site (`internal/observability/global_logger_budget_test.go:57-58`, always-bound keys at `:159`) and `TestNoReservedLogKeyShadowing` fails when a call passes an already-bound key (`:185-187`). The guide instructs the fix: *"fix a failure by threading ctx, not by raising the budget"* (`CLAUDE.md:183`).
personas: **no reserved-key discipline and no such test.** The repo's only `RESERVED_` constant is about process env, not log keys — `CLI_SUBSCRIPTION_RESERVED_ENV` (`src-tauri/engine/src/cli_process.rs:36`), enforced at `src-tauri/src/engine/runner/credentials.rs:932-936` and asserted by `reserved_cli_auth_env_names_never_injected_from_vault` (`:1172`).
**Verdict: `adopt`.** Both the rule and the test shape. And the precedent is personas' own: the env-var reserved-name discipline is exactly the right pattern, applied to the wrong subject.

**7.4 — Where the tag vocabulary lives.**
Router: in the guide CI checks. The two-layer correlation table (`CLAUDE.md:207-212`) sits in the file `make check-agent-guides` verifies (`.github/workflows/docs.yml:26`).
personas: in prose, in a notes file, pointing at ADRs that do not exist in the repo. The vocabulary — exactly two keys, `execution_id` and `persona_id` — is fixed at `.claude/codebase-stack.md:717-721`, with a real mechanism rationale (*"sentry-rust's Hub is thread-local, and tokio's work-stealing multi-threaded runtime can migrate an async task across OS threads at any `.await`"*). Six code sites cite `[[Architect/decisions/2026-05-10-sentry-execution-scope-tags]]` (`runner/mod.rs:1564`, `:1951`, `:1953`, `:2458`, `hooks/observers.rs:35`, `ai_healing.rs:407`) and the decision files are in an external Obsidian vault — there is no `docs/adr/` in this tree.
**Verdict: `adopt`.** Six code comments pointing at a file an agent cannot open is the same defect the router's mirror-notice pattern exists to prevent. Either the ADR comes into `docs/`, or the rule moves to `.claude/CLAUDE.md` where the doctrine already lives.

**7.5 — An identifier written and never read.**
Router: every telemetry surface joins on `route_id`, and the harness makes it a release gate — *"Verify model/provider/artifact/roster/route-key/rollout telemetry and lifecycle callbacks join on `route_id`"* (`docs/POLICY_ROUTER_HARNESS.md:219`).
personas: five identifiers per run — `execution_id`, `trace_id`, `traceparent`, `chain_trace_id`, and the budget ledger's `run_id` (`src-tauri/core/src/run_budget.rs:94`) — with no column or query joining any two. `traceparent` is minted, persisted and injected into the child env with the stated intent that *"the spawned Claude CLI ≥ 2.1.110 participates in the same distributed trace"* (`src-tauri/src/engine/runner/mod.rs:1646-1658`, injected at `:1826`), and **nothing reads it back**. It is excluded from the read projection under a comment claiming it is *"written here and read elsewhere"* (`src-tauri/db/src/repos/execution/executions.rs:89-92`) — a claim that holds for the other six columns listed and not for this one. `core/src/trace.rs:468-470` states the real position: *"We do NOT emit OTLP spans here — there is no collector wired up yet."*
**Verdict: `adapt`.** Not the collector — a local-first app with `llm_tracking: internal` declared and an external tracer *"reconfirmed declined 2026-07-26"* (`app-passport.json`) should not grow one. What transfers is the honesty: either the traceparent gets a reader or the projection comment stops claiming it has one.

**7.6 — Redaction at the durable sink.**

Sentry adds a fifth at `before_send` / `before_breadcrumb` (`src-tauri/src/main.rs:100-149`), including dropping sensitive breadcrumb data keys (`:127`).
**Verdict: `keep ours`.** Five layers, one of them found by measuring the operator's actual log directory (*"3,018 files / 410.6 MB going back 130 days"*, `logger.rs:42-45`), against a prose rule. The gap is the parity test in §6.3, not the coverage.

## 9. Configuration and deployment posture

**9.1 — An unknown mode panics at boot rather than defaulting.**
Router: `ROUTER_DEPLOYMENT_MODE` is read once in the composition root; `selfhosted` and `managed` differ in which surfaces mount at all, and *"Setting variable to any other value panics at boot"* (`CLAUDE.md:232-237`). `panic` is reserved for exactly this (`CLAUDE.md:227`).
personas: `EngineKind::from_setting` warns and falls back to `ClaudeCode` (`src-tauri/core/src/engine_kind.rs:52-61`), and `"codex_cli"` maps to the same variant as a deliberate legacy alias (`:88`). But the closed set is proved exhaustive **at compile time**, not guarded at runtime: `assert_all_covered()` is a `const fn` exhaustive match evaluated by `const _: () = EngineKind::assert_all_covered();` (`:37-48`, `:79`), written *"preventing BYOM policy enforcement gaps"* (`:31-36`).
**Verdict: `keep ours`.** A desktop app must not panic at the operator, and the substitution is one variant wide with a warn attached. More to the point, personas already holds the guarantee the router's boot panic is a proxy for — the router panics because a bad mode string could otherwise reach dispatch; personas cannot construct an unhandled variant at all, because the compiler proves the match total before the process starts.

**9.2 — Public-repo hygiene as a stated rule. — SEED 10.**
Router: *"Never put customer/company/org names or private identifiers in anything committed here. This repo is public — commit messages, branch names, PR titles/descriptions, code comments, tests, and fixtures are world-readable. This holds even when a change is motivated by one customer's investigation … describe the trigger generically"* (`CLAUDE.md:222`). The tree honors it: the incidents cited throughout `internal/proxy/CLAUDE.md` are dated and de-identified (*"prod 2026-08-28"*, *"one org's monorepo"*). There is **no** secret-scanning tooling — no gitleaks config, no scan in CI.
personas: the repo is public (`github.com/xkazm04/personas`, `visibility: public`) and has the tooling the router lacks — `.gitleaks.toml`, `.gitleaksignore`, a pre-commit scan (`lefthook.yml:26-27`), and three census rules of the same shape (`settings-key-holding-secret`, `secret-as-bare-string-field`, `data-decided-secret-masking`). But there is **no stated rule**: `CONTRIBUTING.md` (175 lines) has no security section at all, and grepping `.claude/CLAUDE.md`, `CLAUDE.md`, `CONTRIBUTING.md` and `.claude/rules/*.md` for `world-readable` / `public repo` / `customer name` returns nothing. Two mechanisms also fail open: the scan *"SKIPS with an install hint (exit 0) instead of breaking the commit"* when gitleaks is absent (`scripts/secret-scan.mjs:21-25` — a case `run-census.mjs:22-23` names as canonical), and **no GitHub workflow runs gitleaks at all** — the only CI-side secret detection is `.gitlab-ci.yml:158`, on a forge `audit.yml:43-45` describes as *"a second forge nobody watches."*
**Verdict: `adopt`.** The two halves are split across the two repos: the router has the rule and no scanner, personas has the scanner and no rule. And a scanner is the wrong instrument for the risk personas actually carries — gitleaks catches a key; it does not catch an operator's employer, client, or private incident named in a comment explaining why a workaround exists, and personas' doctrine files are unusually dense with exactly that kind of prose.

**9.3 — Config as environment vs. config as user state.**
Router: *"All router configuration is via environment variables (12-factor)"* with an exhaustive reference (`docs/CONFIGURATION.md:3`).
personas: settings rows in the operator's own SQLite (`src-tauri/db/src/settings_keys.rs`), with env used only for developer/bench escapes (`PERSONAS_ATHENA_MODEL`, `src-tauri/src/companion/session/model.rs:26-31`; `PERSONAS_CLAUDE_MD_PROJECTION`; `PERSONAS_HOOKS_SIDECAR`).
**Verdict: `keep ours`.** 12-factor config belongs to whoever deploys the process. In a local-first app the operator *is* the deployer and the config is their data — it should be backed up, restored and synced with the rest of their install, which an env var is not.

## 10. Layering and module guides

**10.1 — Import rules a linter enforces.**
Router: the three-ring layer model is prose (`CLAUDE.md:18-132`) **and** a `depguard` config — leaf utilities may not import anything under `internal/`; presentation may not import `internal/postgres`, `internal/sqlc`, `internal/translate`, any concrete provider adapter, or `pgx`; `pgx` is confined to `internal/postgres` and `internal/sqlc` (`.golangci.yml:16-44`).
personas: asked this exact question and answered it with measurements. `docs/concepts/golden-paths/crate-layering.md:22-24` — *"**The acyclic property is not a convention here. Cargo enforces it, for free, and it cannot be violated.** A path dependency cycle is a hard resolution error before a single crate compiles"* — with the count at `:29-30`: *"`core` names `personas_db`/`personas_engine` **0 times in 114 files**; `db` names `personas_engine` **0 times in 143 files**."* `:319-326` refutes the framing outright, and `:219-273` **built and measured two census candidates and declined both** — one because it matched **0 of 701** (*"a rule pinned at 0 is a gate that can never fail"*, `scripts/census/lib/engine.mjs:304-314`), the other because cross-manifest parity is not expressible in a matcher that reads one file at a time. The genuine gap is named there and unbuilt: `scripts/check-crate-dep-parity.mjs` (`:268-273`) does not exist. The real cost is elsewhere — `src-tauri/src/engine/mod.rs:45` wildcard-re-exports `crate::db::{byom, chain, memory_recall, model_routing, quality_gate}`, so `crate::engine::X` spans four crates and *"a call site cannot tell which one it reached"* (`crate-layering.md:31-43`, nineteen such modules at `:333-341`), which is why `src-tauri/src/engine/byom.rs` does not exist and a reader looking for it finds nothing.
**Verdict: `keep ours`.** `depguard` is a lint an author can silence with a directive; a path-dependency cycle is a resolution error that never reaches the compiler. personas has the stronger mechanism *and* the better artifact — a golden path that specifies two instruments, measures both, and refuses to ship a gate that would run green while checking nothing. The router's guide states its layer rules beautifully and has no equivalent record of what it tried and rejected.

**10.2 — A module guide per package, a generated mirror, and CI that rejects drift.**

**Verdict: `adopt`.** Two declared rules, two gates that cannot see their own violations, and one of them measured at exactly 0.00% coverage over 2,367 real file-edits. The router's full answer — one guide per package, a generated mirror, `make check-agent-guides` on every PR (`.github/workflows/docs.yml:26`) — is more than personas needs. **10.3 — Prose that carries its own corrections.**

**10.4 — When a shared abstraction is justified.**

**Verdict: `keep ours`.** Same number, better framing: the router's rule prevents a premature helper; personas' also prevents the more common case, a correct helper nobody adopts.

## 11. Testing discipline

**11.1 — Non-tautological tests as a stated rule.**
Router: an engineering principle — *"**Non-tautological tests** — every test must assert behavior that breaks if prod code deleted"* (`CLAUDE.md:16`) — restated in the test conventions: *"Real assertions only. Compare value code-under-test produced to value test author chose. Tautological assertions (`x == x`, 'constructor returns instance', 'mock called with X') rejected"* (`CLAUDE.md:190`).
personas: no *general* rule is stated — but a sharper, narrower one is, and it comes with a measurement the router's does not. `docs/concepts/golden-path-doctrine.md:288-299` — *"**A test that runs on one side of a boundary is a third copy, not a check.** … Both sides of a cross-language 'parity' pair ship a `PARITY_FIXTURES` list. Each asserts *its own* language's ladder against *its own* fixtures. Edit one ladder and its fixtures together and **both suites stay green**. Measured: the two mirrors this covers are at 100% agreement over 42 fixtures, 285 live rows and 33 helper comparisons — and **their tests could not have told anyone if they had drifted**"* — restated in five golden paths. The general form appears only as a rubric line in a model-bench judge prompt (`docs/tests/model-bench/judge-prompt.md:56`), and no lint, ESLint rule, census rule or CI check inspects a test body.
**Verdict: `adapt`.** personas' rule is the better rule — it names a specific tautology shape, quantifies it, and admits the suites in question are currently green *and* blind. What is missing is the router's one-line general form in the place a contributor reads before writing a test (`.claude/CLAUDE.md`'s conventions section), so the specific insight is not the only thing standing between the tree and a `x == x` assertion.

**11.2 — A pre-merge suite against real providers, path-gated, deterministic in CI.**
Router: `smoke/` boots the real router behind a record/replay MITM proxy, keyed on `sha256(method + path + body)` with volatile fields normalized out (`docs/SMOKE.md`), path-gated to `internal/proxy/**`, `internal/translate/**`, `internal/providers/**`, `internal/router/catalog/**`, `cmd/router/**` (`.github/workflows/smoke.yml:19-31`), replay-only on PRs so it needs no key, with a nightly re-record to catch upstream drift (`:32-35`). The doc names the two bugs that motivated it, both invisible to `go test`.
personas: six lanes (`vitest.config.ts`, `vitest.e2e.config.ts`, `vitest.cli.config.ts`, `vitest.integration.config.ts`, `vitest.evals.config.ts`, `playwright.config.ts`) plus cargo test. A real-provider suite **exists** and is deliberately outside the gate — *"Most tests round-trip through real Claude Opus calls (30-90s each)"* (`playwright.config.ts:50-51`), with the spawning spec gated on an env flag: *"Gated by `RUN_REAL_CLAUDE_TESTS=1` … Not part of the default CI gate"* (`tests/playwright/companion-real-claude-workflow.spec.ts:26-29`). But **no workflow of the seven applies a path filter at all** (zero hits for `paths:` / `paths-ignore:` / `dorny/paths-filter` / `changed-files` across `.github/workflows/`), Playwright never runs in CI (zero hits), the census runs only at pre-push (`lefthook.yml:98-99`), `e2e-smoke.yml:72` carries `continue-on-error: true`, and `vitest.integration.config.ts` is a dead lane — its include glob targets a directory that does not exist and its reporter import (`:3`) points at a file deleted in `afcb2fb4b`. And there is **no record/replay layer**: no cassette, nock, msw or VCR anywhere; `evals/README.md:17-20` calls recorded transcripts *"the next step"*. So the CLI's stream-json contract — the source of `model_used` (§3.1), `cost_usd` (§3.5) and both cache columns (§3.6) — is parsed by `src-tauri/engine/src/parser.rs` against no captured fixture of a real session.
**Verdict: `adapt`.** Not the MITM proxy — personas wraps a CLI, not an HTTPS call — and not path gating, which buys little on a trunk-based repo where *"development lands directly on master (no PRs)"* (`.github/workflows/ci.yml:4-6`). But the *cassette* transfers directly: one committed stream-json transcript from a real run, replayed through `parser.rs`, would pin the `usage.cache_creation.ephemeral_5m_input_tokens` fallback (`parser.rs:364-388`) that exists precisely because the CLI changed shape at 2.1.152. The router's replay-only PR job needs no key and no network; a `parser.rs` cassette needs neither either.

**11.3 — An instrument that checks whether it went blind.**
Router: the smoke cassettes are deterministic by construction, and a request field that varies per run must be added to `volatileBodyFields` *"or every cassette for that path becomes a permanent miss"* (`docs/SMOKE.md`) — a miss is a clean 502, not a hang.
personas: four fail-loud conditions, not one. `walked < floor` → *"THE MATCHER IS BROKEN, NOT THE CODEBASE CLEAN"* (`scripts/census/lib/engine.mjs:293-302`); zero matches → *"a rule pinned at 0 is a gate that can never fail"* (`:304-314`); a stale `exclude` (`:316-327`); and a count that rises **or drops** (`scripts/census/run-census.mjs:137-138`), the drop being *"usually a broken matcher, sometimes a real fix — never silently accepted"* (`.claude/CLAUDE.md:108`). The motivation is a list of this repo's own dead gates (`run-census.mjs:21-25`). And the corpus turns the idea on itself: `verification-that-cannot-fail` (`scripts/census/rules.json:4834`) scans `.github/**.yml` for `continue-on-error: true`, and its description ends *"DELETE THIS RULE rather than baselining it at 0 if the count ever reaches zero — the census cannot express 'must be zero'."*
**Verdict: `keep ours`.** personas is well ahead here and it is the most transferable thing in its own tree. A gate that distinguishes "the codebase got clean" from "my matcher stopped matching" is rarer than the gate itself — and every finding in this study that reads *"a rule nobody enforces"* (§9.2, §10.2, §11.2) is a case a floor would have caught, including the doc-sync hook that measured 0.00%.

**11.4 — A test that pins a doctrine rather than a behavior.**
Router: three, all named after the rule they defend — `TestGlobalLoggerBudget`, `TestNoReservedLogKeyShadowing` (`internal/observability/global_logger_budget_test.go:57`, `:185`), `TestEveryProviderHasFamilyAndEnvVar` (`internal/providers/CLAUDE.md:23`).
personas: 205 census rules and 21 custom ESLint rules, each carrying its golden-path doc, its baseline and its own precision argument — `bare-model-id-literal`'s description runs to a paragraph naming the measurement date, the research source, the five duplicate declarations, and the legal fix.
**Verdict: `keep ours`.** personas' census rules are doctrine-pinning tests at a scale the router does not attempt, and they carry their reasoning inline. What the router has that personas does not is doctrine pinned in the *language's own test runner*, where it fails in the same command a developer already runs — which is §11.1's rule and §8.2's proposed test, not a general gap.
