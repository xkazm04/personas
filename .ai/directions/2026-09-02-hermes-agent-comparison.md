## The one sentence that governs every verdict below

Hermes **is** the LLM client: `agent/conversation_loop.py:2259` runs
`while api_call_count < max_iterations …` around
`client.chat.completions.create(...)`, so it owns the message array, the cache
breakpoints, the compaction cursor and the tool schemas.
Personas **is not**: `.claude/codebase-stack.md:28` — *"the application does not
implement an LLM client. It shells out to the `claude` binary"* — and
`src-tauri/engine/src/provider/mod.rs:45` (`CliProvider`) abstracts a *binary*,
not an API. Every comparison point that touches the message array, the prefix
cache, or the turn counter therefore has a real chance of being
`different forces` rather than a gap, and saying so honestly is most of this
document's value. The points that are *not* protected by that asymmetry — the
durable store, the restart contract, the extension surface, the test harness,
the house law — are where hermes has something to give.

**Verdict tally across 76 points:** `adopt` **9** · `adapt` **20** ·
`keep ours` **39** · `different forces` **8**. The `keep ours` majority is the
expected shape and is not self-congratulation: personas is a desktop product
with 247 measured golden paths behind it, and hermes is a runtime. Where hermes
wins it wins on things a runtime is forced to solve — the durable store's damage
policy, the restart contract, the extension host — and those are the three
proposals.

## 1. Agent loop and turn design

| # | hermes | personas | verdict |
|---|---|---|---|
| 1.1 | One synchronous in-process loop: `agent/conversation_loop.py:1996` `run_conversation(...)`, head at `:2259`, tool dispatch at `:8073`, finalisation at `:9212` → `agent/turn_finalizer.py`. | No loop. `src-tauri/src/engine/runner/mod.rs:1` `run_execution` spawns `claude -p`, streams `stream-json` and persists; the loop is inside the child. Four labelled stages, `src-tauri/src/engine/runner/stages.rs:8`. | **different forces** — the turn loop is the vendor's; personas orchestrates *around* it. | 1.4 | Budget-grace call: `agent/conversation_loop.py:2259` `… or agent._budget_grace_call` lets one final turn run after the budget is spent, so the user gets an answer instead of a truncation. | `src-tauri/core/src/run_budget.rs:21` — the aggregate ledger "sets `exceeded`, emits one `tracing::warn!` … and **does not abort**". ## 2. Orchestration and delegation

| # | hermes | personas | verdict |
|---|---|---|---|
| 2.1 | `delegate_task` spawns a subagent with an isolated context inside the same process; the parent sees only the call and the summary (`tools/delegate_tool.py:16`). | 2.8 | No interactive-terminal fleet. | Fleet is a third spawn path: `src-tauri/src/commands/fleet/pty.rs::spawn_session` runs `claude` in a real PTY, with a bounded 512 KB output ring and a reader that always drains "so the PTY pipe never fills and claude never blocks" (`src-tauri/src/commands/fleet/registry.rs:32`, `:37`). | **keep ours** — inverse-list item; watching a human-driven CLI session is a capability hermes has no shape for. |

## 3. Session state and the DB

| # | hermes | personas | verdict |
|---|---|---|---|
| 3.1 | `hermes_state.py:1-15`: one SQLite store, WAL, FTS5, and "compression-triggered session splitting via `parent_session_id` chains" — a long conversation becomes a chain of sessions rather than one growing row. | Two DB files (`personas.db` operational, `personas_data.db` user data, `.claude/codebase-stack.md:684`), WAL at `src-tauri/db/src/lib.rs:357`, pragmas per connection at `:236`. Sessions are `chat_session_context` + `chat_messages`; there is no parent chain. | **adapt** — the chain matters when one conversation outlives one context window. Personas' chat *does* (`--resume`), and its read is a blind reverse window of 200 (`src-tauri/db/src/repos/communication/chat.rs:25`). |
| 3.2 | Corruption class decides the response (`docs/state-db-recovery.md:11`, `:26`): a corrupt **derived** FTS index detaches (drop triggers, `fts_stale` marker, serve `LIKE`) and canonical writes continue; a bare `SQLITE_CORRUPT` on canonical structure **quarantines the handle and stops writing**. | **Absent.** Verified: no `integrity_check`, no corruption branch anywhere in `src-tauri/db/src/lib.rs`. Recovery is a pre-migration copy with `MAX_BACKUPS = 3` (`src-tauri/db/src/backup.rs:1`, `:28`) plus row reconciliation. It would live in `src-tauri/db/src/lib.rs` next to `apply_standard_pragmas` (`:245`). | **adopt** — personas has exactly the two data classes the rule keys on, a 347 MB user store, and a rotation of three that a damaged file will silently consume. See proposal `2026-09-02-store-damage-policy`. |
| 3.3 | The failing live operation never runs `FTS5('rebuild')`; a rebuild happens later under a cross-process admission lock (`docs/state-db-recovery.md:22`). | Personas rebuilds at **boot** when `executions_fts_drift` disagrees (`src-tauri/db/src/lib.rs:444`), and the drift check itself is measured: it reads `%_docsize`, not `COUNT(*)`, because the external-content table answers a full scan from the content table and "could never differ" (`:433-438`). | **keep ours** — boot is the right moment for a desktop app, and personas found the trap the naive check hides. Take only the "never on the live write path" clause. |
| 3.4 | Restart recovery classifies rather than declares: sessions touched in the last 120s get `resume_pending=True, resume_reason="restart_interrupted"` and auto-continue on next access; the mark survives until a turn *succeeds* (`docs/session-lifecycle.md:392`, `:423`); a JSON restart counter escalates to `suspended` after 3 (`:402`); a `.clean_shutdown` marker skips the sweep entirely (`:434`). | `recover_stale_executions` marks every `running` row `Failed` with "App restarted while execution was running" (`src-tauri/src/engine/execution.rs:500-528`). Queued rows *are* re-admitted (`:530`), and a follower defers to a live leader lease (`src-tauri/src/boot/recovery.rs:33`). Personas' own corpus names the defect: `docs/concepts/golden-paths/os-process-reconciliation.md:306` — *"`recover_stale_executions` declares failure it did not observe … 74 of 2,188 executions carry its marker. No liveness check, no `unproven` state, no user surface."* | **adopt** — the golden path already prescribes "at boot, do not declare — classify" (`:57`) and names five blind-fail passes against one classify pass. Hermes supplies the missing escalation half. See proposal `2026-09-02-restart-class-recovery`. |
| 3.5 | Reset policy is a first-class config: `none` / `idle` (1440 min) / `daily` (04:00) / `both`, per-platform, with sessions holding active background processes never expired, and a context notice injected on the first message after a reset (`docs/session-lifecycle.md:294-344`). | `src-tauri/engine/src/session_pool.rs:1` caches the last `claude_session_id` per persona for 30 minutes. No policy modes, no exclusion for a live run, no notice to the user that context was dropped. | **adapt** — the exclusion rule ("never expire a session with work in flight") and the user-visible notice are the two halves worth having; a daily-boundary reset is meaningless for a desktop app that is closed overnight. |
| 3.6 | Queuing: one "next-up" slot per session with **burst collapse** (a repeat send overwrites), plus an overflow FIFO promoted one at a time, and an explicit "if no adapter available, push back — don't silently drop" (`docs/session-lifecycle.md:455-497`). | `src-tauri/engine/src/queue.rs:7` `DEFAULT_MAX_QUEUE_DEPTH = 10` with three priorities (`:21`) and a typed `AdmitResult` (`:53`). Nothing collapses a burst. | **adapt** — for executions personas' priority queue is the better instrument; for the *chat* lane, where a user sends three messages while a turn runs, burst collapse is the missing behaviour. |
| 3.7 | Agent cache: LRU 128, idle TTL 1h, and a memory-pressure valve because "a cached agent pins `_session_messages`, the full live transcript … tens of MB" with three protected classes (`docs/session-lifecycle.md:583-608`). | `src-tauri/engine/src/prepared_run_cache.rs:10` `PREPARED_RUN_TTL` 5 min / `MAX_PREPARED_RUNS` 64; the cache key is a SHA-256 over every prompt input and deliberately excludes episodes "because they append on every run" (`:29`). | **keep ours** — personas caches a *prompt*, not a live transcript, so the pressure valve has nothing to relieve; and the deliberate key exclusion is the sharper piece of thinking. |
| 3.8 | A turn lease serialises the load→run→flush region per resolved `session_id`, because the busy guards are keyed by *routing key* while the transcript is owned by *session id* (`gateway/turn_lease.py:3`). | The equivalent split exists (`chat_lane_owned_externally` keyed by lane, executions keyed by `execution_id`) but there is no lease over the read-modify-write of a chat transcript. | **adapt** — a small, well-named seam; `gateway/turn_lease.py:18` states the failure mode in one sentence and personas has the same two keys. |

## 4. Memory design

Inverse-list item. |
| 4.2 | No decay model in core. | # | hermes | personas | verdict |
|---|---|---|---|

| 5.2 | Routing is per profile and per cron job (`AGENTS.md:1207`), plus OpenRouter-level `provider_routing` sort keys (`CONTRIBUTING.md:326`). | A CSS-specificity cascade: `src-tauri/db/src/model_routing.rs:1`, precedence `explicit > persona_id > category > universal` (`:12`), specificity function (`:81`), tie-break "last declared wins" (`:121`), and learned rules carry `RuleProvenance { proposal_id, evidence_snapshot_id, claim }` (`:46`). | **keep ours** — a routing rule that carries the evidence snapshot that proposed it is a governance property hermes has nothing like. # B. Features to propose

Ranked. Each line says why personas' declared scope
(`.ai/manifest.yaml:96-103`) admits it.

1. **Runner extension surface with two return contracts** — scope says "observe
   runs — cost, health, traces"; observation is exactly the surface that must
   never be able to change behaviour by accident, and `HOOKS_DESIGN.md` already
   exists without that split. → proposal `2026-09-02-runner-extension-surface`.
2. **Restart-class recovery (classify, don't declare; escalate a poison run)** —
   scope says "run local AI agent personas over wrapped CLIs"; a wrapped CLI
   whose host restarts is the normal case, not the exceptional one, and the
   golden path already prescribes classification.
   → proposal `2026-09-02-restart-class-recovery`.
3. **Store-damage policy keyed on the corruption class** — scope says
   "local-first storage"; local-first means the user's only copy, and personas
   currently has three rotating backups and no rule for what a damaged file
   should stop doing. → proposal `2026-09-02-store-damage-policy`.
4. **Opt-in egress allowlist for spawned CLIs** — scope admits it only weakly
   (there is no "does_not" line against local network policy), and personas
   already runs a local HTTP service the child could be pointed at; ranked below
   the top three because `--dangerously-skip-permissions` is a deliberate
   product decision (9.2) and reversing its blast radius is a bigger argument
   than a proposal.
5. **Live-database guard in the test harness** — scope-neutral (it is hygiene,
   not capability), and it is the cheapest item on this list; it belongs on the
   backlog rather than in a direction proposal because it changes no user-facing
   behaviour (10.2).
6. **Cron catchup/grace window and a per-tick hard interrupt** — scope says
   "tune routing from evidence", and a schedule that silently skips a fire the
   app was closed for is evidence the operator never sees (2.6).
7. **Burst collapse on the chat lane** — small, scope-admitted ("multi-locale
   desktop UI"), and it is the one queuing behaviour personas' priority queue
   does not express (3.6).
8. **Auto-block a step after N consecutive non-successes** — one rule from
   hermes' kanban, applied to `team_assignment_orchestrator`; deliberately *not*
   a board, because personas' pipeline findings were already declined for lack
   of usage (2.4).

# C. What personas does better, and hermes could learn from

The comparison would be worthless one-sided. These are the places where reading
personas would improve hermes.

1. **A ratcheting census instead of a review culture.** 204 regex rules with a
   measured baseline that fails on a rise *and* on a silent drop *and* on a rule
   that matches nothing (`.claude/CLAUDE.md:86-140`). Hermes' equivalent debt —
   "hook wire-up drift is the killer bug class: CI-check that every declared
   hook has a live dispatch site" (`docs/rfcs/…:113`, verdict *Adopt now*) — is a
   census rule, and hermes is about to build it as a bespoke script.
2. **Bounding a loop by progress rather than by count.**
   `src-tauri/src/engine/deliberation.rs:32-53` — a stall counter, a per-tick
   rate shaper, a forced-convergence round, and "an unparseable / silent round
   counts as a stall". Hermes bounds by `max_iterations = 500`, which is a proxy
   for the thing personas measures directly.
3. **A first-party memory engine with a value model.** Decay with category-aware
   half-lives, greedy budget packing that skips rather than truncates, tombstones
   that survive their subject's deletion, dispute claims that sink a memory until
   a human answers (`memory_recall.rs:144`, `memory_claims.rs:1`,
   `e16_living_agent.rs:11`). Hermes' core memory is two markdown files totalling
   3,575 characters.
4. **Prompt-injection defence as a type, not a scanner.** Every user-controlled
   value through `sanitize_runtime_variable`, nonce-fenced, canaried, and the
   whole module `pub(super)` so the assembler is the only caller
   (`src-tauri/engine/src/prompt/README.md` §Invariants). Hermes has point
   scanners on cron, skills and memory content, and no structural boundary.
5. **Secrets at rest.** OS keychain, AES-256-GCM, mlock + zeroize, tracked key
   provenance, per-session RSA for IPC (`src-tauri/core/src/crypto.rs:316-569`).
   Hermes stores `.env` files and isolates them with a contextvar.
6. **Redaction with a stated bias and a stated boundary.** At persistence, not at
   emission; patterns plus an entropy sweep; "better to miss an exotic secret
   than to corrupt legitimate IDs" (`src-tauri/core/src/redact.rs:1-18`).
7. **Routing rules that carry their evidence.**
   `RuleProvenance { proposal_id, evidence_snapshot_id, applied_at, claim }`
   (`src-tauri/db/src/model_routing.rs:46`), plus effort tiers calibrated on a
   1,026-turn bench rather than chosen. Hermes routes by config.
8. **Compiler-enforced layering.** `docs/concepts/golden-paths/crate-layering.md:25` —
   "The acyclic property is not a convention here. Cargo enforces it, for free."
   Hermes' `gateway/run.py` is 1.70 MB and its decomposition is a campaign.
9. **A `Withdrawn` section.** Claims that were tested and refuted are kept, with
   the refutation, so they are not reinvented a fourth time
   (`docs/concepts/golden-path-doctrine.md:894`). Hermes' RFC has "verified
   absences"; it has no memory of its own refuted beliefs.
10. **Publishing the failure rate of your own enforcement.**
    `.claude/CLAUDE.md:451` reports that the documentation-sync Stop hook has
    fired on 0.00% of 2,367 file-edits. Almost no repository measures the gates
    it already believes in.
11. **Concurrent agents on one checkout.** The `active-runs.md` ledger plus five
    parallel-safety primitives, each derived from a dated incident, including the
    isolated-index ritual and its two subsequent corrections
    (`.claude/CLAUDE.md:347-436`). Hermes has never had to solve this.
12. **A cost-probe that costs nothing.** `cli_capabilities.rs:1` spawns a bounded
    `claude -p`, reads the `system/init` tool registry, kills the child before a
    turn runs — "a probe costs ~$0" — and uses it to gate a tier-dependent
    feature. Hermes asserts capability from config.
