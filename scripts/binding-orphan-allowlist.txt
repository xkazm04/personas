# Baseline: files in src/lib/bindings/ with NO `#[derive(TS)] #[ts(export)]` type
# behind them. ts-rs never deletes, so each of these is frozen at whatever shape
# it had the day its Rust type went away -- while the command it types kept moving.
#
# scripts/check-binding-orphans.mjs fails on any orphan NOT listed here, and ALSO
# fails when a listed name stops being an orphan (census convention,
# scripts/census/rules.json:1-20) -- a silent drop is what a broken matcher looks
# like, so clearing one costs a deleted line here.
#
# MEASURED at the commit that added this file: 1,008 `#[ts(export)]` types across
# src-tauri/, 1,039 binding files, 35 orphans. Of the 35, **30 are still
# referenced by app code and 20 are still the declared return type of a live
# `invoke<T>`** -- which is precisely why scripts/check-unused-bindings.sh
# protects them: "imported" is its definition of used, so the most dangerous
# orphans are the ones it certifies as fine.
#
# Two sub-classes, both real, distinguished in the reasons below:
#   * 13 whose Rust type STILL EXISTS but no longer carries the TS derive. The
#     binding and the struct drift apart with nothing comparing them.
#   * 22 with no Rust type of that name at all. The command behind most of these
#     returns `serde_json::Value` today, so the TS type is a claim nobody checks.
#
# The recorded figure for this population was 29 (2026-08-17, three independent
# implementations reporting 48/31/29). This walk finds 35 and resolves the three
# `declare_lifecycle!`-generated types the loosest of those got wrong.
#
# NONE of these is fixed here: every fix is either a Rust edit (restore the
# derive, or give the command a named return type) or a regeneration run, and
# both need cargo. They are baselined so the NEXT one costs a line in this file.
#
