## Caveats and what was not measured

- Measured on a DEV build (Vite dev server, React development mode): absolute ms overstate a production build; the ranking and the blank/CLS/waterfall SHAPE transfer. Re-run against `tauri:dev:test` built with `--release`-like settings before treating a ms number as a regression.
- "Cold" = first visit in this page load. The probe never reloads the shared webview, and the shell idle-prefetches section chunks (navPrefetch.ts), so `scripts = 0` marks a module that was already warm; its chrome/content timings then measure render + data, not chunk fetch.
- Chrome and content are DOM heuristics (first new h1/h2/tablist/content-header; >= 40 visible chars or a >= 48 px figure outside chrome, ghosts and aria-hidden). A surface with no heading reports chrome n/a, which never fails the bar on its own.
- IPC depth is an UPPER bound on the fetch waterfall: two unrelated calls that ran back to back also chain. The bar uses the depth EXCLUDING commands already seen while parked (pollers, the park page); `ipcSequentialDepthRaw` keeps everything. A surface that genuinely re-fetches a command the park page also used is undercounted. Calls that bypass invokeWithTimeout (raw invoke) are invisible to ipcMetrics.
- This run (2026-10-20) counted the ghost grace window from t0; the blank-past-grace figures in this scorecard are DERIVED from total blank ms (blankMs - 150 - 67, two sampler frames of edge quantization). Later runs record it directly from the first blank frame (graceBase first-blank-frame).
- personas/editor/use-cases: setEditorTab("use-cases") did not stick (the editor redirects that tab), so that row measured the editor default tab.
- companions/curator:process reached the 8 s cap with no content by the heuristic (67 DOM nodes, ghost visible): either a ghost that never resolves or a figure the heuristic cannot see; carded as verify-first.
- Run order matters for coldness: this was the first walk of the page load except overview/executions and settings/limits, visited by a smoke run minutes earlier (both show scripts=0).
- design-reviews/n8n and design-reviews/presets: their depth-3 chains include batch_import_design_reviews and delete_stale_seed_templates, the DEV-only forced re-seed (src/hooks/design/template/useDesignReviews.ts:84, force: import.meta.env.DEV). A production build seeds once per session, so those two rows were not filed as cards.
