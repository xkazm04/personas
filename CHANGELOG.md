# Changelog

All notable changes to Personas Desktop will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Until a stable **1.0** release, minor versions may contain breaking changes to IPC commands, database schemas, or configuration files. Breaking changes are marked with **BREAKING** and always call out the migration path.

## [Unreleased]

### Added
- **The knowledge library leads with Directions** (Overview → Patterns). After the doctrine distillation collapsed 1,048 techniques into 114 governing directions, the surfaces now show that inversion: the Library sorts directions first and badges them, an altitude filter narrows to Directions or Techniques, and every pattern stack in the graph opens on its directions with the techniques underneath. The library reads as ~10 ways-we-do-things per area instead of a pile of code tricks.
- **Pattern campaigns: measure, fix in waves, re-measure** (Athena chat). The knowledge ops now compose into a self-advancing campaign for a repo whose adopted library has never been measured against the code — personas first: 432 adopted patterns, 49 contexts, zero verified cells. The campaign now opens with a **deep re-scan**: the original extraction rested on one shallow pass per territory with unmeasured depth, so harvest waves chain the same way verification does — each finished wave reports what it found and which territories still owe reading (never harvested, unmeasured, or under 70% depth), and the next wave targets the neediest ground until nothing owes. New finds merge with the existing canon (refinements link to their parents) and wait in the review queue; nothing is verified or applied until you have adjudicated them. Verification passes chain themselves: each finished pass wakes Athena with what was ruled and what still awaits a first verdict, and she starts the next pass until the honest answer is zero — then she plans apply waves **from the measured violations**, never from the library's size. Apply sessions take a context-group territory (up to four at once, each on disjoint ground, with the violation evidence in their brief), commit atomically, and never mark their own work as adherent — only the next verification pass can do that. Progress is counted in violating cells closed, not sessions dispatched.
- **Athena can now run the skills and knowledge loops herself** (Athena chat). She gained sight and hands over the two cross-project surfaces the app maintains: ask her about the **skill fleet** and she reads the real state — which skill sits at which version in which repo, which copies are behind the library, ahead of it, or locally customized, plus recent lessons — and can then **adopt** a skill into projects that lack it, **sync** copies that fell behind (customized copies are reported, never overwritten), or **publish** a project's improved copy to the library (refused unless it is a genuine version bump). Ask her about the **knowledge library** and she reads adopted patterns by area, playbooks, the review queue and which repos owe harvest coverage — and can then **dispatch practice harvests** (per-territory sessions whose results now land in the review queue automatically, with no window open), **apply adopted patterns** in a target repo (one session, atomic commits; only adopted canon qualifies, and the session changes code, never records), and **verify adherence** (the existing verification pass: drift is surfaced for a human, never auto-un-adopted). The whole loop keeps its one rule intact: she proposes and orchestrates, adoption is always your click.
- **The pattern fabric closed its loop** (fabric F4). Harvest items and consult proposals can now declare which existing pattern they *extend* — the ingest door records the lineage as a typed edge (dangling targets are reported, never silently dropped, and never block the item), and when an extension is adopted it automatically joins its parent’s topic when it has no home of its own. Adopted extensions of a playbook’s members surface in the rail as **suggested additions** — one click adds them in the parent’s phase, right after it; suggesting is mechanical, adding stays a curator’s call. And projects are now **born subscribed**: joining a workspace projects the full pattern bundle (router, briefs, consult skill, CLAUDE.md import) into the repo immediately, instead of waiting for someone to press “Project to repos”.
- **The pattern graph learned retrieval, honest depth, and self-maintenance** (Overview → Patterns → Graph; a /perfect wave). A search field finds any area, topic or pattern by fragment and flies you there — retrieval finally matches drill-down. Coverage rings, the project lens and pending halos now reach the third level (facet nodes measured in their own right; cluster rings are true sums of their parts). Playbooks show and repair their own decay: memberships pointing at deprecated patterns get a stale badge, one-click pruning, and replacement hints from supersedes/governs connections. Verification results now land at context grain — a verify run’s file citations mark exactly which contexts follow or violate each practice, with unattributable citations reported rather than dropped — so the rings begin telling the truth the trace layer was built for. And every consult call is logged: playbooks display 30-day match counts, and unmatched intents surface as the “missing playbook” inbox.
- **The pattern library became a three-level implementation map** (Overview → Patterns → Graph). Areas → high-level topic areas → concrete topics (15 → 69 → 246), with patterns stacking inside topics: a cluster that drills deeper says so with a count badge, unfolds its topic ring on click, and every stack is browsable — filter, sort by newest/evidence/title, 8 per page. Counterpart topics deliberately share nouns across branches (frontend tables beside server tables; concurrency tokens beside auth tokens), so the same implementation situation is findable from either side. All 432 surviving patterns were rewritten to the new bar — one-sentence titles, meta-level statements with steps/code demoted to detail — and 23 copy-paste snippets (one-line idioms with nothing to decide, single-repo inventories masquerading as patterns) were deprecated: the knowledge base teaches situations and approaches, not lines to paste. Also fixed: scrolling inside the pattern modal no longer zooms the canvas underneath, and the modal dropped its stats row and the truncated “governed by” chips.
- **CLI sessions can now consult the pattern fabric while coding.** Two channels. Live: the dev-tools HTTP bridge gains `/patterns/index`, `/patterns/consult?intent=…` (deterministic trigger matching; ACTIVE playbooks only, with near-miss drafts reported separately so "no coverage" and "awaiting activation" stay distinguishable; each brief annotated with the calling repo’s own adoption state and context-grain adherence — "already followed here, reuse its own exemplars first"), `/patterns/{id}` (full card + typed edges) and `POST /patterns/propose`, which reuses the harvest ingest door — proposals land `observed` with an optional `extends` edge; sessions propose, humans adopt, no second write path. Ambient: "Project to repos" now writes a tiered bundle instead of one flat file — a ~50-line router README (the only thing CLAUDE.md imports, migrated in place from the v1 line), a machine `index.json`, per-active-playbook phased briefs, the full library as an offline fallback, and a projected `patterns` skill carrying the consult ritual. Draft playbooks are deliberately not projected — activation in the rail is what makes a playbook consultable.
- **Playbooks: patterns bundled by situation** (Overview → Patterns → Graph → Playbooks). The library’s topics say where knowledge lives; a playbook says when it fires — “add a database table”, “expose a new IPC command” — bundling patterns from across branches into before / during / verify phases. Eight seeded playbooks arrive as drafts (12 patterns each, curated cross-branch), reviewable in a new rail on the graph: expand for the phased reading list, click through to any pattern, activate or retire. Build your own by bookmarking patterns across cluster modals (the selection survives closing them) and creating a draft from the basket — title, trigger phrases, summary, and a phase per pattern. Drafts never distribute anything; activation stays a deliberate step, like every adoption. This is the second Pattern Fabric layer (docs/concepts/pattern-fabric.md) and the surface the CLI consult door will read in F2.
- **Patterns can now relate to each other** (Overview → Patterns → Graph). A new typed-connection layer — governs, composes with, prerequisite, conflicts with, supersedes, extends — with the closed vocabulary the library’s other axes already learned to insist on. The 292 existing governing links were migrated onto it, so pattern cards in the cluster modal immediately show their relations as clickable chips (direction-aware: “governs” vs “governed by”), and cross-cluster connections draw on the canvas — but only inside a focused dimension, never at overview zoom, because cross-branch curves over the whole sky are how knowledge graphs become hairballs. Topics also quietly accept an optional third segment (`area/cluster/facet`) so clusters that outgrow ~10 patterns can split without a schema change — groundwork for the Pattern Fabric (docs/concepts/pattern-fabric.md).
- **Topic-graph coverage rings now measure contexts, not projects** (Overview → Patterns → Graph). A ring used to read 100% off one project-grain "adopted" cell even when only a corner of the project followed the practice. A new pattern×context table sits under the adoption matrix: every adopted practice × every mapped context gets a cell, mechanically seeded as *unverified* (or *not applicable* when the stack or layer clearly rules it out — and those never count against the ratio), with *follows*/*violates* reserved for evidence-citing verification. Rings and the pattern modal now show the honest adherence ratio — expect them to drop sharply at first: mostly-unverified is the true baseline the old rings overstated. Projects without a context map keep the previous project-grain share.
- **The orb shows you the reply, not just a count** (Athena orb). When a reply landed while the chat was closed, the orb raised a badge — which tells you *that* something happened without telling you whether it can wait, so the only way to triage was to open the chat, the exact interruption the minimized orb exists to avoid. The message itself now appears above her: short, properly formatted, with **Open chat** and — when a voice is configured — a control to hear it again. Dismissing means *mark as read* rather than *hide*, because leaving the badge up after you have read the words would make it lie. A pending decision still wins: a question addressed to you outranks news, so the message waits and returns the moment the decision clears.
- **Skills now carry a version, reflect on themselves, and show their history** (Dev Tools → Skills → Trace). Skills could be adopted, shared and counted, but what a run *taught* evaporated with the session, and no two projects could tell whose copy of a skill was newer. Three mechanisms close that. Every skill can now declare a `version:` in its frontmatter (major.minor: a minor bump is a prompt refinement, a major one a methodic redesign), and every dispatched skill run ends with a standard **reflection contract**: project learnings go to the existing memory ledger, and method learnings — the ones any project would benefit from — append to a `LESSONS.md` that travels with the skill, bumping the version only when the improvement is actually applied. The contract is honest by design: most runs are expected to record nothing, and an empty reflection is a valid result. Because sessions run offline, the app writes a **`.personas/skill-registry.json`** snapshot into each managed repo (on context scans, installs, and before dispatches) listing each skill's version, the workspace library's, and which sibling projects run it — everything a session needs to decide "publish this improvement to the library" versus "just record the lesson" without the app running. The new **Trace** tab makes all of it visible: an ember-matrix overview ranks skills by recency-weighted heat across the workspace's projects (a hollow ring marks the installed-but-unused ones), and clicking a skill opens a skill-tree view — the library at the core, one branch per project sized by usage, each node ringed by its version drift (behind / ahead / customized / in sync), with the lessons sprouting on the branches and the full version timeline beneath. Lessons also flow into the workspace knowledge review queue, with redesign proposals flagged for priority.
- **A twin and Athena's memory can now move to another machine** (Settings → Data → Export Workspace). The workspace bundle grows from five export scopes to seven. **Twins** ships one selectable row per digital twin: the profile, every per-channel tone, the whole training corpus (including the interview question behind each Q&A, which lives on the communication row and was the half most at risk of being dropped), the memory inbox in all three statuses with the reviewer's notes on the rejections, distilled facts with their citations remapped, reflections, contacts, channel bindings, and the bound knowledge base as text. **Athena memory** ships in two tiers instead of rows, because she is a singleton: **Core self** (her `identity.md`, a whitelist of portable preferences, and the conversation roster) and **Learned memory** (facts, procedurals, goals, backlog, rituals, design decisions). What does not travel is as deliberate as what does. Conversation history stays behind: Athena carries what she learned, not what was said. Doctrine stays behind because it rebuilds itself from the binary on first boot. A twin's slug, active flag, Obsidian path and voice config stay behind because they describe the machine, not the person. A test asserts every one of those exclusions by name, so a later section cannot quietly widen the payload. Both new scopes are **encrypted scopes**: they export only under a passphrase of at least 8 characters, and neither is preselected, because auto-ticking an encrypted scope would turn today's one-click "Export All" into a blocked button for anyone who owns a twin. Tick one without a passphrase and the export is refused by name rather than silently thinned; run a full export without one and the two scopes are omitted with a warning that says so. On the way in, a twin joins the same replace/skip/duplicate conflict panel dev projects already used (matched on name, never the machine-derived slug), Athena's memory **merges with dedup rather than replacing**, so a device that already has memory of its own loses nothing, and her `identity.md` is the one file genuinely overwritten, after a timestamped backup. Twin channels land disabled with a warning naming what to re-link, because auto-matching a channel onto whatever sits at that credential id could post as you to a stranger's Discord. The bundle carries text and never vectors, so a knowledge base is re-indexed on the target rather than shipped, and imported memories are re-embedded in the background. Finally, export **truncation is no longer silent**: the modal forecasts which caps you already exceed before you run it, and the bundle carries the drops it actually made so the receiving machine is told what did not arrive.
- **Rebuild search index** (Companion → Memory). Semantic recall only ever indexed a memory at the moment it was written, so anything that arrived any other way had text and no vector, permanently: a portability import, a restored brain directory, a write made while the embedder was down. Separately, recall has been quietly dropping hits whose vectors were recorded under a different embedding model and logging an instruction to re-embed the brain that nothing in the app could carry out. This action carries it out. It is safe to run at any time, a second pass finds nothing left to do, and on a build without an embedding model it says so instead of failing.
- **Two devices, one Athena to the other** (Settings → Devices). Personas installs on the same network could already see each other, and nothing more: the peer-to-peer layer had discovery, connections and health checks, but no way to establish trust and nothing to say over the link. Two machines can now **pair** — you pick the other device, both screens show the same six-digit code, and you confirm on the receiving one — after which **your Athena can hand the other device's Athena a plain-language instruction**, which it runs as a real turn with its own tools and its own approval rules, streaming back progress notes and a closing summary that arrive on your machine as memory it can report from. The new **Devices** tab lists paired machines, marks one as **home**, and keeps a full job history in both directions with each job's notes. Consent is deliberately mode-conditional: with autonomous mode **off**, instructions go only to the home device and each one waits for a click; with it **on**, they fire directly to any paired device, which is the same standing consent that switch already grants everywhere else. Pairing is the trust boundary and it is a real one — the handshake is a three-leg ed25519 signature exchange (two legs would leave the initiator's proof replayable, since nothing in the opening message is chosen by the responder), each leg checks that a peer's claimed identity actually hashes from the key it presents *before* verifying the signature, and job messages are accepted **only** from paired devices. That last check is separate on purpose: any device on your network may complete the handshake and read your public manifest, so **an authenticated connection is not a trusted one**, and the job path is where trust is enforced. Adding a device never strands one — when both machines already have devices of their own, pairing is refused and names the devices that would be orphaned, rather than silently splitting a group; when only one side does, the other joins it. Counts that arrive over the network are treated as claims, so a peer lying about being empty can only cause a refusal, never make you abandon your own devices. A dropped link costs nothing: work already running keeps running, and on reconnect each side replays exactly the notes the other missed, tracked by the highest unbroken run rather than the highest number seen, so a note arriving out of order cannot orphan the one before it. A job whose runner crashed is failed at startup and the result finds its way back. Athena also learns which machines exist and which are reachable, so she can pick one herself and will not offer to send work to a device that is offline. Requires a full build (`desktop-full`) on both machines, and the link has not yet been exercised across two live machines.
- **A dispatch panel that answers "what did I approve, and did it actually get sent?"** (title-bar → Approved work, `D` in keyboard-nav mode). Approving an idea and dispatching it were two different acts, and nothing in the app ever reported the gap between them: an idea could be accepted and then simply never become a task, invisibly, forever. The new right-docked panel lists every approved idea grouped by **project**, marks the ones with no task at all with a glyph-and-word tag (never colour alone), and shows how long each has been waiting using the backend's own `accepted_at`. Staleness is the backend's rule, echoed — `dev_tools_attention_queue` returns the thresholds it actually applied and the panel renders those; if it has not read them yet it says nothing about staleness rather than printing a cutoff of its own. One click sends the selection to the **Dev runner** or to **Fleet** — and this is the first time Fleet has been reachable from the UI at all; that dispatch arm existed only for the headless overnight engine. Because a Fleet session runs inside a project's folder on disk, an idea with no project (or a project with no path) **cannot** go, and the panel says so with a count before the click instead of letting it come back as a skip reason afterwards. What the dispatch actually did is reported in full: `dispatched` and `skipped` both, every skip carrying the backend's own wording, and never a success tone while a skip is present. The panel is an **overlay, not a column** (docking it in flow would fight the content area's responsive min-width floor and push the page into a horizontal scroll), and it is not a fifth list over `dev_ideas` — rows come from the same shared Backlog queue, and the panel restores the query that queue was serving when it closes. The tray capsule's badge is the length of that same undispatched list, polled on the shared 30s bucket; it collapses at zero and renders nothing before the first read, and is deliberately **not** folded into the human-review count beside it — that one counts decisions still owed, this one counts decisions already made that nothing acted on.
- **Name your fleet sessions, and pick a model and effort per session** (Athena chat → fleet plan). Every dispatched session was called `athena · <project>` or `athena-plan-3`, so eight of them on screen were eight identical labels and finding the one you cared about meant opening them. A plan row can now carry a **label** — which wins over the automatic naming, because the person who wrote the plan is the one who knows what that session is for — plus a **model** and a **reasoning effort**, so a cheap survey session and an expensive build session can sit in the same plan. All three are optional and validated as the plan is drafted, not when it fires: an effort outside the known set or a model value that could act as a flag never renders a card at all.
- **Athena can take you to the Mastermind canvas** (Teams → Mastermind). She could already read it, annotate it, compose panels on it and steer the camera around it — but not simply open it. Arriving also matters mechanically: mounting the canvas is what publishes the snapshot every one of those abilities reads, so "take me to the canvas" now doubles as the refresh when that snapshot is stale or missing.
- **Athena can see and add to the Dev Runner queue** (Dev Tools → Run Desk). The Run Desk is the second execution lane and she had no window into it, which meant she could start a Fleet session for work already sitting queued. She can now read the live queue (queued and running only) and propose a task for it. Proposing **queues** — starting it stays your click on the Run Desk, because that is where the spend happens and the queue is the thing you get to review first.

- **A finished session finally tells you it finished** (Dev Tools → Fleet, Athena chat). Completion was the one thing the fleet never reported: the trigger lane skipped finished sessions, the wake census let "everything is done" wait out the periodic window, and the completion event had no listener on the other end. Work would land and the only way to find out was to go look. A detected completion now writes a `[Fleet] <session> finished — <what it did>` line into the chat in the fleet's own voice, and — when it's work Athena dispatched, outside quiet hours — she says in a sentence what landed and what it unblocks. It announces **once per operation**, not once per session: a five-session dispatch reports when the last one is out, which is the difference between a report and a flood. This lane deliberately ignores the daily proposal budget — you asked for the work, you're owed the outcome.

### Changed
- **Autonomous mode approves everything now** (Athena chat). Turning autonomous mode on is a statement that Athena may act without asking, and yet two thirds of what she proposed still arrived as an approval card waiting for a click, because a fixed list of action names decided what was allowed to fire on its own. The list is gone. With autonomous mode **on**, every action she proposes fires immediately and no card is rendered; with it **off**, nothing changes and every proposal is a card exactly as before — the toggle is now the whole decision, and switching it off is how you get the clicks back. What still holds is what actually bounds the work rather than merely delaying it: she can only propose the actions her grammar defines, every session she starts stays inside a registered project folder, the boldness dial still governs typing into a terminal you may be using, self-development still requires dev mode and a debug build, and instructions to another device still refuse anything but your home machine when autonomous mode is off. Two things are worth knowing before flipping it on: a backlog triage can now apply up to 30 accept/reject verdicts without you reading them, and connector actions that write to the outside world — sending an email, posting a message — happen with no human in between. Actions that also move the app (opening a screen, prefilling a build) now take you there when they auto-fire, which previously only happened when you clicked.
- **Athena's side panel shows four kinds of work in one shape, and its schedules are hers** (Athena chat → side panel). Fleet sessions were a list, her live operations were a list, and the runner and schedules were two bare numbers on a strip at the bottom that vanished entirely when either was zero — so "nothing running" and "this doesn't exist here" looked the same. All four now read identically: a title with a count beside it, the rows beneath, a divider between. A lane at zero keeps its heading and says `(0)`. **Schedules** counted the app's own persona and trigger schedules, which have nothing to do with Athena — the number moved when you armed an unrelated cron. It now lists the check-ins *she* committed to in conversation, each with the time it is due, and Run Desk rows name the actual tasks and open the Run Desk when clicked.
- **The triage card gives its height to the case, and jumping the queue no longer reshuffles it** (title-bar → Human review). Two thirds of a card's first screen was meta rather than argument: a chip row and the project stamp owned a full row above the headline, a docked fact ledger owned one below it, and the prose between them was capped to a two-thirds-width measure inside three nested paddings. The chips, the project stamp and the score meters now all straddle the card's **borders** — meters and stamp on the top edge, kind and tags on the bottom — the ledger is gone (its facts were the ones no verdict ever turned on), and the headline sits alone on its row at the card's full width, one size down and no longer line-balanced so it actually uses that width. The prose starts roughly 60px higher and runs the whole card. Separately, **clicking a row in the queue rail used to pin that card to position 1**, renumbering the list you were reading around your own click and then carrying on from the front. It now moves a read head: the row keeps its number, the card is dealt where it stands, and the next card is the one below it — so a jump to 18 continues at 19. Deciding, skipping, undoing and a failed write all keep your place; running off the end wraps to whatever is still waiting at the top.
- **Athena's memory now consolidates when you've actually talked to her, not when a clock says so** (Athena → Memory). Her nightly maintenance pass ran on a 20-hour timer, and only inside an approved night-shift plan window — so a day of heavy work waited out the timer while a silent week burned a full pass on nothing, and anyone who never approved a plan got no consolidation at all, ever, while the feature looked shipped. It now runs on **sleep pressure**: 40,000 characters of new conversation since the last pass. On measured history that means a heavy day consolidates the same day and a few light ones accumulate into one. The clock survives only as guard rails — a 6-hour floor so one busy afternoon can't cycle twice, and a 72-hour release so a quiet week still gets compressed — and below 2,000 new characters nothing runs, because distilling a handful of turns produces a report saying it found nothing. The plan-approval requirement is gone; the night-shift switch itself still gates the unattended spend. **A pass that hit its input cap no longer strands what it couldn't read.** It reads oldest-first and records exactly where it stopped, so the remainder is the *next* pass's first material rather than a middle nothing ever reaches again — and when a pass declines to run it now says why in real numbers ("pressure 12,431 of 40,000"), not "not due yet".
- **The chat window opens instantly instead of hitching** (Athena chat). Everything inside it — the conversation, the alert stack, the toolbar rail, the Fleet panel, her video watermark — was being built inside the same frame that was flying the window out of the orb, so the animation had nothing left to run on. Measured on an empty conversation, the window took a third of a second to appear and the app was frozen for a quarter of a second of that. The frame now appears immediately with a quiet placeholder, and fills in the moment it has landed: **18ms to appear, down from 334ms**, with the longest freeze cut from 155ms to 94ms and pushed out of the animation entirely.
- **A session in the chat's Fleet panel opens its terminal, and the panel is a panel again** (Athena chat → Fleet side panel). Clicking a session now raises that session's terminal over the app, focused on it, with Back (or Escape) to return — and the conversation stays readable above it the whole time, so checking on a run never costs you your place. The panel itself was half-broken in ways that are obvious once seen: it sized to its contents, so a quiet fleet left a stub floating against the full-height chat column with its border stopping halfway down; and its collapse arrow was clipped by the panel's own edge into a half-moon that looked like it sat *behind* the chat. Both fixed. The "no sessions tracked" line is gone — the count directly above it already says zero.
- **System messages read like notes, not like Athena** (Athena chat). Anything the app itself wrote — a blocked connector call, a finished fleet operation, an action outcome — was rendered as an assistant bubble, complete with Athena's face beside text she never wrote, and its markdown was flattened into a paragraph so bullet lists and inline code arrived as a wall. These now render as a margin note: a hairline rail, a plain-language label saying what produced it ("Action blocked", "Fleet operation"), and the body as real markdown. Long ones — the connector rejection is several sentences of instruction written *for her* — collapse behind a **Show more** rather than making you scroll a briefing to reach the next message, and nothing is ever cut off mid-sentence with an ellipsis. **Markdown in the chat is also properly sized now:** headings were rendered at document scale, so a single `#` in a reply became a banner that pushed the answer below the fold. And **the shouting is gone** — every ALL-CAPS label across the chat, the orb and the decision cards is now written normally.
- **The orb's quick-input bar can hold a real exchange** (Athena orb). It is **50% wider**, and the reply above it is no longer three clamped lines of raw text with the ending cut off — it renders as markdown at reading size, sized to the answer, and scrolls past that instead of truncating. A paragraph fits without scrolling; anything longer scrolls. The input grew up too: it is now a field that expands as you type (Enter sends, Shift+Enter for a new line) so you can write a paragraph as well as read one, and it stops growing and starts scrolling before it can push the bar off screen. The header carries read-aloud and a button to open the full chat, and a turn in flight shows typing dots rather than the previous answer.
- **Athena's chat window: one progress surface, more room, and it stops hiding behind the app header** (Athena chat). A long conversation had become the slowest thing in the app and the busiest thing to look at, and both had the same cause — the panel was doing too much at once. Four fixes, all visible. **A turn now reports itself once.** While she worked, the same fact arrived four ways: a status line naming the live tool ("Reading files…"), a running log of every tool call with durations, an activity-tray task per slow tool, and the plan checklist. The bubble now says she is working, the typing dots say it is still true, and the **Stop reply** control sits inline right next to them instead of below the bubble. The only detail kept is the TodoWrite checklist, because that is her plan for *your* request rather than a transcript of her tooling — and her own progress beats still speak over the generic label. Nothing is lost: the tool trail is still recorded, still saved per turn, and still in the dev conversation-log export. **Long conversations stay quick.** Only the last **10 rounds** are kept on screen — a round being your message and everything she said in reply, so a cut never separates an answer from its question. Older turns come back on a click or simply by scrolling up, a page at a time, with your reading position held; only once everything loaded is on screen does it fetch genuinely older history. Underneath, the panel no longer re-renders every message on every frame of a reply, which is what made a day-long thread feel heavy. **The window is bigger and better behaved** — 20% wider when expanded, and its height is now capped so its own header can never slide up underneath the app's title bar, which it did on a tall screen. Resizing is animated rather than snapping. **Minimising means chat and nothing else** — the right-hand tool rail and the Fleet side panel both fold away, leaving a slim edge handle to expand again.
- **Small label text is readable text now** (everywhere). The `typo-label` token — the app's smallest strong tier, carrying badges, chips, column headers, section dividers and a great many one-line hints — was 700-weight, letter-spaced a full 0.15em, and forced to UPPERCASE with a line-height of exactly 1. That is display styling applied to text people are expected to read: acronyms and proper nouns disappeared into the surrounding shout, wide tracking cost real horizontal room in an already dense interface, and a line-height of 1 meant anything that wrapped overlapped its own descenders. It now reads as normal sentence-case text one size below `typo-title`, on the same recipe as the rest of the family, so a label / title / caption stack reads as three tiers of one voice rather than three unrelated treatments. Roughly 570 `uppercase` and `tracking-*` utilities scattered across 141 files came off with it — every one of them was already a no-op, silently losing to the unlayered token, and would have switched back on the moment the token stopped setting `text-transform`. Nine places that were using the label token for whole sentences (skill hints, build notes, a setup blurb) moved to `typo-caption`, which is body-sized, muted and meant for prose; four of those had already given themselves away by patching `leading-snug` onto a line-height the token would not let them change.
- **"Stale" now says which kind of stopped it means** (Dev Tools → Fleet). One amber bucket held three completely different situations — the task is **done**, the session is **waiting on you** for an answer or a permission prompt, or it is genuinely **wedged** mid-tool — and the only thing separating them was a sentence of prose the interface was string-matching. The 30-second check now reads the tail of each parked session's transcript and the terminal screen and returns a real verdict: a finished run is marked finished and announced (see above), a session waiting on a question or a permission prompt is flipped to *needs you* with a reason that says which, and a session with a tool call that never came back keeps its frozen verdict. A **done** session gets its own still, green treatment instead of pulsing amber next to a stuck one. The classifier abstains when the evidence is thin rather than guessing, a session whose log is still growing is never called frozen, and what's on screen beats what's in the transcript — a permission prompt parked in the terminal never reaches the log at all.

### Fixed
- **Putting a trigger behind human approval is now something you can actually do** (Agent → Design → Triggers, Event Bus). The safety gate for a trigger that fires on its own — run normally, run as a simulation, or hold for a person to approve — was fully built in the backend and unreachable from one end: the queue of held fires had exactly one screen that could show it, and that screen had no route into the app at all. All 165 triggers on this machine were on "run normally" and the held queue was empty, which is what "unreachable" looks like from the outside. The approvals queue now appears where the mode is set (scoped to that agent) and on the Event Bus page (workspace-wide, above every tab), each waiting fire naming the agent, the trigger, the event that arrived and how long it has been waiting — a held fire whose age you cannot see is a decision you cannot prioritise. A count in the Event Bus header says fires are waiting without you having to know the panel exists, and collapses to nothing when none are. The dead screen behind all this has been deleted.

- **An event can no longer disappear between being claimed and being finished** (Event Bus). The bus claims a batch of events by flipping them to `processing` in one atomic statement, which is what stops two overlapping ticks dispatching the same event twice. Nothing, however, ever returned a claimed event that its tick failed to finish — and cleanup deliberately exempts `processing` rows as in-flight, so a tick that died between claiming an event and recording its outcome left that event invisible forever: never delivered, never retried, never pruned, counted in neither the pending nor the dead-letter totals. A reaper now watches the claimed set and returns anything still holding a claim five minutes later, marking it so the Live Stream says the redelivery happened; an event that has burnt its retries is parked in the dead-letter queue rather than cycling forever. It is deliberately timid — a row must be seen holding its claim on two consecutive passes before it is touched, and the owning tick always wins the race — because re-dispatching work someone is still doing would be worse than the problem. **This is insurance, not a repair: there are no stranded events on this machine today.** The count is reported on the scheduler's own stats and logged as a warning when it is anything but zero, since a non-zero value means ticks are dying mid-flight.

- **An event that didn't start a run now says why** (Event Bus → Live Stream / Dead Letter). When an event reached the bus and no execution followed, the reason column was written as `NULL` — literally hard-coded — and each of the gates that drops a match did so silently. On this machine 22 events were sitting in `skipped` with nothing recorded: 22 moments where a trigger did not fire and the product could not say what stopped it. Every gate now records a machine token on the event — no subscriber matched, the agent is switched off, the fire is held for approval, a wildcard match crossed a team boundary, the capability was already running, the run went out as a dry-run simulation — resolved to a label in the interface like every other status token, never emitted as English from the backend. Rows written before this existed read as **unknown**; a reason is never invented for them. Two ways an event could disappear entirely came out with it: a webhook fire held for approval was left mid-flight with no terminal status at all — never delivered, never retried, exempt from cleanup — and a handoff dropped because its target agent was disabled tried to dead-letter itself through a transition the event lifecycle does not allow, so the write always failed, was swallowed, and the row stranded while the interface was told it had been dead-lettered.

- **The Templates header stops saying "50 templates"** (Templates). The count beside the page title was the length of whatever the page happened to have loaded, and that fetch takes the backend's default of 50 rows — so with 124 seeded templates on disk plus team presets, the number was simply wrong, capped, and gave no hint it had been capped. It now comes from a dedicated count query: one aggregate against the database rather than pulling the whole catalog into the window to measure it. While that query is in flight the header shows a placeholder instead of a confident zero, and the Templates tab's own paginated total is untouched.
- **The template integrity docs now describe the check that actually runs** (developer-facing). `check_template_integrity` sat at the top of the instant-adopt path and was documented as "the authoritative security gate". It could not fire: the checksum manifest is keyed by a template's file path and hashes the whole file, while every real caller passed a bare label plus the payload-only design JSON — so the template was "unknown" for 100% of adoptions and the tamper-reject branch was unreachable, with the release build only writing a warning. Fixing the key alone would not have helped, because the hashed content is a different document from the one the manifest was built over. The inert check has been **removed** rather than left as decoration, and `docs/features/templates/06-integrity-and-security.md` now says plainly what enforces integrity: the **catalog-load checksum check**, which drops a tampered template before it is ever seeded — so it can never reach any adoption path — while the compiled-in Rust manifest is a **detector** whose caller only logs. The threat-model section no longer claims an attacker would also have to patch the native binary; today, patching the bundle is sufficient, and the doc says so along with what it would take to close that. No behaviour change for legitimate adoptions.
- **A template that says "Ready" in the gallery is now actually ready to run** (Templates → Gallery). The readiness badge on a template card was computed by a different, weaker rule than the one that decides whether the persona can execute. The badge asked "is the connector installed *and* is there a credential with its name?"; the real gate asks the connector-readiness resolver, which understands that a zero-config connector needs no credential at all, that an aggregate connector is ready with nothing configured, that a native capability has no definition row, and that a stored credential which cannot be bound to exactly one connector is not a working one. The two disagreed **by construction**, in both directions: templates that would have worked were hidden behind "Setup needed", and templates the run gate blocks were advertised as Ready — you adopted one and only then found out. The gallery, the card preview and the side-by-side compare view now all read the same verdict the execution gate reads, resolved in one batched call for the whole page rather than one per card. A connector the resolver has not answered for yet shows as *checking*, never as a confident tick or a red cross, and a not-ready one now names **what** it needs — a Vault credential, a CLI sign-in, a Dev Tools project, an Obsidian vault, a Twin profile — instead of the old catch-all "needs credential".
- **Athena's nudges reach you instead of piling up unseen** (Athena chat / orb). She had written down 66 things worth mentioning and not one of them had ever been engaged. The reason: the moment a nudge was recorded was also the moment it had to win a delivery slot, and a nudge that lost landed in a state nothing on earth could release — no code path re-delivered it, the expiry sweep ignored it, and the duplicate guard treated it as proof she had already spoken. Twenty were sitting like that, the oldest for seven weeks: nine stalled project goals and three quiet fleet sessions she had spotted, recorded, and would never have mentioned. **Noticing and telling you are now two separate steps.** Writing a nudge down is free; one sweep on every five-minute tick decides which of the waiting ones to deliver, under exactly the same daily limits as before — the limits were never the problem (the ceiling of 12 a day has never once been reached), the delivery was. Nothing can strand any more: a nudge that misses a slot simply waits for the next tick, and one that has waited a day is retired rather than delivered stale, which frees the trigger to say it again with current facts — or stay quiet, if the situation resolved itself in the meantime. The same sweep finally runs Athena's own "I'll check back in ten minutes" commitments, which in normal operation had no caller at all; one had been sitting due and undelivered for two days. And a crash between recording a nudge and sending it now costs nothing.
- **Talking to Athena with the chat closed now actually starts a turn** (Athena orb / footer avatar). Hold-to-talk, the orb's quick-input bar and "Ask Athena" from a dashboard all hand their message to the same internal slot — and nothing was listening to it unless the chat window happened to be open, so the message sat there and no turn ever ran. The whole side channel had the same problem: replies streaming in, navigation she performs, cards she raises and approvals she creates were all handled only by the open window. That listening half now lives with the always-present part of the companion, which is where it should have been. As a side effect the orb's quick-input bar can show her last reply immediately instead of only after you have opened the full chat once.
- **Athena no longer pastes a wall of JSON into the chat after moving the canvas** (Athena chat / Teams → Mastermind). When she steered the Mastermind canvas, the reply from the canvas — camera coordinates, a zoom level and a list of island ids, written for *her* to read on the next turn — was rendered into the conversation verbatim, which is useless to a person and buries whatever she actually said. She now states it in a line: "Travelled to a project on the canvas — close view · 14 projects in view", or, when the canvas refused, why: "Couldn't steer the canvas — the view was zoomed too far out". The full readback is untouched in her memory, so nothing she needs was traded away for the shorter sentence.
- **A dev merge that says it worked now has to prove it — and one that refuses no longer strands the work** (Athena dev mode). The `dev_merge` handshake reported success straight out of its strategy choice and then pruned the worktree and deleted the branch on that unverified word, which is the one combination that can actually lose a commit. Three failures came out of it, all fixed. **"Already applied" was reported as total failure:** when a parallel session had landed the same change on master first, the cherry-pick came back empty, git exited non-zero, and the merge was declared a disaster over content that was safely on master — the branch is now checked for patch-equivalence up front, and an empty pick is skipped and reported as applied. **Multi-commit runs were refused outright**, stranding whole pieces of work behind a worktree nobody came back to; they now get a real `--no-ff` merge. Conflicts are still never auto-resolved — the merge aborts, the checkout is left untouched, and the refusal names the intact branch tip so nothing is unfindable. **And nothing is pruned until the content is verified on HEAD**; the verified commit is stamped on the run's ledger row, where "merged" previously carried no sha at all and was an unfalsifiable claim.
- **A merge no longer silently kills the other dev sessions** (Athena dev mode). A dev session runs as a child of the app, so merging — which rebuilds and restarts the dev server — takes every other in-flight session down with it, mid-compile, uncommitted. The merge now refuses while sibling dev sessions are live and names them, and proceeding is an explicit choice rather than something you discover afterwards.
- **A dev session compiling is no longer reported as frozen** (Dev Tools → Fleet). The "no output for 2 minutes means hung" rule is right for a conversational session and wrong for a dev run, whose ordinary working state is a silent `cargo check` that on this codebase runs five to fifteen minutes. Every healthy build was being labelled stuck and "safe to kill". Athena's dev sessions now get roughly a sixteen-minute fuse — past any normal compile, still short enough to catch a real hang.
- **An interrupted dev run's uncommitted work is now saved instead of parked** (Athena dev mode). When an app restart killed a dev session, boot recovery marked the run interrupted and left whatever was in its worktree sitting there — and the merge handshake only ever looks at commits, so finished-but-uncommitted work had no route back. Recovery now commits what it finds under a `[recovered]` message that states plainly it was assembled by the recovery pass and not reviewed by the session, and puts the run back in the normal lifecycle so the ordinary merge handshake picks it up. Review the commit before merging.
- **An unanswered plan from Athena no longer evaporates** (Athena chat). Her actionable proposals — the editable **fleet plan** and the **ship milestone** card — lived only in memory, and the plan JSON is stripped from her reply before it is saved. So the next message you sent, a panel reset, or a dev refresh destroyed the proposal with nothing left to recover: an Aug 2026 session lost six dispatched builds exactly this way. Those two card kinds are now written to the database *before* they reach the chat, and a pending one is brought back whenever you open the panel or switch back to that thread, under a **"Waiting on you from an earlier turn"** label so an older proposal is not mistaken for the current one. Clearing on send still clears the informational cards (the read-once UI snippets), because those are meant to expire with the turn. **Confirm and Cancel are now real decisions** — Cancel records a dismissal so the proposal does not come back, and Confirm **claims** the card before a single terminal opens, which means a double-click, a stale card left over from a refresh, or a replayed event is refused with a plain message instead of quietly starting a second fleet of sessions. A dispatch that fails outright hands the card back so you can correct it and retry.

The backend contract for the 13 nullable persona columns gives a JSON key three meanings — absent = leave alone, `null` = **clear the column**, value = set — but the frontend payload builder emitted an explicit `null` for every field the caller had not mentioned. That was correct until `double_option` was added to support explicit clears, which inverted the meaning of every null already on the wire; `push_field_param!` then bound each one as SQL NULL. The builder now **omits** unmentioned keys, so the three states stay distinct end to end. A pinned test had been failing on `master` since the regression landed and went unseen because `personas-db` unit tests are not in the documented gate — it has been corrected to assert the real contract (absent → skip, null → clear) and now covers the absent case that was never tested.
- **A milestone created active was never cut** (Factory → project → Ship). `cut_at`, the baseline every "added after the cut" flag is measured against, was stamped only when a milestone *transitioned* into `active`. The seeded "Onboard to Personas" milestone every project gets is created directly as `active`, so its baseline stayed NULL forever and the scope-creep signal never fired on the one milestone most projects will ever have. It is now stamped at creation, and a migration backfills rows already on disk. The lifecycle also gained a server-side rule: a direct `planned → shipped` jump is refused, so nothing outside the UI (the management HTTP API, a Fleet dispatch, the A2A gateway) can ship a milestone that was never cut.
- **Ship exit criteria could read GO on a stale scope** (Factory → project → Ship). A milestone's context footprint was resolved by matching context *display names*, and the generated context map emits near-identical names (`teams/factory [1/3]`, `[2/3]`) while every rescan can rename a context. A collision or a rename silently dropped contexts out of the footprint, and since the footprint feeds both the health and KPI-coverage criteria, a milestone could certify as shippable because a critical context had quietly vanished from its own scope. The footprint now joins on context ids, so renames are free and only a genuinely deleted context leaves the cut.

It is the lane's only *design* sensor; every other tool there reports code hygiene. Zero-LLM, zero-dependency, ~5s over a 1200-component tree, and findings land as ordinary `dev_ideas` with the matched snippet and the rule's rationale. Deliberately scoped to the "slop" rules — the `design-system-*` family is dropped at the parser, because on this repo it produced 969 of 1038 findings and duplicates what the `custom/no-raw-*-classes` ESLint rules already track.

Projects scanned before this probe existed render `—` rather than a confident "none". The row does **not** feed the automation score yet — folding a new term in retroactively would step-change every project's score and read as real movement in the readiness trend.

Written because a capable third-party skill produced idiomatic work here and still broke two commit gates it had no way to know about. Every entry was verified against `package.json` / `lefthook.yml` / `eslint.config.js`.
- **Scan skills report the honest shape of a run** — the 22 generated `scan-*` preset skills now (1) survey and collect evidence *before* forming a verdict, and run deterministic checks after, so a tool's output can't anchor the judgment; (2) open with a `Method:` line and must declare `⚠️ DEGRADED` when a pass sampled, skipped a check, or hit a limit — a degraded scan reported as complete silently becomes "we looked at that"; (3) append a snapshot to `.claude/scan-history/scan-<key>.jsonl` and report a trend across runs, comparing like scope with like. They also read `.claude/conventions.json` before proposing changes.
- **The passport wall loads in one call instead of 3N** (Factory → project wall). Drawing the wall used to fan three per-project IPC calls out (contexts, KPIs, milestones) through a concurrency pool, so a 30-project wall cost 90 round trips and 90 queries before a single cover appeared. One batched `dev_tools_project_wall_summary` now answers the whole wall: 1 IPC call and exactly 3 grouped queries regardless of project count. No visual change. The KPI verdict stays a client computation on the raw rows, because it is time-dependent and already has one Rust twin that must not become three.
- **New Ship exit criterion: Scope frozen** (Factory → project → Ship). The per-member "added after the cut" flag was visible on rows but never counted for anything. It is now a fifth exit criterion: `go` when nothing joined the cut after certification, `warn` (naming the offending features in its evidence line) when it did, and `setup` before the cut is stamped, where the signal carries no information yet. It is `warn` and not a hard block because growing a cut is a legitimate decision; but since `warn` folds into the ship verdict, a milestone that kept growing can no longer certify as shipped without the creep being seen first. The four exit criteria also moved into a **registry**: one table of self-describing entries, so a fifth (or sixth) is an append rather than surgery inside the derivation loop.
- **Ship forecasts the next milestone from your own history** (Factory → project → Ship, and the passport cover's roadmap strip). Every lifecycle transition already stamped `cut_at` and `shipped_at`, and nothing read them. The Ship layer now derives the project's **median** cut-to-ship cycle (median, not mean, so one 90-day milestone cannot poison the estimate) and projects the next milestone's landing date from it: counted forward from the real cut, or from today with "if cut today" said out loud when the milestone has not been cut. Below two observed cycles there is **no forecast at all** and the surface says so rather than guessing from one data point. When a forecast lands after a declared target date, both dates are shown side by side. Shipped milestones show no forecast; they have a real date.
- **Choose what a populate run covers** (Factory → project wall → Populate project data) — the action's consent modal now carries a four-lane picker: context map · features · KPIs · simulated KPI data. The default comes from the freshness gates rather than being all-on, so a project whose structure is already current opens with just the KPI lane ticked. Each row says what the lane would do for *that* project ("Context map: 12 groups and current, will be left alone") instead of describing it in the abstract, and excluded lanes are reported as out of scope rather than silently absent.
- **Simulated KPI data for products that have not shipped** (the populate action's fourth lane) — the honest problem with a pre-production project is that you need pillars to know what to measure but have no traffic to measure, and a target invented to fill the field looks like evidence. The lane hands the adopted KPIs to the simulation engine, which walks their journeys with representative characters and researches targets from comparable products with citations. Values stay tagged as the simulation they are (`local`/`test`, never `production`) and are never reported as real measurements.
- **Populate project data** (Factory → project wall → actions row) — a new per-project action that fills in the three things Personas needs to work with a freshly adopted repo at all: a **context map**, a **feature inventory**, and a **KPI set you approve one by one**. Each lane is gated on what already exists — missing, older than 14 days, or fresh — and the consent modal states what *this* run will do before you confirm it, so a project that only needs KPIs does not pay for two re-scans. Contexts and features are assigned autonomously; **KPI proposals are walked with you five at a time** (adopt · adopt with a different target · reject · defer) with each decision recorded the moment you answer it, so an interrupted run keeps what was already decided. A final pass names the exact monitoring binding for every adopted KPI the project has a connector for. Pick where it runs: a **Fleet** session, or a **new terminal window you own** that keeps going after Personas closes (the app cannot watch or stop that one, so the briefing is written into the repo and the session can be re-run by hand). All scanning goes through the app's own engine, so results are identical to scanning from the Factory toolbar.
- **Full context scans now fan out** — a full (non-delta) context scan explores the tree with parallel subagents and reconciles their reports before writing the map, instead of walking it one directory at a time in a single session. Applies to every entry point into that lane — the Factory toolbar, the Context Map page, and the new populate action. Delta re-scans are unchanged and stay cheap.
- **Passport actions explain themselves before they run** (Factory → project wall → actions row) — the consent gate behind Onboard / Standards scan / Copy report / Rescan / Improve plan is now a full modal instead of a 296px popover with one paragraph. Each action declares its **impact class** (read-only · writes when you confirm · runs an agent session), a fact strip (scope, engine, duration, what it writes, which repo it runs in), the **ordered steps** the click actually sets off, and the **boundaries** that hold regardless — credential values never leave the vault, queued Claude tasks wait for review, read-only passes never touch the repo. You can now tell what a click costs before paying for it.
- **Roadmap on the passport cover → one-click Ship** (Factory → project wall) — every project cover in the Overview grid now carries a minimized roadmap: one pip per milestone (shipped / active cut / planned), a `shipped/total` tally, and the **next milestone** named below with its target date. Clicking the strip opens that project directly on its **Ship** tab instead of the default Overview. Projects with no milestones show a "plan the first cut" invitation and still open Ship. The passport wall and the L2 Overview's context cards also got a readability pass — nothing on the wall renders below `text-base`, KPI-card rows sit at `text-sm` or larger, and every icon grew ~50%. The tile's blockers digest moved onto the cover's identity line as a warning glyph + count (full list in the tooltip), the View / Sort / Module control-group labels became glyphs, and an unmeasured context card now reads a single italic *define KPI* instead of three shifting setup asks.
- **Roadmap surface visuals** — the in-app Roadmap (Home → What's New) gains two traced, self-drawing SVG glyphs: a route rail alongside the hero card whose amber/teal/hollow nodes mirror the NOW/NEXT/LATER lanes below it, and an empty-waypoint glyph replacing the bare em-dash in a lane with no items. Motion for every traced glyph in the app now comes from one shared preset library (`motionPresets.ts`) instead of per-component keyframes, with ambient loops reserved for surfaces where work is genuinely in progress and an opacity-only fallback under `prefers-reduced-motion`.
- **Knowledge-base supersede-on-reingest + Rebuild index** — re-ingesting a source file whose content changed now *supersedes* the old document (its chunks and vectors are deleted transactionally before the new version is indexed), so edited files no longer double-index and stale passages stop winning searches; unchanged files still skip. A new **Rebuild index** action on the knowledge base's Settings tab (`kb_reindex`) re-embeds every stored passage with the current embedding model — the recovery path when the app's embedding model changes or an index drifts — with live progress and cancellation.
- **Knowledge-base search relevance floor** — `kb_search` now drops vector candidates beyond the shared relevance floor (`MAX_VECTOR_DISTANCE`) before BM25/RRF ranking, so small corpora return honestly-empty results instead of far-away noise; the Search tab reports how many low-relevance passages were hidden. The ambient all-KB scan behind clipboard intelligence is consolidated into one shared engine implementation (ready-KBs only) used by both the command and the watcher.
- **SLA breach events** — reliability breaches now notify instead of waiting to be noticed. On the execution-completion path (never at dashboard load), a cheap bounded check of each persona's recent runs emits a typed `sla.breach.opened` event into the event bus when a persona crosses into a breach, and one `sla.breach.recovered` when it climbs back out — visible in Overview → Events (red / green) and carrying `persona_id` + reason + streak/rate for healing to consume. **Zero-config**: no targets to author, no settings surface. Fixed conservative defaults — breach at **≥ 5 consecutive failures** or a **windowed success rate below 50% over ≥ 5 decided runs**; recovery uses a hysteresis bar (back above 75% with no active failure streak) so an episode never flaps. Episode state is durable (`sla_breach_episodes`), so a breach announces exactly once and a restart mid-episode never re-emits.
- **Faster Athena replies via per-class model routing** — calibrated by a 1,026-turn decision-ability bench (`docs/plans/athena-model-bench-report.md`): main chat turns now run Opus at low reasoning effort (identical accuracy in the bench, ~16% lower latency), and headless micro calls (auto-titles, triage legs, one-shot classifications) upgraded from Sonnet 4.6 to Sonnet 5 at low effort. One routing table (`companion/model_routing.rs`) owns every tier; `PERSONAS_ATHENA_MODEL`/`PERSONAS_ATHENA_EFFORT` override per spawn for measurement.
- **Concurrent conversation safety (multiconv P1)** — with turns running in parallel across Athena threads, everything turn-scoped is now partitioned per conversation: a background thread's stream can no longer write into the focused thread's bubble, the mid-turn message queue and Stop button act on the thread you're in, a user message no longer cancels another thread's autonomous chain (the explicit Cancel remains a global brake), background tasks know which thread spawned them, and Reset wipes only the current thread's transcript.
- **Athena constitution v44** — bench-derived discipline: every distinct ask in a message gets its own single-line op (two-action messages no longer silently drop the second action), and Athena may not claim something is "already in my notes" unless this turn's recall actually shows it — she proposes the memory write instead.
- **Athena model/effort benchmark harness** — `scripts/test/athena-model-bench.mjs` + a 38-scenario corpus scored by the production dispatcher (`athena-bench-validate`), with per-run checkpointing, resume, and promotion-gate verdicts vs the Opus baseline. `PERSONAS_DUMP_PROMPT=1` snapshots real composed prompts for replay.

Overflow Idle/Stale sessions are auto-hibernated oldest-first (resumable via Wake), and a spawn/wake at the cap hibernates the best idle candidate to make room, so a large tracked fleet costs only what the active sessions cost. Working sessions are never interrupted (soft cap).

Same conversation semantics (pinned session id, transcript, hooks, Insights, hibernate/wake — waking resumes interactively); replies from the banner or Athena are wrapped into stream-json messages. Tiles show a **Background** badge; no terminal is ever mounted for these.
- **Scheduled memory reflection from Chain Studio** — "Memory Reflection" joins Context Scan Update as a system-event target in the Studio: patch a Schedule (or Event Listener) source into it, pick an agent or a whole team, and reflection runs on that cadence as a background job whose output is a proposal in Overview → Memories (never an unattended mutation). Studio polish in the same change: palette option cards are single-row with the description as a hover tooltip, and ledger rows are slightly narrower.
- **Team memory reflection** — a reflection pass over a whole team: lessons held redundantly by two or more members are consolidated into one **team-shared** insight (visible to every member's runs once the proposal is applied; the per-member copies archive with provenance). Available via `reflect_team_memories_with_cli` and as a background job.
- **Reflection → backlog bridge** — reflection now also extracts **product findings** (open bugs, debt, unresolved review threads mentioned in memories) and files them as pending ideas in the Dev Tools backlog, with provenance back to the source memories. The backlog's own accept/reject triage is the approval gate; saturation-capped and deduped against existing ideas.
- **Memory reflection** (Overview → Memories → Reflect) — an LLM pass that consolidates related or contradicting memories into fewer, durable insights. Insights carry **provenance** (`Synthesized from` in the memory detail view; sources are archived, never deleted) and everything lands as a proposal you apply or discard — live memories are never touched without confirmation. Also available as a background job (`enqueue_persona_memory_reflection`).
- **Value-aware memory recall** — the memories injected into a run are now selected by decayed value (importance × category half-life × real usage) packed whole into the prompt budget, instead of "sort by importance and truncate". Constraints barely decay; session context fades in weeks.
