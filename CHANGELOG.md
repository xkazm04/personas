# Changelog

All notable changes to Personas Desktop will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Until a stable **1.0** release, minor versions may contain breaking changes to IPC commands, database schemas, or configuration files. Breaking changes are marked with **BREAKING** and always call out the migration path.

## [Unreleased]

### Added
- **The agent Design hub gains the living-agent surfaces (Core · Responsibilities · Brain).** Three new Design sub-tabs — shipped briefly as a top-level Life tab, folded into Design in the post-ship checklist; a remembered Life tab reopens as Design › Core. The living-agent surface for one persona: author its Core character (three dials, conflict style, motivation/stance/north-star prose, principles and constraints — saved as one explicit change, never autosaved); create and retire standing responsibilities (outcomes with success criteria, objectives, scope rung 0..2, refusal classes from the domain library plus `custom:` lines, attention cadence and budget) with the attention ledger's verdicts beneath; and review the Brain — the episodic record with a load-older cursor, the read-only self-model that changes only through approved proposals, the proposal inbox (memory curation and self-model diffs share one apply/discard gate), and a manual "Consolidate now" trigger. Attention passes also appear in the Activity tab as their own item type.
- **The attention loop is visible, and it has a switch.** Overview → Mission Control gains an Attention Loop card: the global on/off toggle for the living-agent attention loop (the `autonomous_attention_loop` setting existed with no UI at all — the loop could only be enabled by editing the database), the newest ledger pass (kind, lane, verdict, when), and today's dispatched / refused / consolidation counts. A failed status read says "unavailable" rather than posing as an idle loop, and an empty ledger says "no passes recorded yet" rather than showing zeros it never measured.
- **The management API can now read and write the Ship layer.** `GET /api/dev/projects`, `GET /api/dev/projects/{id}/ship` and `GET /api/dev/milestones/{id}` serve a project's roadmap, members (names resolved) and its use-case / goal registries; `POST` routes create a milestone from a brief (with optional existing members and new goals in one call), register a use case, decompose more goals onto a milestone, move members between buckets, and patch a brief or a goal's progress. Writes require the `personas:build` scope and go through the same validators Athena's chat cards use, so nothing a terminal creates is looser than what a card would accept; lifecycle transitions, deletion, KPI members and rating writes are deliberately absent. Until now both `/ship-milestone`'s Phase 1 and the goal-assist brief told a CLI session to use routes that did not exist. The pairing modal's Approve / Dismiss buttons carry test ids so a test-automation build can pair a CLI session from the bridge.
- **A fleet session on the Activity board can be read without opening its terminal.** Each live-session tile gains a small icon beside its label that opens a **recap** — and the point of it is what it does *not* do: it attaches no PTY and mounts no xterm, so an operator watching twenty fleets can ask "what is this one doing" twenty times without taking twenty live subscriptions. Most of what it shows is Claude Code's own writing rather than anything this app generates: the CLI records an `away_summary` ("Goal was … Next: …") into its transcript, present in 43 of the 60 newest transcripts on this machine, and the panel prefers it over everything else; where there is none it falls back to the trailing assistant turn and says which of the two it is showing. Under that sits the provenance an operator needs to trust it — the live terminal title the session is emitting right now, its model-generated title, your last prompt, how long it has been alive and since it last moved, why the registry put it in the state it is in, and the one genuinely live signal: whether a tool call is still open and how long it has been open (an open shell at three seconds is working; the same call at twenty minutes is the wedge case). A session with no transcript yet — just spawned, headless, never bound — says so plainly instead of showing a blank panel, and the recap never errors on one. The read is bounded to the end of the transcript, so it costs the same on a session six hours old as on one six minutes old.

### Changed
- **A failed run's class is now stated where the failure is raised, not recovered from its sentence.** `persona_executions` gains a nullable `error_category`, written only by the three sites that know the class from a structural fact: the engine's own safety ceiling (its own timer fired), the runner's non-zero exit with no diagnostic stderr, and the provider usage-limit parse. The case that motivated it is measured in this tree: the engine minted "Engine safety ceiling exceeded (20m)" knowing exactly what it was, the only channel it had to say so was prose, and **40 of 43 `Unknown` healing issues (93%)** were that one string — landing on a recovery that creates an issue and never retries, while the `Timeout` recovery it should have reached **succeeded 72.7% of the time, the best rate of any class**. Healing now prefers the row's own class and falls back to the string ladder only when nothing knew it, and the Overview's error breakdown counts classed rows in SQL instead of pulling every failed message back to re-run the ladder. **Two things deliberately did not change:** `classify_error` stays exactly as it is for the retained history and for failures whose origin genuinely is a foreign string, and nothing backfills — a row written before the column existed keeps `NULL` rather than being given a guessed class. What an operator will notice: runs that used to appear as `Unknown` in the error histogram now appear as `Timeout`.
- **The Activity board only draws the tiles you can see.** The Monitor's rail has been virtualized for a while; the board beside it was not, so every persona card and every live session in the fleet was a live DOM node whether or not it was on screen — on a surface being built toward 100+ concurrent automations. Measured on the load harness at 100 synthetic sessions, all 100 were in the DOM; the board now holds **41 nodes at 50, 100, 200 and 400 sessions alike**, and under that same 100-session load the main thread's blocked share fell from **10.18% to 6.36%**, the 95th-percentile frame from **133.5ms to 100ms**, and the average frame from **96ms to 44ms** — roughly twice the frame rate. The board is two axes (columns scroll sideways, tiles stack inside a column), and the vertical one is what actually grows, so each column now scrolls on its own with its header pinned above it — the standard board geometry, and it fixes an old annoyance where scrolling to the bottom of a deep column dragged every short column off screen with it. The teamless tray below wraps and windows the same way. Short columns render exactly as before: windowing only engages past 30 rows.
- **A session's token totals were roughly 2.2× too high.** Claude Code writes one transcript record per *content block* of an assistant turn — a turn that thinks and then calls a tool is two records — and every one of them repeats the same message id and the identical usage figures. The rollup that feeds the fleet's token totals, the efficiency bar and the per-session context pill was summing them per record, so a turn was counted once for every block it happened to contain. Checked against the one ground truth a transcript carries (its own final cost record), the old sum ran at a median **2.22×** the real figure across 45 transcripts and the corrected one lands at **1.00×** (34 of 45 within 2%). Tool counts, files touched and background-shell counts are unchanged — those blocks are genuinely distinct and are still counted from every record — and the context-size figure was never affected.
- **The Persona Monitor stops working for surfaces nobody is looking at.** Three loops kept running regardless of what was on screen. (1) The Monitor's four header destinations are peers, but the pending-review, unread-message and persona-health polls ran on all of them — even though everything built from those feeds (the fleet grid, its drawer, the system band) is drawn only by **Activity**. On Timeline, Conversations and Map that was `list_manual_reviews`, `list_reports(300)` and `get_persona_summaries` re-read twice a minute for a model with no pixels behind it. The comment defending this pointed at a footer review count that no longer exists — it was replaced by the dispatch dock, and the justification outlived the pixels. (2) The Activity rail projected all three of its tabs — Reviews, Dispatch and Messages — into rows and lookup indexes on every poll, including the two tabs not on screen; the Messages tab re-mapped up to 600 merged channel items and rebuilt a 600-entry index each time, and resolved each row's author with a linear scan of the whole persona roster. (3) The elapsed-time clock ticked once a second behind a hidden window, re-rendering the whole Monitor to paint a timer nobody could see. **The three tab badges are unchanged and still truthful:** every feed stays subscribed, and each badge is now read from its own source (the triage queue, the accepted-idea rows, the channel slice's unread watermark) rather than from the row projection — so skipping the projection cannot make a badge go quiet. Switching tabs or views re-derives from live data in the same render, and returning to Activity refreshes immediately rather than waiting out a poll, painting the last-known fleet in the meantime instead of a fresh ghost.
- **52 more backlog ideas landed under the measured Before/After rule** (each idea now carries a Claim/Before/After/Method/Result evaluation; 36 ideas that measured not-better were rejected with their figures, 61 stay for a human because their benefit has no figure or needs a contract/policy decision). What changed for you: the vault database console's safe-mode classifier stops disagreeing with the backend on comment-bearing SQL, its saved-query delete asks first, its schema filter footer says "3 of 50 tables", the chat input stays typeable while an answer generates, Redis key-type failures read as failures with a retry, and every error block there is the shared banner; the fleet terminal tells a displaced pane it was taken over and offers to reclaim it, survives a failed output listener with a notice and a retry, keeps scrollback across re-attaches, asks before minting a second pairing token, stops re-scanning processes on every alt-tab, shows its renderer budgets in Settings, and refreshes the roster after a fully failed broadcast; the trace waterfall is virtualized to a bounded window, a running execution's live spans now paint instead of being dropped, Spans and Errors tiles count one population, the tracer's own force-close markers no longer count as errors, unpriced chain steps say so instead of summing to zero, and $0 reads as $0 everywhere; Studio's Bun preflight treats an unknown probe as unknown, Stop reports when it found nothing to stop, and a stray digit can no longer answer Athena while a popover is open; compare cards format numbers per locale, trigger pickers speak the user's language, and the platform importer's three GitHub Actions detections agree.
- **100 more backlog ideas landed across 18 feature areas** (the ideas the net-delta rule auto-accepted plus the operator's own accepts, executed by coordinator subagents; 14 were demoted back to the deck with the executor's reason). Highlights: the vault database console can cancel a running query, its safe-mode classifier now catches `EXPLAIN ANALYZE` and the full DROP/ALTER verb list, and its saved-query sidebar has accessible names; the Studio surface is fully localized (88 strings) and its popovers close on Escape; the guided tours are translated (432 strings ×14 locales); fleet terminals bound their live WebGL and attached-terminal budgets, frame clipboard pastes, refcount attach/detach so two panes can share a session, stop blinking over a dead process, and broadcast with progress and cancel; the trace inspector no longer renders unpriced spans as $0 or a missing outcome as a green tick, and the log viewer/memory graph/vault tables got real ghosts and keyboard reach; provider API-key fields no longer inherit the browser's password autocomplete; competitions reap their spawned dev servers; the persona-core codex is keyboard-anchored, its petals go visibly inert during a build, and 330 eager SVG paths mount lazily; trigger pickers, cron presets, execution-status labels, span-type badges and the memory timeline now read in the user's language.

Highlights the operator will notice: busy states on vault/database/fleet/install controls now show a real spinner instead of a vanishing icon; the database safe-mode classifier no longer fails open on Convex mutations; a failed saved-query save no longer shows a green "Saved" badge; the memory graph and vault tables are keyboard-reachable; fleet broadcast reports *which* sessions missed a command and companion-device revoke failures are surfaced; competition Cancel/Delete ask for confirmation and cards stop polling once a race ends; dozens of hardcoded English labels (competition milestones, KB status tokens, model prices — which were also off by 1000× in their unit — cron prose, memory surfaces) now go through the 14 locales; dates respect the app language rather than the OS locale; Studio's dev-server boot no longer says "Starting…" forever. - **Quick Answer's queue rail is roughly twice as wide, and its topics are readable.** The rail listing what is coming up in the triage deck was pinned at 18rem and spent most of that on chrome, so almost every topic truncated after a few words. Three changes bought the width back. The rail is now **fluid** — `clamp(18rem, 100vw − 56rem, 36rem)` — so it takes every pixel the card does not need and keeps growing with the window instead of waiting for a breakpoint (519px on a 1359px window, up from 270px). The quick-action dock is now a strip of 36px keys with 21px glyphs (was 17px in 28px pills), grouped by job — find │ schedules · review · dispatch │ monitor · notifications │ console — with hairline dividers and a primary underline on the open surface. Every dock key and the Back button use the app's own `Tooltip` instead of the native `title=` bubble. In the notification tray, titles render in the theme's primary colour and wrap instead of truncating, the "ago" stamp sits in each row's bottom-right corner so it no longer steals width, and read notifications older than 7 days drop out of the list (unread ones stay until acted on).

- **Accepted work can be sent to a runner without leaving the triage deck.** Quick Answer's queue rail now has two tabs. **To decide** is the ledger it always was. **Accepted** is new, and it closes a loop the deck used to drop: accepting an idea recorded a decision and then nothing happened until somebody navigated to Plugins → Dev Tools → Run Desk and pressed "Batch from accepted" — so the app already had a name for the resulting pile ("an idea a human said YES to that never became work") and no surface that let the person who said yes act on it. The tab lists exactly that pile — accepted ideas with no task behind them — with the project each belongs to and how long it has been sitting there, tick boxes to choose, and the Run Desk's own three dispatch techniques in the rail header: **Single** (strictly one at a time), **Batch** (the runner's default of two) and **Parallel** with a stepper bound to the *same* concurrency setting the Run Desk writes, so the two surfaces cannot come to disagree about what "parallel" means. Dispatched rows leave the list as they go out, and a send that partially failed reports what was skipped beside what went, never folded into one number. Auto-Run stays on the Run Desk — it is a durable scheduler with a banner that reports it, not a dispatch of what you just selected.
- **Accepted work can be deleted from the triage deck.** Quick Answer's rail → Accepted tab has a trash icon beside the "n selected" count. The tab drains the pile of ideas you said yes to that never became work, and until now it only drained in the direction of yes: a reviewer who changed their mind had no exit, so those ideas stayed accepted with no task forever. Deleting asks first, says plainly that it removes the ideas permanently along with the record that you accepted them, and reports how many were already gone whenever it deleted fewer rows than it asked for. Nothing is cancelled by it, because by construction nothing in that list has been sent to a runner.
- **The triage queue rail groups by project, and its rows are half as tall.** Both of Quick Answer's rail tabs listed one row per item with the project repeated on every single one — an inline chip beside the topic on **To decide**, a project-and-age line under the title on **Accepted** — plus a position number pinned to each decide row's corner. The project is now a group header stated once per run, so all of a project's work reads together and the topic gets the rail's full width; groups appear in the order the queue deals them, never alphabetically, so the next card stays at the top. The ordinal is gone (the current row's border and tint already say where you are) and rows are a single 30px line on both tabs instead of a clamped two-line box at 55 and 76px, so roughly twice as much of the queue fits on screen. The "how long it has been sitting there" stamp on accepted rows was dropped with it.

In a production bundle the entry, the route and the idle-prefetch of its chunk all fold away.

### Security
- **The `http_get` tool can no longer be steered at your own machine, and an imported persona can no longer walk off with your API key.** Two fixes in the remote (Qwen/DashScope) HTTP engine. First, the built-in `http_get` tool — whose URL the *model* supplies, and whose response body is fed back into the conversation and therefore uploaded to the provider on the next turn — was executing on the same HTTP client built for the chat endpoint: system DNS resolver, ten automatic redirects, and a private-address check applied to the first hop only. A page could answer `302 Location: http://169.254.169.254/…` (cloud metadata) or `http://127.0.0.1:9420/…` (this app's own credential proxy) and the body came back. Tool execution now runs on its own SSRF-safe client that re-validates **every** redirect hop and rejects private addresses at connect time, with a pre-flight check covering the cases DNS never sees (raw IP literals, cloud-metadata hostnames, non-http schemes). Second, a persona's `model_profile.base_url` replaces the inference endpoint wholesale — scheme and authority — and it is copied verbatim out of imported bundles and adopted templates, where the only check on it had been a 500-character length cap; an attacker-authored bundle could therefore point your executions at their server and receive the entire assembled prompt, and if it omitted a token, your real API key from the OS keyring along with it. The stored provider key is now **endpoint-scoped**: it is attached only to the provider's own host or to a private/loopback host (a local Ollama / LM Studio / vLLM — the headline BYOM case, which keeps working unchanged), and any other endpoint must carry its own explicit auth token; an execution against an endpoint that qualifies for neither now fails with a message naming the endpoint, instead of quietly shipping the credential. The four untrusted write doors (bundle import, template adoption, team synthesis, bundle validation) now strip any `auth_token` smuggled inside `model_profile` and reject a `base_url` that is not a usable http(s) URL — matching the rule import already applied to every other credential, which was "metadata only; the user re-enters the secret".
- **The in-app HTTP server on `127.0.0.1:17400+` now authenticates every request.** It had mounted 36 routes across five routers with no middleware layer, no token and no `Host` check — including `/dev-tools` (34 routes, mounted unconditionally in release), which could register a project at any path on disk and then start a context scan there, and a context scan sets the working directory of a `claude` child spawned with `--dangerously-skip-permissions`; whoever picks that directory picks the `CLAUDE.md` and the `.claude/settings.json` hooks that child reads and obeys. Two independent gates now sit over the whole router, applied once so a router added tomorrow is covered without its author doing anything: a **`Host` allowlist** (`127.0.0.1` / `localhost` / `::1`), which is what defeats DNS rebinding — a page that rebinds its own hostname to loopback becomes same-origin with this server and can read responses, but the browser still sends the attacker's name in `Host` — and a **shared secret**, which is what stops another principal on the same machine, since `127.0.0.1` is machine-scoped rather than user-scoped. Ordinary drive-by CSRF from a non-rebound page was already blocked by the `application/json` requirement and is not what changed. The app's own consumers keep working without a re-pair: terminal skills read `{port, token}` from `~/.personas/local-http.json`, Fleet hooks get the header baked into their `curl` line and an install predating this change repairs itself at next launch, and per-session `mcp.json` carries it alongside the Athena session token. The Browser Bridge extension is exempt from the token — it already gates on its own pairing token — but not from the `Host` check.
- **A CLI caller can no longer write instructions into a permission-disabled agent's prompt.** `POST /project-tracking/cli-event` interpolated its `title` and `summary` verbatim, with no delimiting, escaping or length cap, into the project-pulse prompt — which is piped to a CLI run with `--dangerously-skip-permissions` and no tool restrictions. Caller text is now announced as untrusted, flattened to a single delimited line (so nothing it contains can open a heading, a fence or a JSON envelope at the start of a line), capped per field and bounded in count. That turn also stopped running in the user's home directory, where a `CLAUDE.md` and `.claude/settings.json` hooks would be picked up, and runs in an empty scratch directory instead.
- **Scan and export roots are confined to the project's registered root.** `POST /dev-tools/scan-codebase` and `POST /dev-tools/export-context-map` accepted any `root_path` that existed; the first chose an agent's working directory, the second rewrote `context-map.json` and a `CLAUDE.md` block there. Both now refuse a path outside the project's own tree (a prefix-name sibling and a `..` traversal included), and registering a project over HTTP requires a directory that actually exists.

### Fixed
- **One malformed execution row no longer blanks every execution surface at startup** (`Database error: Invalid column type Text at index: 15, name: cache_read_tokens`). SQLite's INTEGER affinity converts a bound string only when the conversion is lossless, so a hand-written `INSERT` could leave `'mock'` — or a timestamp — sitting in a column declared `INTEGER NOT NULL DEFAULT 0`; rusqlite is strict on the way back out, and because one mapper is behind every full-row read of `persona_executions`, a single such row failed the whole list rather than itself. Two fixes: a boot migration repairs the stored rows (a text value that round-trips as a canonical number is kept as that number; anything else collapses to the column's own default — never a blind `CAST`, which would have read a timestamp as 2,026 tokens and a corrupt boolean as `true`), and the reader now coerces the numeric and boolean columns instead of refusing them, so the next stray write degrades one field rather than the page. Text in an id or status column is still loud, as it should be.
- **Personas without a valid icon no longer render broken-image frames.** Every image branch of the persona icon (built-in art, custom upload, remote URL) now falls back to the persona's initials (or the generic bot glyph) when the source fails to load.
- **The database schema browser stops showing a bare "Loading…" sentence where a shape belongs.** Three surfaces — the table/key sidebar, the column table, and the Redis key detail — paired `feedback/LoadingSpinner` with a line of loading copy. That component renders `null`, so what actually painted was one centred sentence floating in an empty panel, followed by a full relayout when the data landed. All three now render the app's standard cold-load ghost: geometry matched to the real rows, faded in behind a staggered ≥120ms delay so a fast introspection never paints one at all, and — in the column table — sitting *under* the header row, which is static chrome and no longer disappears while the fetch is in flight. A refetch that already has rows on screen keeps them. The loading copy is still announced to screen readers.

### Added
- **A watched feed can now fix your repos by itself** (Events → Marketplace, Chain Studio → System events). The Watchtower table grew a **Routing** column: pin a feed to any of your registered dev projects from a small checkbox popover, and bind the new **`feed_impact_dispatch`** system op to that feed's `shared:<slug>` event. When the feed fires — an upstream connector API change ships — the op opens one Claude Code Fleet session per routed project (capped at 8 per wave, deduped against sessions already working the same feed×project) that greps the repo for real usage, implements the adaptation when warranted, runs the repo's *own* gates, and commits to its main branch only when they're green. Each session reports through a gated ingest door (`feed-impact/runs/<id>/result.json` → validated into `shared_event_impact_runs` — the session never touches the database), a background watcher lands finished waves with no window open and raises one "*feed*: impact wave complete" notification, and the feed's event-history modal shows every firing's verdicts as chips: committed (with the sha), assessed, gates red, failed, or no impact. As a dispatch-class op it honors approval mode — held fires stay a human's call.
- **A milestone's brief becomes goals in one click — "Decompose brief" on the Ship tab.** The description you write under a milestone is a real brief: it names the deliverables, the research to run, the paths to write to, and what is out of scope. Until now nothing could act on it — turning it into trackable work meant hand-authoring each goal and binding it, one at a time. The new button asks Athena to read the milestone and propose its deliverables as goals, and she answers with an **editable card**: rewrite any title, edit any description, drop the rows that do not belong, and nothing is written until you press Create. - **Two devices, one Athena to the other** (Settings → Devices). Personas installs on the same network could already see each other, and nothing more: the peer-to-peer layer had discovery, connections and health checks, but no way to establish trust and nothing to say over the link. Two machines can now **pair** — you pick the other device, both screens show the same six-digit code, and you confirm on the receiving one — after which **your Athena can hand the other device's Athena a plain-language instruction**, which it runs as a real turn with its own tools and its own approval rules, streaming back progress notes and a closing summary that arrive on your machine as memory it can report from. The new **Devices** tab lists paired machines, marks one as **home**, and keeps a full job history in both directions with each job's notes. Consent is deliberately mode-conditional: with autonomous mode **off**, instructions go only to the home device and each one waits for a click; with it **on**, they fire directly to any paired device, which is the same standing consent that switch already grants everywhere else. Pairing is the trust boundary and it is a real one — the handshake is a three-leg ed25519 signature exchange (two legs would leave the initiator's proof replayable, since nothing in the opening message is chosen by the responder), each leg checks that a peer's claimed identity actually hashes from the key it presents *before* verifying the signature, every leg and the six-digit code are bound to the encrypted channel they travel over (so a relay that terminates the connection to each side cannot forward the signatures on — see the security entry below), and job messages are accepted **only** from paired devices. That last check is separate on purpose: any device on your network may complete the handshake and read your public manifest, so **an authenticated connection is not a trusted one**, and the job path is where trust is enforced. Adding a device never strands one — when both machines already have devices of their own, pairing is refused and names the devices that would be orphaned, rather than silently splitting a group; when only one side does, the other joins it. Counts that arrive over the network are treated as claims, so a peer lying about being empty can only cause a refusal, never make you abandon your own devices. A dropped link costs nothing: work already running keeps running, and on reconnect each side replays exactly the notes the other missed, tracked by the highest unbroken run rather than the highest number seen, so a note arriving out of order cannot orphan the one before it. A job whose runner crashed is failed at startup and the result finds its way back. Athena also learns which machines exist and which are reachable, so she can pick one herself and will not offer to send work to a device that is offline. Requires a full build (`desktop-full`) on both machines, and the link has not yet been exercised across two live machines.

Progress was derived as *ready features / total features*, so a milestone whose cut was five goals and zero features read 0% forever — which is exactly the shape a milestone takes right after its brief has been decomposed into goals. The last vendor retirement (`*-20250514`) left dead ids in the failover ladder precisely because there were 54 files to patch and no single one to patch first; the next retirement is a one-line change. - **Autonomous mode approves everything now** (Athena chat). Turning autonomous mode on is a statement that Athena may act without asking, and yet two thirds of what she proposed still arrived as an approval card waiting for a click, because a fixed list of action names decided what was allowed to fire on its own. The list is gone. With autonomous mode **on**, every action she proposes fires immediately and no card is rendered; with it **off**, nothing changes and every proposal is a card exactly as before — the toggle is now the whole decision, and switching it off is how you get the clicks back. What still holds is what actually bounds the work rather than merely delaying it: she can only propose the actions her grammar defines, every session she starts stays inside a registered project folder, the boldness dial still governs typing into a terminal you may be using, self-development still requires dev mode and a debug build, and instructions to another device still refuse anything but your home machine when autonomous mode is off. The chips, the project stamp and the score meters now all straddle the card's **borders** — meters and stamp on the top edge, kind and tags on the bottom — the ledger is gone (its facts were the ones no verdict ever turned on), and the headline sits alone on its row at the card's full width, one size down and no longer line-balanced so it actually uses that width. - **Athena's memory now consolidates when you've actually talked to her, not when a clock says so** (Athena → Memory). Her nightly maintenance pass ran on a 20-hour timer, and only inside an approved night-shift plan window — so a day of heavy work waited out the timer while a silent week burned a full pass on nothing, and anyone who never approved a plan got no consolidation at all, ever, while the feature looked shipped. It now runs on **sleep pressure**: 40,000 characters of new conversation since the last pass. On measured history that means a heavy day consolidates the same day and a few light ones accumulate into one. The clock survives only as guard rails — a 6-hour floor so one busy afternoon can't cycle twice, and a 72-hour release so a quiet week still gets compressed — and below 2,000 new characters nothing runs, because distilling a handful of turns produces a report saying it found nothing. - **Athena's chat window: one progress surface, more room, and it stops hiding behind the app header** (Athena chat). A long conversation had become the slowest thing in the app and the busiest thing to look at, and both had the same cause — the panel was doing too much at once. Four fixes, all visible. **A turn now reports itself once.** While she worked, the same fact arrived four ways: a status line naming the live tool ("Reading files…"), a running log of every tool call with durations, an activity-tray task per slow tool, and the plan checklist. - **Small label text is readable text now** (everywhere). The `typo-label` token — the app's smallest strong tier, carrying badges, chips, column headers, section dividers and a great many one-line hints — was 700-weight, letter-spaced a full 0.15em, and forced to UPPERCASE with a line-height of exactly 1. That is display styling applied to text people are expected to read: acronyms and proper nouns disappeared into the surrounding shout, wide tracking cost real horizontal room in an already dense interface, and a line-height of 1 meant anything that wrapped overlapped its own descenders. - **"Stale" now says which kind of stopped it means** (Dev Tools → Fleet). ### Fixed
- **A run that hit its turn limit no longer shows as completed.** The CLI ends every turn with a verdict line that says whether the turn succeeded and, if not, why (turn limit reached, error during execution). The app read that line for cost and tokens only and decided success from the process exit code, so a persona that ran out of turns on an otherwise clean exit was recorded as completed with no output to show for it, and a run whose stream was cut off before the verdict looked exactly like a finished one. The verdict now comes first: an error verdict marks the run failed with the reason named, and a stream that ends without any verdict is marked incomplete rather than completed.
- **SECURITY: device pairing could be completed by a machine-in-the-middle, and the six-digit code would not have shown it** (Settings → Devices; found in review — pairing ships for the first time in this same release, with the fix already in it, so no released build was ever exposed). The peer handshake was a real mutual proof — three legs, fresh nonces from both sides, ed25519 signatures bound to each peer’s identity — and every one of those signatures was genuine. What none of them contained was anything drawn from the *encrypted channel carrying them*. The QUIC certificates are generated fresh on every bind and unrelated to a device’s identity, so nothing ever verified them, and there is no second layer of encryption underneath. An attacker already positioned on your network could therefore terminate TLS to each machine and forward all three signed messages byte for byte, forging nothing and holding neither private key: both devices verified the other’s real signature and concluded they were talking to each other, through him. Worse, the pairing fingerprint was derived only from the two public peer ids and a nonce he was relaying — so **both screens showed the same code**, and the human comparison that is the entire trust boundary of pairing confirmed the attack rather than catching it. Every signed transcript, and the fingerprint, now mix in a **TLS keying-material exporter** (RFC 5705) taken from the live QUIC session. Two sessions export two different values, so a relayed proof no longer verifies and a relayed ceremony shows two different codes. **BREAKING (wire): the peer protocol goes 2 → 3**, because what goes into a signed transcript changed and cannot be negotiated — an attacker would simply ask for the old version, which is the downgrade this exists to prevent. Both machines must run this version or later; the version check already rejects mismatches by name rather than failing mysteriously. **Devices you have already paired stay paired** — pairing records a peer id, group and public key, none of which this touches — and pairing v2 was never exercised across two live machines, so there is nothing in the field to migrate.
- **SECURITY: the Obsidian connector could be steered outside your vault** (Agent → Connectors → Obsidian). When the bridge talks to a vault through the filesystem — the path it takes whenever the Local REST API plugin is not configured — four actions checked the note path against the vault before touching it, and the check did not work. It compared the joined path to the vault textually, and a textual comparison never resolves `..`, so a path climbing out of the vault matched the vault and was waved through; the operating system then resolved the climb and opened whatever was on the other end. Reading a note could read any file the app can read, writing one could write any file **and create the folders on the way there**, appending could create a file anywhere, and listing could enumerate any directory. This matters because a note path can come from an agent's own output, so a prompt injected into a page an agent reads could name one. Every path is now resolved against the vault and proven to land inside it before anything is opened, symlinks included — a link pointing out of the vault is refused rather than followed. Legitimate vault-relative work is unchanged, including creating a note in a folder that does not exist yet. The REST-API path gets the same check, because the same climb escaped the plugin's own vault namespace into its other endpoints.

- **Bundling MCP connections under a gateway never worked, on any install** (Connections → an MCP gateway → Members). Adding a member to a gateway failed every time with a database error about a missing table, and the members list failed the same way, so the panel could not even show what a gateway already contained. The cause was a name: the membership table was wired to a credentials table that does not exist under that name, in three separate places — the link between a gateway and its members, the query that lists them, and, unrelatedly, the credential-rotation section of the anomaly drill-down in Observability, which errored the whole drill-down when opened. All three now point at the real table, and existing installs are repaired on next launch without touching any data. Deleting a credential now also correctly removes it from any gateway it belonged to. The safety gate for a trigger that fires on its own — run normally, run as a simulation, or hold for a person to approve — was fully built in the backend and unreachable from one end: the queue of held fires had exactly one screen that could show it, and that screen had no route into the app at all. All 165 triggers on this machine were on "run normally" and the held queue was empty, which is what "unreachable" looks like from the outside. The approvals queue now appears where the mode is set (scoped to that agent) and on the Event Bus page (workspace-wide, above every tab), each waiting fire naming the agent, the trigger, the event that arrived and how long it has been waiting — a held fire whose age you cannot see is a decision you cannot prioritise. A count in the Event Bus header says fires are waiting without you having to know the panel exists, and collapses to nothing when none are. The dead screen behind all this has been deleted.

- **An event can no longer disappear between being claimed and being finished** (Event Bus). The bus claims a batch of events by flipping them to `processing` in one atomic statement, which is what stops two overlapping ticks dispatching the same event twice. Nothing, however, ever returned a claimed event that its tick failed to finish — and cleanup deliberately exempts `processing` rows as in-flight, so a tick that died between claiming an event and recording its outcome left that event invisible forever: never delivered, never retried, never pruned, counted in neither the pending nor the dead-letter totals. A reaper now watches the claimed set and returns anything still holding a claim five minutes later, marking it so the Live Stream says the redelivery happened; an event that has burnt its retries is parked in the dead-letter queue rather than cycling forever. It is deliberately timid — a row must be seen holding its claim on two consecutive passes before it is touched, and the owning tick always wins the race — because re-dispatching work someone is still doing would be worse than the problem. **This is insurance, not a repair: there are no stranded events on this machine today.** The count is reported on the scheduler's own stats and logged as a warning when it is anything but zero, since a non-zero value means ticks are dying mid-flight.

- **An event that didn't start a run now says why** (Event Bus → Live Stream / Dead Letter). When an event reached the bus and no execution followed, the reason column was written as `NULL` — literally hard-coded — and each of the gates that drops a match did so silently. On this machine 22 events were sitting in `skipped` with nothing recorded: 22 moments where a trigger did not fire and the product could not say what stopped it. Every gate now records a machine token on the event — no subscriber matched, the agent is switched off, the fire is held for approval, a wildcard match crossed a team boundary, the capability was already running, the run went out as a dry-run simulation — resolved to a label in the interface like every other status token, never emitted as English from the backend. Rows written before this existed read as **unknown**; a reason is never invented for them. Two ways an event could disappear entirely came out with it: a webhook fire held for approval was left mid-flight with no terminal status at all — never delivered, never retried, exempt from cleanup — and a handoff dropped because its target agent was disabled tried to dead-letter itself through a transition the event lifecycle does not allow, so the write always failed, was swallowed, and the row stranded while the interface was told it had been dead-lettered.

- **The Templates header stops saying "50 templates"** (Templates). The count beside the page title was the length of whatever the page happened to have loaded, and that fetch takes the backend's default of 50 rows — so with 124 seeded templates on disk plus team presets, the number was simply wrong, capped, and gave no hint it had been capped. It now comes from a dedicated count query: one aggregate against the database rather than pulling the whole catalog into the window to measure it. While that query is in flight the header shows a placeholder instead of a confident zero, and the Templates tab's own paginated total is untouched.
- **The template integrity docs now describe the check that actually runs** (developer-facing). `check_template_integrity` sat at the top of the instant-adopt path and was documented as "the authoritative security gate". It could not fire: the checksum manifest is keyed by a template's file path and hashes the whole file, while every real caller passed a bare label plus the payload-only design JSON — so the template was "unknown" for 100% of adoptions and the tamper-reject branch was unreachable, with the release build only writing a warning. Fixing the key alone would not have helped, because the hashed content is a different document from the one the manifest was built over. The inert check has been **removed** rather than left as decoration, and `docs/features/templates/06-integrity-and-security.md` now says plainly what enforces integrity: the **catalog-load checksum check**, which drops a tampered template before it is ever seeded — so it can never reach any adoption path — while the compiled-in Rust manifest is a **detector** whose caller only logs. The threat-model section no longer claims an attacker would also have to patch the native binary; today, patching the bundle is sufficient, and the doc says so along with what it would take to close that. No behaviour change for legitimate adoptions.
- **A template that says "Ready" in the gallery is now actually ready to run** (Templates → Gallery). The readiness badge on a template card was computed by a different, weaker rule than the one that decides whether the persona can execute. The badge asked "is the connector installed *and* is there a credential with its name?"; the real gate asks the connector-readiness resolver, which understands that a zero-config connector needs no credential at all, that an aggregate connector is ready with nothing configured, that a native capability has no definition row, and that a stored credential which cannot be bound to exactly one connector is not a working one. The two disagreed **by construction**, in both directions: templates that would have worked were hidden behind "Setup needed", and templates the run gate blocks were advertised as Ready — you adopted one and only then found out. The gallery, the card preview and the side-by-side compare view now all read the same verdict the execution gate reads, resolved in one batched call for the whole page rather than one per card. A connector the resolver has not answered for yet shows as *checking*, never as a confident tick or a red cross, and a not-ready one now names **what** it needs — a Vault credential, a CLI sign-in, a Dev Tools project, an Obsidian vault, a Twin profile — instead of the old catch-all "needs credential".
- **Athena's nudges reach you instead of piling up unseen** (Athena chat / orb). She had written down 66 things worth mentioning and not one of them had ever been engaged. The reason: the moment a nudge was recorded was also the moment it had to win a delivery slot, and a nudge that lost landed in a state nothing on earth could release — no code path re-delivered it, the expiry sweep ignored it, and the duplicate guard treated it as proof she had already spoken. Twenty were sitting like that, the oldest for seven weeks: nine stalled project goals and three quiet fleet sessions she had spotted, recorded, and would never have mentioned. **Noticing and telling you are now two separate steps.** Writing a nudge down is free; one sweep on every five-minute tick decides which of the waiting ones to deliver, under exactly the same daily limits as before — the limits were never the problem (the ceiling of 12 a day has never once been reached), the delivery was. Nothing can strand any more: a nudge that misses a slot simply waits for the next tick, and one that has waited a day is retired rather than delivered stale, which frees the trigger to say it again with current facts — or stay quiet, if the situation resolved itself in the meantime. The same sweep finally runs Athena's own "I'll check back in ten minutes" commitments, which in normal operation had no caller at all; one had been sitting due and undelivered for two days. And a crash between recording a nudge and sending it now costs nothing.
- **Talking to Athena with the chat closed now actually starts a turn** (Athena orb / footer avatar). Hold-to-talk, the orb's quick-input bar and "Ask Athena" from a dashboard all hand their message to the same internal slot — and nothing was listening to it unless the chat window happened to be open, so the message sat there and no turn ever ran. The whole side channel had the same problem: replies streaming in, navigation she performs, cards she raises and approvals she creates were all handled only by the open window. That listening half now lives with the always-present part of the companion, which is where it should have been. As a side effect the orb's quick-input bar can show her last reply immediately instead of only after you have opened the full chat once.
- **Athena no longer pastes a wall of JSON into the chat after moving the canvas** (Athena chat / Teams → Mastermind). When she steered the Mastermind canvas, the reply from the canvas — camera coordinates, a zoom level and a list of island ids, written for *her* to read on the next turn — was rendered into the conversation verbatim, which is useless to a person and buries whatever she actually said. She now states it in a line: "Travelled to a project on the canvas — close view · 14 projects in view", or, when the canvas refused, why: "Couldn't steer the canvas — the view was zoomed too far out". The full readback is untouched in her memory, so nothing she needs was traded away for the shorter sentence.
- **A dev merge that says it worked now has to prove it — and one that refuses no longer strands the work** (Athena dev mode). The `dev_merge` handshake reported success straight out of its strategy choice and then pruned the worktree and deleted the branch on that unverified word, which is the one combination that can actually lose a commit. Three failures came out of it, all fixed. **"Already applied" was reported as total failure:** when a parallel session had landed the same change on master first, the cherry-pick came back empty, git exited non-zero, and the merge was declared a disaster over content that was safely on master — the branch is now checked for patch-equivalence up front, and an empty pick is skipped and reported as applied. **Multi-commit runs were refused outright**, stranding whole pieces of work behind a worktree nobody came back to; they now get a real `--no-ff` merge. Conflicts are still never auto-resolved — the merge aborts, the checkout is left untouched, and the refusal names the intact branch tip so nothing is unfindable. **And nothing is pruned until the content is verified on HEAD**; the verified commit is stamped on the run's ledger row, where "merged" previously carried no sha at all and was an unfalsifiable claim.
- **A merge no longer silently kills the other dev sessions** (Athena dev mode). A dev session runs as a child of the app, so merging — which rebuilds and restarts the dev server — takes every other in-flight session down with it, mid-compile, uncommitted. The merge now refuses while sibling dev sessions are live and names them, and proceeding is an explicit choice rather than something you discover afterwards.
- **A dev session compiling is no longer reported as frozen** (Dev Tools → Fleet). The "no output for 2 minutes means hung" rule is right for a conversational session and wrong for a dev run, whose ordinary working state is a silent `cargo check` that on this codebase runs five to fifteen minutes. Every healthy build was being labelled stuck and "safe to kill". Athena's dev sessions now get roughly a sixteen-minute fuse — past any normal compile, still short enough to catch a real hang.
- **An interrupted dev run's uncommitted work is now saved instead of parked** (Athena dev mode). When an app restart killed a dev session, boot recovery marked the run interrupted and left whatever was in its worktree sitting there — and the merge handshake only ever looks at commits, so finished-but-uncommitted work had no route back. Recovery now commits what it finds under a `[recovered]` message that states plainly it was assembled by the recovery pass and not reviewed by the session, and puts the run back in the normal lifecycle so the ordinary merge handshake picks it up. Review the commit before merging.
- **An unanswered plan from Athena no longer evaporates** (Athena chat). Her actionable proposals — the editable **fleet plan** and the **ship milestone** card — lived only in memory, and the plan JSON is stripped from her reply before it is saved. So the next message you sent, a panel reset, or a dev refresh destroyed the proposal with nothing left to recover: an Aug 2026 session lost six dispatched builds exactly this way. Those two card kinds are now written to the database *before* they reach the chat, and a pending one is brought back whenever you open the panel or switch back to that thread, under a **"Waiting on you from an earlier turn"** label so an older proposal is not mistaken for the current one. Clearing on send still clears the informational cards (the read-once UI snippets), because those are meant to expire with the turn. **Confirm and Cancel are now real decisions** — Cancel records a dismissal so the proposal does not come back, and Confirm **claims** the card before a single terminal opens, which means a double-click, a stale card left over from a refresh, or a replayed event is refused with a plain message instead of quietly starting a second fleet of sessions. A dispatch that fails outright hands the card back so you can correct it and retry.

- `README.md` restructured for a public audience: badges, quickstart-first, deep content moved to `/docs`.

- Onboarding tours no longer narrate retired UI: the Lab step walks the versions-table Lab, and the Recipes/Templates steps actually open their sub-tab.
