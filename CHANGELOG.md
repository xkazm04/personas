# Changelog

All notable changes to Personas Desktop will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Until a stable **1.0** release, minor versions may contain breaking changes to IPC commands, database schemas, or configuration files. Breaking changes are marked with **BREAKING** and always call out the migration path.

## [Unreleased]

### Added
- **Bridge a team channel to Slack** (Teams → Studio → Settings). A team's channel can now be wired to a Slack channel in both directions: team messages, directives and step events mirror out (three separate switches, because step events are the chatty one and almost nobody wants them in Slack), and messages posted in the Slack channel come back in and reach the team's personas the way a directive does. Messages that arrived from Slack are never mirrored back out, so the two halves cannot loop. Setup asks for three things: a **Slack connection** from the Vault (with no Slack credential the panel explains where to add one instead of showing an empty dropdown), the **team member persona** that carries the binding, and the **Slack channel** — picked live from the channels the bot can actually reach, falling back to a channel-id field when the workspace returns none. The panel warns inline when the chosen persona is disabled, because the poller and the relay both scan enabled personas only, so a disabled carrier silently stops the wire. A bridge is stored as a notification channel on that persona rather than in a table of its own, which is what lets the existing Slack poller and dispatcher work unchanged; saving merges into the persona's channel list and leaves its ordinary Slack alerts untouched. The Monitor's linked-channel chip now reads bridges from the backend instead of the persona roster, which returns channel config blank and made every team look unbridged.
- **Context sweeps: one scan reads the code once, every matched lens judges it** (Dev Tools → Skills). The 22 standalone `scan-*` skills had no shared strategy — each Fleet run re-read the same context for one lens and its findings died in the session transcript. A new consolidated **`scan-sweep`** preset skill (generated alongside the lenses, with a per-lens brief bundle) takes one context and evaluates it through its full matched lens bundle in a single session. The Coverage Pipeline now dispatches sweeps (lens-bundle chips per context, least-covered first), the Preset library leads with a scan-sweep hero row and collapses the 22 lenses behind a roster toggle, and lens matching is single-sourced from `scan_agents.toml` so a lens can never ship without a matcher again. Sweep findings finally land in the backlog: structured `finding` lines ride the memory outbox into `dev_ideas` (origin `scan_sweep`, standard dedup guard honoring rejected ideas, backlog-cap backpressure) and render in Approvals → Backlog with a Scan-sweep badge and evidence popover. The app also exports `.personas/backlog-digest.json` (pending/accepted/rejected idea titles, refreshed at context-scan end and before every sweep dispatch) so scans stop re-proposing known or rejected ideas. **Tier 2 — evidence-driven deep scans:** a lens that hits a critical finding or three real findings in one context escalates; the app auto-dispatches the focused `/scan-<lens> <context>` session (at most 2 per ingest, toast per spawn, killable via the Auto deep scans toggle), with the escalation's dedup key acting as the cooldown until the operator resolves it. Open escalations list in a new Recommended deep scans panel for manual dispatch. Sweeps **resolve by default** — each dispatched session implements its accepted S/M findings end to end with one verified atomic commit per finding (fixed items report as progress, not backlog), so several sweeps can run per project, one context each; `--ideas-only` keeps the propose-only behavior, and L moonshot items are always triaged rather than auto-built. **BREAKING — the 22 single-lens `scan-*` skills are retired**: the sweep is the only scan entry point (repo, installer bundle, preset catalog, and system-skill allowlist all carry `scan-sweep` alone), a focused deep pass is `/scan-sweep --lenses <key> <context>` (auto deep-scan dispatch and the Recommended-deep-scans panel updated accordingly), and lens visual identities survive purely for chips and historical usage rows. Projects with previously installed single-lens copies keep them as plain local skills. Migration: use `/scan-sweep`, optionally with `--lenses`.
- **Dev projects and workspace knowledge travel with workspace exports** (Settings → Data Portability). The export picker gains two scopes — **Dev projects** (the row plus the full planning graph: goals, contexts, ideas, tasks, use cases, milestones, project KPIs, memories, and the on-disk `.claude/skills/` library) and **Knowledge** (workspace knowledge entries, deduped on import). Telemetry, scan caches, credential ids, and global skills deliberately do not travel. Importing a bundle whose project collides with an existing one (same folder path or name) now pauses on a per-project **Skip / Duplicate / Replace** resolution panel instead of guessing — everything else imports on the first pass, and the result card sums both passes, including skill files written or deferred when the project folder is missing on this machine.
- **Per-context KPI scanning, swept across sessions** — a single project-wide pass gives eight KPIs for a codebase with 236 contexts, which cannot tell you which *module* is healthy: a live pass over this repo left 3 of 12 context groups with no KPI at all. The KPI scan now takes an optional context scope, proposing **at most 4 KPIs bound to one subsystem**, seeing only that context (handing it the full map invites proposals scoped elsewhere). Backpressure became per-scope, so one unreviewed subsystem never blocks a sweep across the other 235. Because a sweep over hundreds of contexts cannot finish in one sitting, `project-populate` now keeps durable state in an Obsidian vault — an index, one note per context touched, and an append-only decision log — ranking uncovered contexts by what would matter if they broke and taking a batch each session. **Zero KPIs is the expected verdict for most contexts** (plumbing, type barrels, re-export layers) and recording that zero is what stops the sweep paying for the same context twice.

- **Talk to Athena, get an editable plan, confirm, and the sessions start** (Athena chat). Asking her to put several agents on a piece of work used to end in prose. She now drafts a **fleet plan** in the chat: one row per CLI session, each with the project folder it runs in, what that session should accomplish, and optionally a skill to lead with. Every row is editable and removable before anything happens — objectives get rewritten, a row that misread the ask gets dropped — and only **Confirm** starts terminals (one row spawns a single session; two or more become one operation with up to eight). Cancel dismisses it with nothing having happened. It works identically for a spoken request, since voice reaches the same send path. The plan is validated as it is drafted, not when it fires: a folder outside the registered dev projects, an empty objective, or a ninth session never renders a card at all, so a plan you can see is a plan that can actually run. **A containment note:** `fleet_spawn` and `fleet_dispatch` now follow the Fleet boldness dial like her other fleet actions, which on the default **Bold** setting means a typed or spoken request can start real permission-skipping sessions without an intervening click. That is deliberate. What bounds it is unchanged and unweakened — sessions can only ever start inside a **registered dev project** — and the editable plan card is the correction path. Every confirmed plan also lands in the durable fleet decision ledger (intent, session count, and each session's folder and exact opening prompt), recorded as operator-confirmed so it reads apart from an autonomous auto-fire.

### Changed
- **Mastermind opens without the freeze** (Projects → Development). Cold-opening the canvas at portfolio scale locked the UI for a beat: the ~9 data families (passport phases, Ship milestones, KPIs, relations, scans, monitoring, spend) resolve in quick succession right after mount, and each arrival that touched every island re-rendered the whole world in one synchronous commit. Island data adoption is now **staggered project by project** — a handful of islands pick up their fresh content per animation frame while the rest briefly keep what they already painted — so the canvas appears immediately and data ripples in without stalling pan, zoom or clicks. Single-island updates (dragging, a fleet session changing state, a scan going busy) still apply in the same frame.
- **Mastermind is one view and the primary channel into the dev-tools layers** (Projects → Development). The Hex Mosaic is final: the A/B variant switcher and the Inverse Grid prototype are retired. Zoom bands recalibrated to trigger Mid at 20%, Near at 50% and Close at 80%, and the Near band now reads state first — the dimension icon fills each hex as a low-opacity watermark with the state value (ordinal progress, freshness days, or a status mark) in the foreground. Every island banner carries a **Ship milestone chip** (next milestone + shipped count from `dev_milestones`; a late velocity forecast tints it warning) that opens the project's Factory Ship tab in one click. The island context menu and the project sidebar gain **Open in Factory / Open Ship plan / Open Skills manager** doors, and left project-list rows now open the project sidebar. Under the hood Factory gained a reusable deep-link door (`pendingFactoryFocus`) so any surface can land it on a specific project's L2 tab instead of the wall.
- **"Run in a terminal" now opens the terminal** (Dev Tools → Skills → Use). The non-Fleet dispatch target used to copy `claude "/skill …"` to the clipboard and leave the operator to open a console, navigate to the repo and paste. It now calls the existing external-console transport: a new OS terminal window opens already in the project folder with the Claude CLI running and the command seeded, carrying `--dangerously-skip-permissions` to match the Fleet lane. **"All contexts" opens exactly one window** whatever the context count — Fleet can afford a background session per context because it manages them, but a console is a window someone closes by hand, and on this repo "all" is 767 of them; the single session is seeded with the full command list and works through it one run at a time (past ~4 KB the list travels as `.personas/skill-batch.md` rather than risking the Windows command-line ceiling). The window belongs to the operator — the app keeps no handle, cannot steer or kill it, and it outlives the app. The target is relabelled **CMD → Terminal**; the clipboard survives as the fallback for platforms where no console can be spawned (Windows-only today) or when the CLI is not on PATH.
- **Skills Manager columns line up** (Dev Tools → Skills). Coverage, Usage and Last used drifted horizontally from row to row and from their own headers. Each row is its own CSS grid and the Action column was `auto`-width, so it sized to that row's content: a row with two action icons pushed every column left by an icon-width against a row with one, and the header's text label matched neither. The Action track is now fixed for both panels.
- **All Personas is one table again** — the Table / Constellation layout switcher is gone and the roster always opens as the data-dense table (the spatial Constellation map, its 200-node render cap, and the persisted layout preference were removed; the mobile card list is unchanged). Table polish in the same pass: every column header now renders at one type scale (filterable headers were a size and weight off from sortable and plain ones) and sits on the same x-axis as its cell content, the select-all checkbox in the header matches the row checkboxes instead of being squeezed by the header's wider padding, the **Verdict** column is now **Quality**, and the Status column carries lifecycle + health only — the setup-readiness warning still shows on the persona editor header and the mobile card.
- **KPI proposals now measure the product, not the repository** (Projects → Factory → Scan KPIs, and the KPI tab). A live scan over this codebase proposed eight KPIs — test coverage, bundle size, compiler errors, incident counts — and every one was rejected: they were numbers about the repo, already enforced by CI gates, that would not change what anyone works on. The scan prompt now leads with **value and outcome KPIs** (activation, task completion, time-to-value, time saved versus the manual alternative), caps technical proposals at **two**, and refuses to propose anything a pre-push hook or CI already blocks — a closed gate is not a KPI. The root cause was subtle and is now named in the prompt: an instruction to run each command and confirm it yields a number quietly let *what can be measured today* choose the list, so verification now decides **how** a KPI is measured and never **which** ones get proposed. For a product that has not shipped the pillars are still required — phrased as user-journey outcomes so the simulation lane can put numbers against them before launch. Two dead-on-arrival shapes are blocked as well: connector KPIs carrying SQL (measurement composes an HTTPS request against the connector's REST API, so the SQL was never executed), and `derived` KPIs on a project with no linked team (they hard-fail; one such KPI had been sitting ACTIVE and silently unmeasurable).
- **BREAKING — Idea Scanner tab retired; Skills absorbs it** — the 22 scan agents are now **preset system skills** (`scan-*`, bundled with the installer) and the Dev Tools → Skills page gains an **Analytics** tab carrying the scanner's concepts forward: a **coverage pipeline** (Auto-Scan successor — one preset Fleet run per context, least-covered first), **skill performance** (per-skill usage, coverage, run outcomes + the preset accept/impl rates), a unified **skill history** (Fleet skill dispatches ∪ legacy scan rows), and the relocated **Static scan** lane. The skills library panel gains a **Preset | Custom** switcher with lens icons. The backend scan lane and ideas/triage flow are unchanged (Context Map, Mastermind and triage sweeps still drive it); old Idea-Scanner redirects land on Skills. Migration: no action — installed projects keep their ideas/scans; run presets from Skills instead.
- **Workspace creation consent: "Adopt default skills"** — the new-workspace form offers an explicit opt-in; projects later assigned to a consenting workspace get the preset scan skills installed automatically (skip-existing), and consenting workspaces carry a Presets badge in the Atlas.

### Fixed
- **Editing one persona field silently erased ten others** — toggling deep-fanout or changing a per-capability dim wiped that persona's description, icon, colour, model profile, budget cap, turn cap, design context, home team, structured prompt and last design result. The backend contract for the 13 nullable persona columns gives a JSON key three meanings — absent = leave alone, `null` = **clear the column**, value = set — but the frontend payload builder emitted an explicit `null` for every field the caller had not mentioned. That was correct until `double_option` was added to support explicit clears, which inverted the meaning of every null already on the wire; `push_field_param!` then bound each one as SQL NULL. The builder now **omits** unmentioned keys, so the three states stay distinct end to end. A pinned test had been failing on `master` since the regression landed and went unseen because `personas-db` unit tests are not in the documented gate — it has been corrected to assert the real contract (absent → skip, null → clear) and now covers the absent case that was never tested.
- **A milestone created active was never cut** (Factory → project → Ship). `cut_at`, the baseline every "added after the cut" flag is measured against, was stamped only when a milestone *transitioned* into `active`. The seeded "Onboard to Personas" milestone every project gets is created directly as `active`, so its baseline stayed NULL forever and the scope-creep signal never fired on the one milestone most projects will ever have. It is now stamped at creation, and a migration backfills rows already on disk. The lifecycle also gained a server-side rule: a direct `planned → shipped` jump is refused, so nothing outside the UI (the management HTTP API, a Fleet dispatch, the A2A gateway) can ship a milestone that was never cut.
- **Ship exit criteria could read GO on a stale scope** (Factory → project → Ship). A milestone's context footprint was resolved by matching context *display names*, and the generated context map emits near-identical names (`teams/factory [1/3]`, `[2/3]`) while every rescan can rename a context. A collision or a rename silently dropped contexts out of the footprint, and since the footprint feeds both the health and KPI-coverage criteria, a milestone could certify as shippable because a critical context had quietly vanished from its own scope. The footprint now joins on context ids, so renames are free and only a genuinely deleted context leaves the cut.

### Added
- **A design sensor in the static-scan lane** (Dev Tools → Skills → Analytics → Static scan) — `impeccable` joins Fallow/Knip/Jscpd as a configurable tool (`npx impeccable detect --json --no-advisory src`). It is the lane's only *design* sensor; every other tool there reports code hygiene. Zero-LLM, zero-dependency, ~5s over a 1200-component tree, and findings land as ordinary `dev_ideas` with the matched snippet and the rule's rationale. Deliberately scoped to the "slop" rules — the `design-system-*` family is dropped at the parser, because on this repo it produced 969 of 1038 findings and duplicates what the `custom/no-raw-*-classes` ESLint rules already track.
- **Passport: a `design-system` row** (Factory → project wall) — asks whether an agent can read a project's visual rules before it writes UI, across four rungs: none → informal (guidance somewhere the project chose) → documented (a root `DESIGN.md` at the portable spec location) → machine-readable (that file also carries YAML token frontmatter a linter can consume). Projects scanned before this probe existed render `—` rather than a confident "none". The row does **not** feed the automation score yet — folding a new term in retroactively would step-change every project's score and read as real movement in the readiness trend.
- **`.claude/conventions.json` — this repo's gates, machine-readable** — the parseable companion to CLAUDE.md: blocking gates and what they block, codegen triggers (which script must run after which edit), UI token/contrast/i18n rules with the ESLint rule that enforces each, and the multi-session git discipline. Written because a capable third-party skill produced idiomatic work here and still broke two commit gates it had no way to know about. Every entry was verified against `package.json` / `lefthook.yml` / `eslint.config.js`.
- **Scan skills report the honest shape of a run** — the 22 generated `scan-*` preset skills now (1) survey and collect evidence *before* forming a verdict, and run deterministic checks after, so a tool's output can't anchor the judgment; (2) open with a `Method:` line and must declare `⚠️ DEGRADED` when a pass sampled, skipped a check, or hit a limit — a degraded scan reported as complete silently becomes "we looked at that"; (3) append a snapshot to `.claude/scan-history/scan-<key>.jsonl` and report a trend across runs, comparing like scope with like. They also read `.claude/conventions.json` before proposing changes.
- **The passport wall loads in one call instead of 3N** (Factory → project wall). Drawing the wall used to fan three per-project IPC calls out (contexts, KPIs, milestones) through a concurrency pool, so a 30-project wall cost 90 round trips and 90 queries before a single cover appeared. One batched `dev_tools_project_wall_summary` now answers the whole wall: 1 IPC call and exactly 3 grouped queries regardless of project count. No visual change. The KPI verdict stays a client computation on the raw rows, because it is time-dependent and already has one Rust twin that must not become three.
- **New Ship exit criterion: Scope frozen** (Factory → project → Ship). The per-member "added after the cut" flag was visible on rows but never counted for anything. It is now a fifth exit criterion: `go` when nothing joined the cut after certification, `warn` (naming the offending features in its evidence line) when it did, and `setup` before the cut is stamped, where the signal carries no information yet. It is `warn` and not a hard block because growing a cut is a legitimate decision; but since `warn` folds into the ship verdict, a milestone that kept growing can no longer certify as shipped without the creep being seen first. The four exit criteria also moved into a **registry**: one table of self-describing entries, so a fifth (or sixth) is an append rather than surgery inside the derivation loop.
- **Ship forecasts the next milestone from your own history** (Factory → project → Ship, and the passport cover's roadmap strip). Every lifecycle transition already stamped `cut_at` and `shipped_at`, and nothing read them. The Ship layer now derives the project's **median** cut-to-ship cycle (median, not mean, so one 90-day milestone cannot poison the estimate) and projects the next milestone's landing date from it: counted forward from the real cut, or from today with "if cut today" said out loud when the milestone has not been cut. Below two observed cycles there is **no forecast at all** and the surface says so rather than guessing from one data point. When a forecast lands after a declared target date, both dates are shown side by side. Shipped milestones show no forecast; they have a real date.
- **Choose what a populate run covers** (Factory → project wall → Populate project data) — the action's consent modal now carries a four-lane picker: context map · features · KPIs · simulated KPI data. The default comes from the freshness gates rather than being all-on, so a project whose structure is already current opens with just the KPI lane ticked. Each row says what the lane would do for *that* project ("Context map: 12 groups and current, will be left alone") instead of describing it in the abstract, and excluded lanes are reported as out of scope rather than silently absent.
- **Simulated KPI data for products that have not shipped** (the populate action's fourth lane) — the honest problem with a pre-production project is that you need pillars to know what to measure but have no traffic to measure, and a target invented to fill the field looks like evidence. The lane hands the adopted KPIs to the simulation engine, which walks their journeys with representative characters and researches targets from comparable products with citations. Values stay tagged as the simulation they are (`local`/`test`, never `production`) and are never reported as real measurements.
- **Populate project data** (Factory → project wall → actions row) — a new per-project action that fills in the three things Personas needs to work with a freshly adopted repo at all: a **context map**, a **feature inventory**, and a **KPI set you approve one by one**. Each lane is gated on what already exists — missing, older than 14 days, or fresh — and the consent modal states what *this* run will do before you confirm it, so a project that only needs KPIs does not pay for two re-scans. Contexts and features are assigned autonomously; **KPI proposals are walked with you five at a time** (adopt · adopt with a different target · reject · defer) with each decision recorded the moment you answer it, so an interrupted run keeps what was already decided. A final pass names the exact monitoring binding for every adopted KPI the project has a connector for. Pick where it runs: a **Fleet** session, or a **new terminal window you own** that keeps going after Personas closes (the app cannot watch or stop that one, so the briefing is written into the repo and the session can be re-run by hand). All scanning goes through the app's own engine, so results are identical to scanning from the Factory toolbar.
- **Full context scans now fan out** — a full (non-delta) context scan explores the tree with parallel subagents and reconciles their reports before writing the map, instead of walking it one directory at a time in a single session. Applies to every entry point into that lane — the Factory toolbar, the Context Map page, and the new populate action. Delta re-scans are unchanged and stay cheap.
- **Passport actions explain themselves before they run** (Factory → project wall → actions row) — the consent gate behind Onboard / Standards scan / Copy report / Rescan / Improve plan is now a full modal instead of a 296px popover with one paragraph. Each action declares its **impact class** (read-only · writes when you confirm · runs an agent session), a fact strip (scope, engine, duration, what it writes, which repo it runs in), the **ordered steps** the click actually sets off, and the **boundaries** that hold regardless — credential values never leave the vault, queued Claude tasks wait for review, read-only passes never touch the repo. You can now tell what a click costs before paying for it.
- **Roadmap on the passport cover → one-click Ship** (Factory → project wall) — every project cover in the Overview grid now carries a minimized roadmap: one pip per milestone (shipped / active cut / planned), a `shipped/total` tally, and the **next milestone** named below with its target date. Clicking the strip opens that project directly on its **Ship** tab instead of the default Overview. Projects with no milestones show a "plan the first cut" invitation and still open Ship. The passport wall and the L2 Overview's context cards also got a readability pass — nothing on the wall renders below `text-base`, KPI-card rows sit at `text-sm` or larger, and every icon grew ~50%. The tile's blockers digest moved onto the cover's identity line as a warning glyph + count (full list in the tooltip), the View / Sort / Module control-group labels became glyphs, and an unmeasured context card now reads a single italic *define KPI* instead of three shifting setup asks.
- **Roadmap surface visuals** — the in-app Roadmap (Home → What's New) gains two traced, self-drawing SVG glyphs: a route rail alongside the hero card whose amber/teal/hollow nodes mirror the NOW/NEXT/LATER lanes below it, and an empty-waypoint glyph replacing the bare em-dash in a lane with no items. Motion for every traced glyph in the app now comes from one shared preset library (`motionPresets.ts`) instead of per-component keyframes, with ambient loops reserved for surfaces where work is genuinely in progress and an opacity-only fallback under `prefers-reduced-motion`.
- **Knowledge-base supersede-on-reingest + Rebuild index** — re-ingesting a source file whose content changed now *supersedes* the old document (its chunks and vectors are deleted transactionally before the new version is indexed), so edited files no longer double-index and stale passages stop winning searches; unchanged files still skip. A new **Rebuild index** action on the knowledge base's Settings tab (`kb_reindex`) re-embeds every stored passage with the current embedding model — the recovery path when the app's embedding model changes or an index drifts — with live progress and cancellation.
- **Knowledge-base search relevance floor** — `kb_search` now drops vector candidates beyond the shared relevance floor (`MAX_VECTOR_DISTANCE`) before BM25/RRF ranking, so small corpora return honestly-empty results instead of far-away noise; the Search tab reports how many low-relevance passages were hidden. The ambient all-KB scan behind clipboard intelligence is consolidated into one shared engine implementation (ready-KBs only) used by both the command and the watcher.
- **SLA breach events** — reliability breaches now notify instead of waiting to be noticed. On the execution-completion path (never at dashboard load), a cheap bounded check of each persona's recent runs emits a typed `sla.breach.opened` event into the event bus when a persona crosses into a breach, and one `sla.breach.recovered` when it climbs back out — visible in Overview → Events (red / green) and carrying `persona_id` + reason + streak/rate for healing to consume. **Zero-config**: no targets to author, no settings surface. Fixed conservative defaults — breach at **≥ 5 consecutive failures** or a **windowed success rate below 50% over ≥ 5 decided runs**; recovery uses a hysteresis bar (back above 75% with no active failure streak) so an episode never flaps. Episode state is durable (`sla_breach_episodes`), so a breach announces exactly once and a restart mid-episode never re-emits.
- **Faster Athena replies via per-class model routing** — calibrated by a 1,026-turn decision-ability bench (`docs/plans/athena-model-bench-report.md`): main chat turns now run Opus at low reasoning effort (identical accuracy in the bench, ~16% lower latency), and headless micro calls (auto-titles, triage legs, one-shot classifications) upgraded from Sonnet 4.6 to Sonnet 5 at low effort. One routing table (`companion/model_routing.rs`) owns every tier; `PERSONAS_ATHENA_MODEL`/`PERSONAS_ATHENA_EFFORT` override per spawn for measurement.
- **Concurrent conversation safety (multiconv P1)** — with turns running in parallel across Athena threads, everything turn-scoped is now partitioned per conversation: a background thread's stream can no longer write into the focused thread's bubble, the mid-turn message queue and Stop button act on the thread you're in, a user message no longer cancels another thread's autonomous chain (the explicit Cancel remains a global brake), background tasks know which thread spawned them, and Reset wipes only the current thread's transcript.
- **Athena constitution v44** — bench-derived discipline: every distinct ask in a message gets its own single-line op (two-action messages no longer silently drop the second action), and Athena may not claim something is "already in my notes" unless this turn's recall actually shows it — she proposes the memory write instead.
- **Athena model/effort benchmark harness** — `scripts/test/athena-model-bench.mjs` + a 38-scenario corpus scored by the production dispatcher (`athena-bench-validate`), with per-run checkpointing, resume, and promotion-gate verdicts vs the Opus baseline. `PERSONAS_DUMP_PROMPT=1` snapshots real composed prompts for replay.
- **Fleet live-slot scheduler** (Fleet → Settings → *Limit live sessions*) — cap how many `claude` processes run at once (1–64). Overflow Idle/Stale sessions are auto-hibernated oldest-first (resumable via Wake), and a spawn/wake at the cap hibernates the best idle candidate to make room, so a large tracked fleet costs only what the active sessions cost. Working sessions are never interrupted (soft cap).
- **Fleet terminal scaling hygiene** — one shared output listener dispatches PTY chunks (was one filtered listener per terminal), off-screen xterm instances are LRU-bounded (max 6 parked; re-attach replays the backend ring losslessly), and the context-size pill reads the incremental per-session rollup instead of re-parsing the whole transcript per mount.
- **Fleet screen reads are now O(screen), not O(ring)** — each session keeps a persistent VT screen model fed incrementally from its output stream, so Athena's screen reading, dedupe hashing, and tile previews stop re-parsing up to 512 KiB per look.
- **Fleet headless (background) sessions** — the Spawn-with-task composer gains *Run in background (no terminal)*: the session runs as `claude -p` with stream-json stdio instead of a PTY, so there is no terminal redraw loop and idle CPU is ~zero. Same conversation semantics (pinned session id, transcript, hooks, Insights, hibernate/wake — waking resumes interactively); replies from the banner or Athena are wrapped into stream-json messages. Tiles show a **Background** badge; no terminal is ever mounted for these.
- **Scheduled memory reflection from Chain Studio** — "Memory Reflection" joins Context Scan Update as a system-event target in the Studio: patch a Schedule (or Event Listener) source into it, pick an agent or a whole team, and reflection runs on that cadence as a background job whose output is a proposal in Overview → Memories (never an unattended mutation). Studio polish in the same change: palette option cards are single-row with the description as a hover tooltip, and ledger rows are slightly narrower.
- **Team memory reflection** — a reflection pass over a whole team: lessons held redundantly by two or more members are consolidated into one **team-shared** insight (visible to every member's runs once the proposal is applied; the per-member copies archive with provenance). Available via `reflect_team_memories_with_cli` and as a background job.
- **Reflection → backlog bridge** — reflection now also extracts **product findings** (open bugs, debt, unresolved review threads mentioned in memories) and files them as pending ideas in the Dev Tools backlog, with provenance back to the source memories. The backlog's own accept/reject triage is the approval gate; saturation-capped and deduped against existing ideas.
- **Memory reflection** (Overview → Memories → Reflect) — an LLM pass that consolidates related or contradicting memories into fewer, durable insights. Insights carry **provenance** (`Synthesized from` in the memory detail view; sources are archived, never deleted) and everything lands as a proposal you apply or discard — live memories are never touched without confirmation. Also available as a background job (`enqueue_persona_memory_reflection`).
- **Value-aware memory recall** — the memories injected into a run are now selected by decayed value (importance × category half-life × real usage) packed whole into the prompt budget, instead of "sort by importance and truncate". Constraints barely decay; session context fades in weeks.
- **Decay-based forgetting** — stale low-importance active memories (score below floor, ≥21 days old, importance ≤3) are auto-archived (reversible) after each run, replacing the binary 30-day rule.
- **Use cases — a behavioral layer over the context map** (Dev Tools → Context Map). A use case slices *through* contexts ("Checkout conversion" spans a UI, an API and a data context), so it — not an arbitrary single context — can own an outcome. Selecting one highlights every context it spans. Seed them deterministically from your existing feature labels (**From features**), or let an agent propose the project's key ones (**Scan**, triage-gated). A use case is now the narrowest **KPI scope** (`dev_kpis.use_case_id`): goal derivation offers such a KPI the use case's whole context slice as candidate work, and the **LLM Overview** marks which observed LLM call sites map to a declared use case (matched on the use case's slug). Active use cases publish into `context-map.json` so CLI agents see them too.
- **Curated connector API-update events** — the Events → Marketplace tab now ships a subscribable feed per connector with public API docs (e.g. *"ElevenLabs API updates"*). A monthly dev-side watcher (the `connector-api-watch` pumper app) diffs each connector's public docs and Claude-summarizes what changed; detected changes are baked into the release and delivered to subscribers **fully locally** (no cloud) as `shared:<slug>` events they can route into their own triggers and chains. The Marketplace tab is no longer dev-only.
- **Persona Foundry** — a compose-from-parts creation surface at Agents → create: pick a mentality **archetype** (9 curated presets with core dials, voice, and principles, distilled from the template corpus), a **memory strategy** (Focused / Learner / Team player / Grounded expert / Second brain), and attach **capabilities** from the recipe catalog — then create through the same pipeline template adoption uses. "Describe it" (chat build) and "Browse templates" remain one click away on the same screen.
- **Recipe removal** — adopted capabilities can now be detached from an agent (Remove button + confirmation on the recipe detail page); re-adopting an already-adopted recipe is refused instead of silently duplicating it.
- **Composition x-ray** — template adoption now opens with a strip showing the template's parts (mentality + its catalog recipes), the same vocabulary the Foundry composes by hand.
- **Illustrated empty states** — six first-run empty states (Goals timeline, KPI dashboard, Director coaching, Smee relays, Shared feeds, Rate limits) now render a traced, self-drawing neon glyph instead of a flat lucide icon, via the shared `MotionizedGlyph` primitive (dark + light themed, honors reduced motion). The `motionize` skill gained a DashScope image generator fallback and a `--split` tracer mode so each glyph's path data lazy-loads with its own route.

### Fixed
- **Adoption stamps mentality dials** — the persona core profile (risk tolerance, conflict style, …) authored in templates is now applied on the standard adoption path; previously it was silently dropped (only the dev-tools instant-adopt path ever read it, from a field no template carried).
- **Recipe catalog repairs** — the three 2026 consolidated templates (email intelligence/support, sales deal intelligence) had incoherent recipe provenance and one silently-orphaned adoption question (`uc_email_triage` id collision); re-keyed with a corpus-wide integrity test so the bug class can't return. Also: two recipes upgraded to Opus (code review, PR test+merge), two downgraded to Sonnet, one 6-field cron fixed, the last schema-v1 template migrated, and a misfiled template moved to its real category.
- **gcloud CLI auth for Google Cloud Platform** — the GCP connector's add-credential form now offers a "gcloud CLI" tab that imports your active `gcloud` session (no service-account key file needed). Captured tokens auto-refresh while the session is valid; persona API calls resolve the captured token as Bearer auth (`GcpCloudStrategy`) and recover mid-run expiry via the 401 retry path.
- **CLI session re-auth recovery** — when a CLI-captured credential's underlying session dies (e.g. `gcloud` re-login required), the credential is flagged for re-auth, an OS notification fires, and the Vault banner shows the terminal login instruction with a "Retry capture" button instead of failing silently with backoff.

### Changed
- **Honest cascade strength** — the Health → Cascade chains labelled each team-mate edge with a `0.7` strength that looked computed but was hardcoded. Each edge now shows the **measured co-failure correlation** (Jaccard overlap of the two personas' failure days over their shared daily window, with a minimum-sample floor); the arrow renders the real `% co-fail`, or "no co-failures" when there isn't enough shared history to claim one.
- **Honest Status-page composite** — the health composite no longer weights `successRate` (0.30) *and* an `slaCompliance` (0.25) that read the exact same `success_rate` value, i.e. one metric counted twice across 55% of the grade. The 0.25 weight now scores the **consecutive-failure streak** (a genuinely independent, already-computed signal: a persona can hold a high window success rate while being mid-outage right now). Grades shift — a persona in a live failure streak drops even if its rolling success rate looks fine. The Status-page breakdown's "SLA Compliance" column is now "Stability".
- **One health formula** — the Health screen's three scoring paths (Heartbeats-tab score, Status-page composite, agents health digest) now resolve grades through a single `computeGrade` threshold (80/50) instead of four verbatim copies, and the heartbeat budget sub-score is strictly monotonic: a persona spending more of its budget can no longer *raise* its own health score (the old curve jumped a 79%-spent persona from 21 up to 30 at 81% spent). Some Heartbeats grades near the 80%-budget boundary shift as a result. Scoring is consolidated in one dev-weight-asserted module.
