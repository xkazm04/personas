## 2026-08-04 — ascent (run 1)

Outcome: go-with-risks; 16 commits pushed; scorecard P0/P3/P4/P6 green, P1/P2/P5 partial (all partials blocked on operator env values or the Personas app being up, not on code).

Friction and fixes for the skill:

1. **Pathspec commits are mandatory.** Three separate index-race incidents: builders' staged files swept into a concurrent builder's commit between `git diff --cached --stat` and `git commit` (attribution noise, no content loss). Fix applied to doctrine: builder briefs must use `git commit -- <paths>` (with `git add <paths>` first for untracked files — bare pathspec commit errors on untracked). `git apply --cached` per-hunk worked well for co-mingled files (.env.example).

3. **launch-gate probe gap:** add "does CI actually RUN the e2e suite?" to the probes. Ascent's specs existed but never ran in CI, so they rotted silently against the shipping product. Existence of a harness is not evidence of a working gate.
4. **Bridge-dependent delegations need a reachability probe in Phase A.** project-populate hard-requires the Personas app loopback bridge; the app was down, so the accepted "full re-run" degraded to file-level reconciliation mid-execution. Assessors should probe app/bridge reachability up front so the decision round can present "requires the app running" honestly.
5. **Round shape validated:** 4 rounds of ≤4 questions, pipelined (P0/P5 presented while other assessors still ran) — zero dead wait, no operator overload. Two operator overrides (full project-populate; keep onboarding walls) — the select mechanism captured them cleanly.
6. **Framework-upgrade byproduct:** Next rewrites its `nextjs-agent-rules` block in AGENTS.md during build; classify that diff as own-run work and commit it, not foreign drift.
7. **Push-then-protect ordering worked**: enable branch protection only after the run's own push, with `enforce_admins: false` for solo-owner repos.

Friction and fixes for the skill:

1. **The P0 intent question is now load-bearing enough to ask BEFORE the assessors return.** Gravitone's README pitches an Arm hackathon Track-2 entry while /mvp drives a market release. Asking up front re-scoped P5 to skip in one round and redirected the run's weight onto reproducibility, claim accuracy and the five-minute judge path. 2. **Probe the repo as a STRANGER sees it, not from inside the working directory.** The two highest-value findings of the run were invisible to every file-level probe: the git root was `arm/` with the project under `gravitone/`, so the public repo landing page rendered no README and GitHub reported `licenseInfo: null` — and 40 commits were unpushed, so the judged artifact was three weeks stale. Neither is in checklist.md. **Proposal: add a P5/P6 probe — `gh repo view` (description, license, topics, homepage), `gh api repos/:o/:r/contents` (what renders at the root), and `git rev-list --count origin/HEAD..HEAD` (is the public artifact current?).**

3. **License detection is a text-similarity match and attribution breaks it.** The builder helpfully preserved a Kyutai attribution paragraph *inside* the MIT body, between the copyright line and the permission grant. GitHub's licensee then refused to match, so the repo reported no license — the exact Track 2 requirement. Fix: verbatim MIT in LICENSE, attribution in NOTICE. **Proposal: checklist probe "does `gh api repos/:o/:r/license` resolve?" — file presence is not detection.**

4. **A first CI run on a repo that has never had one is a 4-iteration debugging session, not a confirmation.** The builder verified every command locally in a clean worktree and still hit four stacked, environment-only causes: (a) `npm ci` rejects a Windows-generated lockfile on Linux over pruned transitive deps of optional wasm32 packages — and regenerating on Windows does NOT fix it, pristine or with `--os=linux`; (b) ffmpeg absent on GitHub's ubuntu image, which the service genuinely shells out to; (c) a test round-tripping sentry's RESOLVED option set back into `init()`, which broke when the CI's newer SDK added a derived key; (d) Node 22 vs local 24 — 33 failures from a jsdom/Node dual-realm `Blob` identity mismatch. Run 2's "expect 3-5 iterations" generalizes: **local-green is weak evidence for first-CI-green; budget the loop.**

5. **Job-level env in a workflow can silently change the product's MODE.** The Firebase placeholders needed by `next build` (it prerenders /keys) were job-level, so the test run inherited them — and a present project id is exactly how the studio selects firebase auth mode over single-user. 21 tests failed `expected 401 to be 400`. **Proposal: builder-brief language — "scope build-only env to the build step; tests must run in the posture a plain `git clone && npm test` gets."**

6. **Running the deploy script IS the audit, even when the cloud is unreachable.** AWS credentials were expired so nothing launched — yet executing `aws-oneclick.sh` verbatim surfaced six defects, headed by `set -uo pipefail` with no `-e` and no exit-status checks: every call failed, and the script printed a triumphant `Base URL : http://:8080` after 20 minutes of unguarded retries. It had also minted a live root key into an untracked, un-gitignored file. **A deploy script that cannot fail cannot be trusted when it succeeds** — worth adding to the deploy item as an explicit probe (`grep -L 'set -e'` over deploy scripts).

7. **Premise error rate was ~1 per brief again, and correction went both ways.** Wrong: "the fallback is silent" (two banners existed; the real hole was no label at playback), "derive identity the way other routes do" (no server-side verification existed anywhere), "`next build` succeeds" (assessor had a gitignored .env.local), "pytest needs the ML deps" (fake_engine stubs them), "~47 outline-none" (inflated by scanning .next/), "npm audit fix will fix it" (it fixed nothing; next pins postcss/sharp exactly).
