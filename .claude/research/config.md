The `vault` list is the SAME Obsidian vault named `personas` on two machines - `kazda` and `mkdol`
hold it under their own `Documents/Obsidian/`. First existing wins; the skill's `<repo>/.research/`
fallback is the last resort and means neither machine's vault was found (git-ignore it if it appears).
`vault_subdir` is empty: `Research/`, `Lessons/`, `Patterns/` and `00 - Index.md` live at the vault
ROOT, shared with `/explorer` and `/architect` (which namespace under their own subdirs).

`.claude/active-runs.md` is the live-sessions ledger. Do NOT hand-edit it - `scripts/active-runs.mjs`
picks the authoritative `## Active` section, stamps the time, formats the entry and refuses a
duplicate slug:

```bash
node scripts/active-runs.mjs register --slug <slug> --title "/research on <source>" \
  --paths "<path>" ... --source "<url>"
node scripts/active-runs.mjs check --paths "<path>" ...   # exit 0 clean, 2 live conflict
node scripts/active-runs.mjs complete --slug <slug> --status "completed (commit: <sha>)"
node scripts/active-runs.mjs doctor                        # structural damage report
```

`check` already excludes the ledger itself and already ignores entries past the 2-hour staleness
window. Rationale: `docs/architecture/cli-coordination.md`.

## Buckets
- **A - Code**: always live.
- **B - New persona template**: catalog at `scripts/templates/{category}/{id}.json`, inventoried in
  `.claude/codebase-catalogs.md` (Template Catalog + Coverage Analysis). Command: `/add-template`,
  pre-filled with the finding's title + summary + recommended services.
- **C - New credential / connector**: catalog at `scripts/connectors/builtin/`, inventoried in the
  same file (Connector Catalog + auth distribution). Command: `/add-credential`, service name

## Gates
- Every task -> `npm run check`: **ten** gates in an `&&` chain incl. `census:check`, `tsc --noEmit`,
  `eslint src/`. **Never a hand-rolled `tsc`+`lint` pair** - the chain stops at the first failure and
  `census:check` is the one most likely to fail a diff that compiles. See `.claude/CLAUDE.md` ->
  "PR self-review".
- Rust changes -> `cargo check` in `src-tauri/` (needs `--features desktop`)
- i18n changes -> `npm run check:i18n:strict` (the no-gap gate)
- Lint baseline is ~10k warnings: gate on no NEW warnings in the files this diff touched.

## Repo law
Authority: `.claude/CLAUDE.md`.
- **i18n contract (14 locales).** Every user-facing string: key into `src/i18n/locales/en.json` via
  `useTranslation()`, translated into all 13 other locales in the same change -
  `scripts/i18n/translate-extract.mjs` -> fill `.i18n-work/missing-<code>.json` ->
  `translate-merge.mjs`. The `i18n-no-gaps` pre-commit hook blocks gaps. No hardcoded English in
  JSX, placeholder, title or aria-label. Backend status tokens via `tokenLabel()`
  (`src/i18n/tokenMaps.ts`); errors via `resolveErrorTranslated()` (`src/i18n/useTranslatedError.ts`).
  A string-adding finding costs 14 locales - put that in the effort note, not in the surprise.
- UI: the typography contrast / muted-text antipattern rule in CLAUDE.md -> UI Conventions.
  Semantic design tokens (`.claude/Design.md` section 8); shared components from CATALOG.md.
- Voice for user-facing copy: CLAUDE.md -> "UI Conventions -> Internationalization -> Voice for
  user-facing copy". Applies to every word of Phase 12.
- IPC via `invokeWithTimeout`; errors via `toastCatch`/`silentCatch` + the error registry.
- Planning docs: handoffs at `.planning/handoffs/{date}-{slug}.md`; discovery briefs and
  ambiguous-location designs at `.planning/research/{date}-{slug}.md`. A design for a known landing
  site is co-located as `src/features/<area>/<sub_feature>/DESIGN.md` instead.

## Domain notes
- **The central mechanism**: personas wraps the **Claude Code CLI** - it literally spawns the
  `claude` binary as its LLM provider (`codebase-stack.md` section 2). Any idea about Claude Code
  features (hooks, slash commands, MCP, settings, output styles, subagents, session resume) is
  **highly relevant to this codebase**, never out of scope. This single fact decides half the
  relevance calls.
- **Catalog count is never the runtime denominator.** 87 connectors in the catalog != 87 in any
  execution: each persona binds **0-3**. 92 templates != 92 prompts the LLM sees: each persona uses
  at most 1. N protocol blocks defined != N injected: some are conditional on persona type or
  dev-tools mode. A finding whose premise depends on catalog == runtime is wrong - drop or reframe.
  See `codebase-stack.md` section 3 for the connector binding model.
- **Framework vs plugin routing.** Personas-the-framework is general-purpose. Code/SDLC-specific
  features (worktree isolation, CLAUDE.md updates, repo scans, PR generation, build automation)
  belong in `src/features/plugins/dev-tools/` + `src-tauri/src/commands/infrastructure/dev_tools.rs`,
  NOT in the core engine. See `codebase-stack.md` section 3, "Personas framework vs `dev-tools`
  plugin". The test: "would a non-coding persona benefit from this?" If no -> plugin, not core.

## Release log
- Config: `src/data/releases.json` - structural metadata only (`config.active` names the version the
  in-app view opens by default; items carry `id, type, status, added_at`). Never put user-facing
  strings here.
- Content: `src/features/home/components/releases/i18n/` - exactly 14 locale files
  (`en.ts, cs.ts, de.ts, es.ts, fr.ts, ja.ts, ko.ts, zh.ts, ar.ts, hi.ts, ru.ts, id.ts, bn.ts, vi.ts`)
  plus `useReleasesTranslation.ts`.
- Key shape: `whatsNew.releases.{version}.items.{itemId}` with `title` and `description`.
- The "What's New" view loads by direct property access - a missing key crashes the UI. Refuse to
  write a partial set. Write English everywhere plus a top-of-file
  `// TODO(i18n-{lang}): translate from English placeholders` marker in the 13 non-English files.
