First non-JS target for this skill — a Rust workspace shipping a container + binaries + 3 SDKs, no web UI. Several checklist items needed translating (landing = the repo README + GHCR page; design-system = shared render crate + error envelope; auth = API-key lifecycle, not signup).

Friction and fixes for the skill:

1. **The onboarding probe's "exercise the core loop" rule earned its keep twice in one run, and the second find was invisible to every other probe.** First: the documented quickstart 400'd on a missing project and both SDKs swallowed it (`except Exception: pass`), so a stranger saw pure silence. Second, and only because the orchestrator *ran the quickstart it was about to document*: `LIGHTTRACK_PRICING` resolves against cwd, release archives ship binaries only, so every `install.sh` user got `cost_usd: null` on every event — a silent null on the second headline feature, shipped since the first tag. **Proposal: promote "run the documented quickstart verbatim, from a directory that is NOT the repo" into the onboarding probes.** Running it from the repo root would have shown `0.00045` and proved nothing.

2. **"Any artifact CI does not exercise is presumed broken" (brainiac run 4) paid out THREE times here** — the Intel-macOS binary absent from every release since the first tag (all 5 release runs cancelled at the 24h *queue* limit), the Rust SDK not compiling at HEAD after drifting from core, and `npm ci` broken for the TS SDK. This rule is now the single highest-yield line in the brief pack. It deserves to be checklist text, not just calibration lore.

3. **`timeout-minutes` does NOT bound runner queue wait** — my brief asserted it would have prevented the 24h cancellations; the builder proved otherwise (queue wait is a separate 24h limit) and fixed the actual cause, a retired `macos-13` label. Orchestrator premises are wrong at about the same rate as assessor premises; the "verify then deviate and report" language catches both. Worth saying explicitly in briefs that the *brief itself* is a premise.

4. **Making clippy blocking against a floating stable toolchain is a trap the skill should name.** Local rustc was 1.94, CI stable was 1.97; the gate went green locally and red on CI twice, on lints that did not exist locally, then a third time on a Linux-only dead import unreachable from Windows. 5. **A cross-builder seam dropped half of an accepted item, and only an explicit re-probe caught it.** The onboarding fix had a server half, an SDK half, and a README half; the README owner had already committed and finished *before* the operator accepted the item, and the SDK builder's scope was `clients/**`. Run 3 said "cross-builder seams are the orchestrator's job" — this run shows the seam can also be *temporal*, between a finished builder and a later decision. **Proposal: at certification, re-probe each accepted item's done-criterion directly rather than trusting the union of builder reports.**

6. **Redaction default-flip surfaced a latent pairing bug that only the new default made reachable.** The scrubber treats 32+ hex chars as a secret and `hash` persistence stores a 64-char sha256, so scrub-on-by-default collapsed every hashed payload to `<SECRET>`, destroying hash mode's presence/diff promise. The builder's own new test caught it. Generalizable: **when a run flips a default, ask what other feature was only ever exercised under the old one.**

7. **Pathspec commit doctrine held for the fourth run, with one sweep incident** — a builder's 12 staged files were absorbed into another builder's commit inside a ~2s `git status` → `git add` window. Content intact, correctly not amended, and the affected builder switched to pathspec commits afterward. The residual race is *staging* on a shared index, not committing; `git apply --cached` + isolated `GIT_INDEX_FILE` remains the only fully safe pattern under concurrency.

8. **Assessor premise error rate held at ~1 per brief and corrected upward twice**: the fmt builder found the dominant clippy lint was `derivable_impls` (8 sites), which the assessor never mentioned; the store-pg builder found `crates/store-pg/src/events.rs` already over the LOC rule before its tests and *reported the widening rather than hiding it*. ### lighttrack run 5 — follow-up phase (same day)

The operator asked to walk the follow-ups one at a time with select options. That turned into the highest-yield phase of the whole run: **9 of the 10 items produced a code change, and the two features nobody had exercised turned out to be broken in ways no probe had caught.**

9. **"Walk the differentiator" belongs in the checklist, not in the follow-ups.** `value-case`'s done-criterion already says each killer feature must survive an end-to-end walkthrough — but it is the item most likely to be waved through on documentation. Actually walking LightTrack's two headline features found: `lt-runner score` sending `unscored=1` against an `Option<bool>` query field, i.e. **the primary scoring command could not make a single judge call**, on a repo whose pitch is LLM-as-judge; and `config/model_aliases.json` resolving relative to cwd, which left models unmerged, which left every row single-source, which the k-anonymity floor then withheld — **an empty leaderboard, silently.** Both were invisible to every read-only probe and to the test suite. **Proposal: make value-case's walkthrough mandatory and explicitly adversarial ("run it as a stranger, from outside the repo root"), not deferrable to P6.**

10. **A default-flip needs a downstream-consumer audit, not just a behaviour test.** Flipping ingest scrubbing on (D14) was correct and tested. What no test covered: the LLM judge reads the *stored* payload, and the phone regex matched any ISO date — so a clean sentence became "bought on `<PHONE>`" and the judge scored the mangled version **0.88 against 0.85 for the clean one**, praising specifics that were no longer there. The corruption is undetectable from any score, alert or dashboard. Generalizes run 5's item 6: **when you flip a default, enumerate every consumer of the data that default touches and check each one — a passing test for the flipped feature says nothing about what reads its output.**

11. **The "relative path to a config file" defect is a repo-wide class, not an incident.** Found twice, independently, hours apart: `config/pricing.json` (every `curl | sh` install returned `cost_usd: null`) and `config/model_aliases.json` (empty leaderboard). Same shape, same silence, same `include_str!` fix. **Proposal: add a probe — "does any shipped binary resolve a config path relative to cwd, and does the release archive contain that file?" It is a two-line grep that would have caught both.**

12. **Builders declining to fix things was as valuable as fixing them.** Three examples worth keeping: a builder downgraded its own finding after checking the schema (the unguarded jsonb cast is unreachable — `metadata` is nullable and never written as `''` — so it committed it as defensive parity, not a fix); another refused to route two tri-state query params through `is_truthy` because a typo would then *narrow* results rather than widen them, and flagged them for the operator instead; a third measured a flake at 1-in-163 over 800 instrumented runs rather than accepting my "~4%", then fixed it by pinning inputs and **tightening** the assertion from `> 0` to `== 2`. The brief language that produces this is "deviate and REPORT with evidence" plus "an honest 'not fixed, here is why' is a good outcome."

13. **Orchestrator premises were wrong at roughly the assessor rate, again.** Mine this phase: `collective.rs` was 1174 LOC not 1023; `store-pg/events.rs` 646 not 607; `timeout-minutes` does not bound runner queue wait; `authenticate` is the single chokepoint for *rejection* but not *acceptance* (a valid relay device key returns Ok without touching it — and that path held a second plain `==` on a secret). Every one was caught by a builder because premise-verification is mandatory brief language. **Say explicitly in briefs that the brief itself is a premise.**

14. **A walkthrough finds UX defects that no code review will.** Beyond the two bugs: `POST /v1/projects` silently ignored a caller-supplied id, so the README's very next documented step 404'd; rubric creation existed only in code, with `lighttrack_render` already shipping list/show renderers **no CLI command could reach**; and `score --rubric` took freeform text while its siblings took `--rubric-id`, making the documented weighted-dimension methodology unreachable from the primary command. All three are "the code is correct, the product is unusable" — findable only by trying to use it.

The builder correctly refused to add an exclusion — an admin security change is not a subagent's call. Also worth surfacing to operators: one `claude -p` judge verdict cost **$0.019**, almost all of it context overhead (55k cached + 4k created tokens for a ~200-token judgment).
